## L9 · 真实产品界面要求必须延续到 POC（2026-09-14）

- **现象**：用户要求真实 Paws 界面与参考片运镜，拒绝了使用模拟 UI 和卡片旋转的基础版本。
- **根因**：只检查参考片后半段制作讲解，漏看开头成片；把 POC 错当成可以降低素材真实性。
- **下次规则**：先连续取帧区分成片和讲解；POC 缩短镜头数量，保留真实素材。分别核对输入框特写、设备外壳、屏幕姿态与转场轨迹。本条作为任务范围先验保留。

> 本文件是 animate-prompt 的**持续经验日志**。机制参考《站点经验沉淀机制：从 SKILL.md 规则到自动化读取的完整链路》(OBA-k8m3pw7t)：

## L1 · 首轮"看懂运动"过浅，漏掉三类用户可见行为（2026-05-17）

- **现象**：一个拟物指纹扫描视频，我第一轮分析只抓到"指纹自绘 + 渐变 + 循环"，连续被用户纠正 4 次才补全：① 没追踪光标 → 误判成 autoplay 时间循环，实际是 **hover 交互**（移入按下/移出复位）；② 看到了按钮但没建模它的 **拟物按压**（阴影 outset↔inset 翻转）；③ 漏了**两趟绘制**（先白刻痕成形、颜色滞后跟上）；④ 退出当成瞬间消失，实际是 **~0.6s 整体 opacity 渐隐**。
- **根因**：Phase 3.1 只走了一遍且只看"主体在动什么"，把容器/光标/多趟/退场当背景；并且过早宣布"完成标准已满足"。
- **下次规则**：Phase 3.1 必须**专门再看一遍**，逐项点名这四个最易漏维度（光标轨迹→触发模型、容器自身状态、是否多趟绘制、退场是渐隐还是瞬移）；这四项没逐一给出结论前，不得进入产出/宣布完成。已并入 SKILL.md Phase 3.1 清单与完成标准。

## L2 · 复杂图形先手画，浪费一整轮（2026-05-17）

- **现象**：指纹这种复杂图形，我第一版用手搓贝塞尔近似，用户立刻指出"形状差太多"，整轮作废，才改走矢量化。
- **根因**：没在 Phase 0/识别期就判定"动效主体是肉眼无法用几条贝塞尔还原的复杂图形"。
- **下次规则**：识别到主体是指纹/手写/logo/复杂插画时，**跳过手画直接进 Phase 3.5 矢量化**；且先判动画类型再选路线（静态/擦除→potrace 填充；自绘→skimage 骨架中心线）。已并入 SKILL.md Phase 3.5。

## L3 · 反复过早宣布"✅ 完成"（2026-05-17）

- **现象**：多次输出"✅ 对齐完成/三诉求达成"后，用户又发现新的遗漏行为，体感是反复"宣布胜利又被打回"。
- **根因**：把"我做的那部分对了"当成"用户要的行为齐了"，闭环只比对自己关注的几帧。
- **下次规则**：闭环比对必须覆盖 L1 的四个易漏维度对应的关键帧（进入/退出/多趟中段/容器状态），全部与源视频一致才可言"完成"；只要本轮被用户纠正过 ≥1 次，交付前必须更新本文件，否则任务视为未完成。已并入 SKILL.md 完成标准。

## L4 · 环境下载静默停滞（2026-05-17）

- **现象**：`brew install`、`playwright install` 在后台 0 输出挂死，浪费等待。
- **根因**：公司网络需代理；未预判。
- **下次规则**：装包/下载前先 `export HTTP(S)_PROXY/ALL_PROXY=<本机代理>` 前台带 `timeout` 跑；闭环截图优先复用系统已缓存 Chromium（Playwright `executablePath`），不等新下载。已并入 SKILL.md 工具依赖。

## L5 · 两趟绘制的「滞后量」写太小，闭环里两趟塌缩成一趟（2026-05-18）

- **现象**：又一个拟物指纹扫描视频，Prompt 把「颜色趟滞后压痕趟」的相位差写成 ~0.45s，闭环生成的 HTML 在中段帧里颜色已追上压痕，看不到「顶部上色 / 中部白刻痕 / 底部未出」的三段共存——两趟视觉上塌成一趟。
- **根因**：① 相位差只占单趟时长（~1.3s）的三分之一，不足以在任意中间帧拉开可见间隔；② 未上色的「白刻痕」趟用纯白 stroke，在白色拟物按钮上几乎零对比，即使存在也看不出是独立状态。
- **下次规则**：写「多趟绘制」类 Prompt 时——(a) 趟间相位差至少给到单趟时长的 **50%~65%**（如单趟 1.25s → 滞后 ≥0.8s），别写"略微滞后"这种模糊量级；(b) 明确要求未上色那趟有**自身对比度**（略灰 stroke / 雕刻阴影），否则"三段共存"无法被肉眼或闭环验证到。闭环比对必须专门抓一帧落在滞后窗口内的中段帧确认三段，不能只比起末态。已并入 SKILL.md Phase 3.1「多趟绘制」行与完成标准。

## L6 · 把「逐线自绘」误判成「整体遮罩 wipe」——只做时间采样没做空间放大 + 套旧经验 + 闭环验错对象（2026-05-18）

- **现象**：同一个拟物指纹扫描视频，真实机制是**每条纹路作为独立 path 各自 `stroke-dashoffset` 自绘、按行 stagger 错峰并行、笔尖带发光绘制头、画完后白→紫蓝上色**；我两版 Prompt 都写成 `clip-path: inset()` 整体自上而下遮罩揭示。用户直接指出"线条是一条一条出现的"。
- **根因**：① **只在时间维度密集抽帧，没做空间放大**——全程把直径仅 ~130px 的指纹缩成 <300px 小图看 montage，单线独立生长与发光头被糊掉，看到"从上到下"就脑补成遮罩；② **过度套 L1 旧经验**——L1 的"两趟绘制/颜色滞后"被我先入为主当成"双图层+遮罩+滞后填充"，没按 SKILL「读取回退」规则重新独立判读；③ **闭环验错对象**——Phase 4 只比对了"整体是不是从上到下"这种粗粒度表象，用错误心智模型（遮罩 wipe）做比对，机制级差异（逐线 vs 遮罩、有无发光头）被确认偏差放过。
- **下次规则**：(a) 动效主体在原视频里偏小（直径 < 画面 1/3）时，Phase 2 必须 `ffmpeg crop` 到主体区域放大到 ≥400px 再逐帧 Read——"加密"含时间密集采样**和**空间放大两个维度；(b) 命中 lessons 旧经验时先独立判读当前帧、再拿旧经验对照，矛盾以当前为准，禁止拿旧结论直接套；(c) Phase 4 闭环比对必须落到机制级特征（逐线自绘 vs 整体遮罩、绘制头有无发光、stagger 单位是元素还是切线），不能只比整体方向/起末态。已并入 SKILL.md Phase 2 第三轮与完成标准。

## L7 · 修正一个维度时手画复杂图形，把已对的「形状」维度做坏了（2026-05-19）

- **现象**：把闭环 HTML 的机制从「整体遮罩」改成「逐线自绘」时，我顺手把真实指纹 SVG 换成自己生成的 11 条同心拱形——机制对了，形状却烂成一个"皱眉"符号。用户："这个效果越做越差了"。最终走 Phase 3.5 skeleton 中心线从源视频矢量化出 18 条真 ridge 才修复。
- **根因**：① 改一个维度（机制）时没守住另一个**已正确**的维度（形状用真实 SVG），违反 L2"复杂图形别手画"——L2 当时只说"第一版别手画"，没说"修别的东西时也不准退回手画"；② 把闭环验证用的 `index.html` 当成产物在反复迭代，真正的产物是 Prompt，脚手架越改越上头、单次改动同时动了多个维度。
- **下次规则**：(a) 闭环 HTML 是脚手架不是产物，每次改它**只动"被验证为错"的那一处**，其余维度（尤其已验证为对的）必须原样保留；(b) 任何需要复杂图形的位置一律走 Phase 3.5 矢量化，**禁止"临时手画凑一下"**——哪怕只是验证脚手架用；(c) 一轮改动若动了多个维度，交付前逐维度核对没有顺手打破已对的部分。已并入 SKILL.md Phase 3.5 与完成标准。

## L8 · 帧率和起末态都通过，但卡片抽离仍像瞬间换树（2026-08-06）

- **现象**：图片堆叠交互的验收视频是 25fps，折叠态和展开态截图也都正确，但用户仍看不到“一张一张图叠在一起、再逐张抽出”的效果，整体更像淡入后切成列表。
- **根因**：① 折叠态只露出很浅的三层偏移，相近纸色让后层边缘在手机画面中几乎消失；② 实现条件切换了两棵节点树，用淡入淡出连接起末态，同一张卡片没有可追踪的连续空间轨迹；③ 验收只检查起末几何和视频编码/帧率，没有采样中间帧验证同一元素至少经过三个不同位置。
- **下次规则**：堆叠/抽卡类动效必须在密集帧里同时验证“空间层级”和“时间轨迹”：折叠态至少清楚露出三条等尺寸后层边缘；实现优先保持同一批节点常驻，用共享元素或坐标动画逐张 stagger；自动化至少采样三个中间位置并断言元素间距持续变化。帧率、编码和起末态正确不能替代轨迹验证。已并入 SKILL.md Phase 3.1 与完成标准。
