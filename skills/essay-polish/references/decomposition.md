# 根据理解障碍拆解内容

选择能解决当前障碍的方法，可组合使用，不要求每篇集齐。

| 障碍 | 方法 | 具体操作 | 检查方式 |
|---|---|---|---|
| 不知道先学什么 | 路径拆解 | 按读者何时需要某种能力安排顺序，标明每步前置知识 | 新步骤是否依赖尚未解释的概念 |
| 看得到结果但不懂过程 | 分层剖析 | 展示同一对象从输入、转换到输出的变化 | 相邻层之间的转换是否说清 |
| 大任务难以开始 | 任务拆解 | 按可检验的中间结果拆分，每步写明输入与输出 | 子任务能否连接成完整结果 |
| 抽象概念难以理解 | 类比桥 | 选读者熟悉的结构，逐项映射，再说明类比失效处 | 类比是否引入错误规则 |
| 不知道为什么选某方案 | 方案对比 | 用同一场景和约束比较成本、收益与限制 | 推荐是否能从比较结果推出 |

## 通用示例：解释数据去重

先明确业务问题：“同一笔订单重复导入会造成重复统计。”再解释去重依据，避免一上来罗列工具功能。

任务可以拆为读取记录 → 按订单编号识别重复 → 按冲突规则保留记录 → 核对结果。每步都有可观察的输出。

简化示例中，输入编号为 `[A, A, B]`，按编号保留第一条后输出 `[A, B]`。但真实资料可能出现“同编号、不同金额”；这时必须交代保留最新、人工确认或报错等策略，不能假装简单去重解决了业务冲突。

需要比较方案时，比较内存集合与数据库唯一约束分别适用的规模、持久性及并发条件，不宣称某一种永远最好。

这个例子仅用于说明解释方法，不代表某个真实项目的实测结果。
