# Essay Polish

让文章对目标读者更容易理解、更有依据、更能达成写作目的。保留作者的意思与有辨识度的声音；改写力度由用户要求决定。

## 确定任务

先读完用户提供的正文及必要上下文，从已有信息确定：

- 读者已知什么、希望读完理解或做到什么。
- 文章类型：观点论述、经验分享、解释说明、实操教程或系列文章。
- 本次范围：表达润色、结构重写、素材成文或只做诊断。
- 应保留的观点、事实、术语、篇幅、格式与发布语境。

已有正文时默认直接改稿。仅缺少会改变核心论点或读者定位的信息时追问；小的风格选择自行处理。用户只要润色时，不擅自改变论点、篇章架构或补写大量内容。只要诊断时，不把整篇改写当成默认交付。

## 工作方法

### 1. 找出内容骨架

用一句话明确中心问题和文章要给出的回答。识别各段职责：提出问题、说明概念、提供依据、展开推理、举例、限定适用条件或给出行动。

- 删除不服务写作目的的重复；有价值但打断主线的细节移至注释或补充材料。
- 区分事实、作者判断、假设与待核实信息。不得把推测改成定论。
- 多份素材先去重并识别矛盾，不用流畅措辞掩盖证据缺口。保留关键论断、引文与原始来源的对应关系；来源冲突时说明分歧，不擅自拼成一致结论。
- 没有素材、只有主题时，先确定读者目标和所需资料；无法核实时缩小论断或明确待核实处。

### 2. 调整顺序与解释

一般文章围绕中心问题组织：必要背景 → 核心判断 → 依据与推理 → 适用边界或行动。它是判断顺序的参考，不是必须出现的标题模板。

让每段回答一个明确问题，并让下一段承接读者自然产生的疑问。论述有跳跃时，补上真正缺失的解释；不靠“显然”“因此”伪造因果关系。

复杂内容按障碍选择拆解方法，读取 [references/decomposition.md](references/decomposition.md)。教程或教学型系列文章额外读取 [references/tutorials.md](references/tutorials.md)，一般文章无需加载该专项。非教学型系列只检查主题一致性、篇章关系和必要衔接，不强加学习目标、运行案例或操作检查点。

### 3. 打磨语言

- 优先用具体主体、动作和结果；缩短不承载信息的铺垫。
- 保留必要术语，首次出现时按读者基础解释；不要为了口语化损失准确性。
- 合并重复表达，拆开同时承担多个推理任务的长句。
- 用自然过渡连接因果、对比与递进，避免每段套固定句式。
- 保留合理的犹疑、限定和个人表达，不统一改成营销口吻。
- 例子用于解释关键难点；不堆砌案例、反问、类比或夸张承诺。

### 4. 核对与交付

交付前按 [references/review.md](references/review.md) 核对适用项，修正实际发现的问题。

默认交付完整改稿，并用少量文字说明影响最大的调整。用户要求只给正文时，省略说明。仍影响可信度的缺口单独注明，不把未经核实的新增事实混入成稿。

文件任务遵循用户指定位置与覆盖方式；未授权覆盖时另存改稿。重构素材时保留原始资料。只在本次授权范围内写入，不自动发布、安装依赖或上传资料。

## 内容与证据边界

- 不编造数据、引用、出处、人物经历、实验结果或运行记录。
- 用户原稿中的数字与引文不会因为经过润色就变成已验证事实；关键疑点应指出。
- 源码能支持行为说明，不一定支持作者的设计动机；推断要标明。
- 示例和类比需标明适用边界；代码片段不能冒充完整可运行案例。
- 没有执行条件时可以提供复现步骤与预期现象，但须明确尚未实测。
- 对外文章应消除只有原作者才理解的内部简称、私有链接和环境前提；保留公开理解所需的上下文，不擅自公开私人素材。

本 Skill 独立使用，不依赖特定知识库、个人路径、浏览器工具或其他 Skill。输出形式服从用户需要，不默认生成网页或建立额外工作流。
