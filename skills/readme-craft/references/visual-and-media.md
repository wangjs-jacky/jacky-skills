# 视觉与媒体制作规范

## 1. 三类视觉资产的选型边界

| 资产形态 | 适用场景 | 交付格式与源件 | 避坑红线 |
|---|---|---|---|
| **Hybrid 混合视觉大图**（首选） | Hero 封面、3D/图层拆解图、作品墙、前后对比展示 | HTML/CSS 或 SVG 排版 + 真实透明素材/洁净截图 → 无头 Chrome 高清输出 `PNG/WebP`（`1600×900` 或 `1600×960`） | 不要把大段说明文塞进图里；单张大图尽量控制在极少短标签，让真实画面占 80%+ 面积 |
| **纯矢量 SVG** | 极简标题条、轻徽章、极少文字的几何/时间线示意 | 纯标准 SVG 1.1（`viewBox` 宽 `1200~1600`），系统字体栈 | 禁止 `<foreignObject>`、`<script>`、外链字体与未内联本地相对图片；禁止画满屏文字矩形框的“PPT 流程图” |
| **GitHub 原生可播 MP4** | 交互工具、网页应用、动效/操作流程演示 | 真实录屏 `H.264 / yuv420p` MP4（仓库可存档原件）+ **GitHub `user-attachments` 独立段落 URL** | 禁止在 README 里直接写 `[demo](demo.mp4)` 充当播放器（GitHub 只会跳转文件页）；禁止同页再堆叠同内容 GIF |

## 2. Hybrid 混合大图制作清单

1. **提取真实素材**：优先使用仓库内已有高清素材（透明 WebP/PNG 渲染层、洁净页面截图、真实终端/文本输出），排查并去除浏览器扩展图标、私密路径或无关干扰元素。
2. **锁定色彩与明暗兼容**：
   - 给画布加明确的底色与微弱外框（如暖纸底、深橄榄绿或深炭灰卡片），确保在 GitHub 亮色与暗色主题下都有清晰边界。
   - 若要突出光效、材质或 UI 细节，可在画面中段安排一块深色对比舞台，与浅色底形成视觉重心。
3. **严格控制字数与图层顺序**：
   - 背景光效置于最底层，主体素材居于中层，极简标注线与角度/坐标提示置于最顶层（避免标注被主体遮挡）。
   - 严禁浮层标签压住界面里的关键按钮或文字。
4. **本地高清渲染与目检**：
   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
     --headless=new --disable-gpu \
     --window-size=1600,900 --force-device-scale-factor=1 --hide-scrollbars \
     --screenshot="/path/to/docs/readme/output.png" \
     "file:///path/to/artboard.html"
   ```
   渲染后必须用读图工具逐块核对边缘裁切、阴影、文字对齐与清晰度，达标后再嵌入 README。

## 3. 操作类实机 MP4 规范

1. **单任务闭环脚本**：围绕一个完整真实任务录屏（15~30 秒为宜），起点是干净初始态，过程展示真实输入/操作变化，终点落到文案承诺的最终产出（如导出结果、复制结构化上下文、页面状态切换）。
2. **媒体参数**：编码 `H.264 (yuv420p)`、无坏帧或长停顿；如通过逐帧采集合成，需检查相邻帧间隔并在素材记录中如实注明实际采集帧率。
3. **GitHub 原生嵌入**：
   - 上传至对应仓库的 GitHub 附件存储，取得稳定的 `https://github.com/user-attachments/assets/<uuid>` 地址（不要用带过期签名的临时链接）。
   - 在 `README.md` 中**单独成段**粘贴该 URL，前后保留空行，使 GitHub 自动渲染原生播放器。
   - 推送分支后在真实 GitHub 仓库首页（桌面 + 窄屏）确认播放器可就地播放。

## 4. 素材与核验记录（`docs/readme/SOURCES.md`）

若为仓库新增了原创主视觉、拆解图或实机视频，建议在 `docs/readme/SOURCES.md` 用简短表格记录：
- 文件名、尺寸与来源（真实截图 / 渲染图层 / 录屏）；
- 核验范围与未覆盖边界（例如“仅核对桌面与窄屏仿真，未做真机输入法验收”）。
