## 开始前：渐进读取

1. 从当前 Skill 的实际位置定位知识根目录。若有小型 `experience.local.md`，按需读取本次实例入口。
2. 读[分类模型](references/ops-model.md)和[对象索引](references/{{COLLECTION}}/index.md)，按当前目标命中 key。
3. 仅读该对象 `index.md` 和本次 operation；不扫描整个库。
4. 用当前证据复核目标、环境、前置状态和适用条件。历史记录不能覆盖用户当前说明。
5. 缺少经验时，在现有授权下使用当前执行工具探索，按模型中的证据策略记录；不要编造既有成功。分类规则不足时再确认，不猜测迁移。

## 自动沉淀与收尾

每次完成、失败或中断时，读取[知识格式与写回协议](references/knowledge-schema.md)，按证据执行写回，不等用户另行要求记录。

- 共享事实更新对象档案，具体目标经验更新 operation，私有实例更新 ignored 文件；同步相关索引。
- 有真实完整成功才刷新 `last_verified`；重复成功仍维护验证日期，正文无新事实不重复追加。
- 部分结果和失败不得冒充成功；确有可复用事实时按证据策略记录，否则说明无新增。
- 写入受阻或检查失败时报告未沉淀，并给出可应用的修改；不得宣称已经保存。
- 如已有适用结构校验器，按当前检查授权执行并说明结果；静态检查不证明业务成功。
- 先完成知识处理，再按执行工具规则收尾。用户接管或控制权失效时立即遵循工具的停止规则，只处理已获得且允许保存的证据。

报告本次结果、实际写回位置、证据范围和遗留项。自动沉淀仅修改知识，不自动提交、推送或执行额外业务动作；它依靠 Agent 遵循协议，不是后台监控服务或宿主强制钩子。

## 私有信息

真实账号、路径、环境映射与证据位置只保存在 ignored 的本机记录。凭据、Cookie、Token、签名 URL、完整业务响应不进入任何经验文件。可分享知识不得依赖创建者机器的绝对路径。
