# 创建与迁移

改造已有 Skill、脚本、功能或经验文档时读取。先确定哪些能力由现有执行工具提供，哪些经验应由 OPS 维护。

## 盘点并给出映射

只查看本次目标和直接相关材料，记录：

| 原内容 | 新的唯一归属 | 处理方式 |
| --- | --- | --- |
| API 用法、连接、任务空间、控制权 | 原执行 Skill/工具 | 保留调用，不复制成 OPS API 手册 |
| 多操作共用的边界、配额、入口、陷阱 | 对象 `index.md` | 提取来源、条件和核对日期 |
| 一个真实用户目标的工作经验 | 对象下 operation | 保留前置条件、成功标准与证据 |
| 账号、机器、路径、部署映射 | ignored 私有实例 | 脱敏后再决定是否有共享价值 |
| 想法、未验证流程 | 分类模型候选清单或明确的 documented 文档 | 不升级为成功经验 |
| 过期或冲突规则 | 原归属的修正记录 | 给出证据和适用边界，更新路由 |

先确认分类，再执行依赖该分类的移动。现有 schema 能满足目标时优先保留，不能为了套模板破坏消费它的脚本、索引和安装路径。

## 新建时的最小产物

1. 入口、确认过的分类模型、路由索引、知识格式、安装提示词和忽略规则。
2. 只为已知对象创建对象档案。没有事实时路由可以为空，写明尚无已验证经验。
3. operation 仅从用户范围、现有证据或明确的设计需求产生；文件是否允许保存未验证知识，由分类模型中的证据策略决定。
4. 需要 UI 元数据时按官方 `skill-creator` 的当前格式生成 `agents/openai.yaml`，保持正常自动发现。

`create-ops` 是创建工具；生成的领域 OPS 必须可独立运行，模板和规则要写进目标目录，不能引用创建者机器上的绝对路径。

## 保护真实历史

- 导入旧经验时保留原验证日期和证据，不把迁移日期当作验证日期。
- 无证据的“成功”不能自动变成 `verified`。保留为待核实说明，或按目标 schema 降级。
- 已有“仅接受成功验证”模型继续使用，候选需求留在模型清单；不要批量给它加入新状态。
- 当前证据推翻旧结论时修正或降级相应记录，不能只追加一段相反结论。
- 同一事实只保留一个权威来源；拆分后更新旧入口为链接。确认没有消费者后才移除重复内容。
- 私有经验迁移前确认忽略规则；凭据、签名 URL、完整业务响应不进入任何经验文件。

## 完成迁移的核对

读回关键路由和一个相关 operation，确认入口确实能抵达；核对原功能调用、脚本参数、授权和收尾规则仍有归属。移动或重命名时检查所有直接引用、安装链接与消费 schema 的脚本，保留用户无关改动。

只报告实际做过的检查。没有业务运行证据时交付“结构改造完成，业务行为未重新验证”，不把静态检查当作线上成功。提交、推送或发布沿用任务授权，不由 OPS 写回协议自行触发。
