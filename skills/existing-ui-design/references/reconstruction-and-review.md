# 页面复原与交互核验

用于从现有网页提取底稿并制作交互原型。它补充容易漏掉的复原问题，不替代 Ego 的操作和证据协议。

## 采样范围与公开副本

采样当前可见、与任务相关的界面，包括布局容器、computed styles、主题变量、字体和必要图标资源。动态页面在授权范围内进入代表状态，再记录该状态的结构和交互；不要仅凭空页面猜有内容后的样子。

单页应用可能在根 DOM 中保留隐藏的旧路由、其他会话或不可见面板。直接复制整个 document 既可能泄露内容，也会把旧状态带入原型。先确定当前可见子树；公开副本只保留需要的结构，替换历史内容、身份、头像、机器、文件路径和动态标识，移除脚本、隐藏业务数据、认证材料与真实提交地址。

优先使用项目已有可分享资源；需要采集资源时核对其用途和公开范围。保留字体及图标的实际加载证据，不以 CSS 声明存在推断已经加载。原始采样资料留在私有工作区；只把经过筛选的静态文件写入发布工作区，不能把整个采样目录直接发布。

不依赖某次页面的混淆类名、固定祖先层级或任务空间 ID 编写通用抓取器。页面结构变化后重新定位可见容器。

## 复原证据

对比原页、无新增功能的底稿和设计稿，使用相同视口、主题、代表内容和滚动状态。至少观察：

| 锚点 | 核对内容 |
| --- | --- |
| 主布局 | 导航与主区的宽度、对齐、分隔和背景 |
| 核心操作 | 输入框或主要操作栏的位置、尺寸、可达性 |
| 内容密度 | 字体实际加载、字号、行高、行距与间距 |
| 窄屏与浮层 | 容器边界、可见范围、遮挡和内部滚动 |

允许存在与目标相符的适配，但要指出哪些是原样复原、哪些是新增设计、哪些仍为推断。不要凭一张桌面截图宣布手机端也已复原。

## 从静态 DOM 恢复交互

复制出来的 DOM 只记录一个时刻的状态，不携带原框架完整的状态管理。例如空输入时的发送按钮可能保留 disabled；必须根据新输入更新状态并实际点击，不能只验证文本已填入。

把关键动作串成完整用户路径。例如对话产品可以是“展开条目 → 查看产物 → 带回原输入框 → 演示发送 → 返回继续阅读”；其他产品按其实际流程选择，不照搬示例。

对保存功能验证“编辑 → 保存 → 关闭重开 → 刷新”，说明保存到本地还是服务端。多版共用存储时避免反馈或设置意外串版；版本切换后不应误报已提交真实业务数据。

布局中隐藏内层面板可能仍留下外层 slot 的占位宽度；根据真实容器结构调整。overflow: hidden 可能掩盖横向裁切，document.scrollWidth <= viewport 并不能证明内容完整。核对主要内容、按钮、输入框和弹窗实际边界及可点击性。

## 让多版可以公平比较

每版围绕同一个问题提出不同答案。例如已有对话中的新增任务信息，可以比较就地展开、当前内容旁的详情区、按需打开的详情层；它们仍沿用同一产品底稿。具体选择服从空间、任务复杂度及用户反馈。

版本切换尽量保持相同内容、展开深度和当前位置，避免把状态差异误认为设计优劣。用简短记录保存每版的假设、关键差异、已核验路径和用户反馈；不得将未回复记作接受。

Happy 发布快照不可变时，更新内容需要新的受管快照；按工具实际语义操作，不能承诺修改旧链接会自动更新。多个候选合在一个快照中可减少预览槽占用。槽满时报告现有预览，未经用户授权不关闭旧链接。
