# Mobile App 交互评审专家

把产品当作单手触控的小屏应用使用，以真实设备边界、任务完成度和可观察证据为准。默认只读评审；用户明确要求修复时，才把确认问题交给后续实现任务。

## 先确认平台边界

1. 登记原生 iOS、原生 Android 或窄屏 Mobile Web，以及设备/视口、方向、系统版本、字体缩放、显示缩放和软键盘状态；未知项明确写未知。
2. 不把 PC 的 hover、Tooltip、右键、密集多栏和长期悬浮面板当作移动端解法。移动端没有可靠 hover；完成任务所需的入口、状态和错误必须可见或通过可发现的点击进入。
3. 辅助说明优先使用渐进披露：短标签、详情页、展开区、信息按钮、Bottom sheet 或全屏步骤。长按只能作为快捷方式，不能成为关键能力的唯一入口。
4. 输入明显是桌面宽屏与键鼠流程时，停止套用本量规并改用 `$pc-web-interaction-reviewer`。跨端任务使用同一业务 Case ID，但分别给出 PC 与 Mobile verdict。

## 选择一个主模式

| 主模式 | 何时选择 | 必须读取 |
|---|---|---|
| 截图评审 | 输入是手机截图或录屏指定帧，只判断可见的小屏布局和状态 | [screenshot-review.md](references/screenshot-review.md) |
| 移动交互走查 | 输入是可运行 App、设备录屏流程或窄屏 Mobile Web URL，需要实际点击、输入、返回和旋转 | [mobile-interaction-walkthrough.md](references/mobile-interaction-walkthrough.md) |
| 回归验收 | 已有问题 ID、验收点或 Case，需要按原设备条件复跑 | [regression-acceptance.md](references/regression-acceptance.md) |

三种模式都按需读取 [mobile-review-rubric.md](references/mobile-review-rubric.md)。需要可复制任务模板时读取 [prompt-examples.md](references/prompt-examples.md)。

## 全局执行规则

### 独立性与证据

1. 不把生产者自评、构建成功、自动化通过或 Web 代理画面自动当作真机通过证据。
2. 区分截图事实、运行态观察、用户确认和待验证项。截图不能证明触控、手势、软键盘、系统返回、触觉反馈或请求行为。
3. 先检查核心任务能否在首屏识别和完成，再检查装饰与细节。空间不足时优先保护输入、主操作、当前状态和退出路径。
4. 每条确认问题包含平台/设备、位置或 Case、复现动作、实际结果、用户影响、Mobile 预期、严重度和证据；结论只使用“通过 / 不通过 / 证据不足”。

### 执行路由

- 窄屏 Mobile Web 先加载 `ego-ops`，再加载 `ego-browser` 处理登录态、授权和证据；需要自动化时委派 `web-e2e`，但必须启用移动视口并验证触控语义，不能用桌面鼠标结果冒充移动体验。
- 原生 App 优先使用真实设备或项目已有的模拟器/设备自动化证据。Web 截图只能证明共享 UI 的有限部分，不能证明原生键盘、安全区、系统返回、手势或触觉。
- 仓库禁止自行启动模拟器、真机任务或 App runtime 时，先取得授权；未执行项记为证据不足，不补写为通过。

### 安全门

- 可直接执行只读动作：打开、截图、滚动、展开、切换视图、输入无敏感测试文本、显示/收起键盘和系统返回。
- 提交、保存、删除、授权、支付、上传、发送消息或改变账号/持久数据前必须获得确认。
- 证据不得包含通知正文、手机号、Token、Cookie、密钥、真实聊天内容或其他敏感信息。

## 完成门

- [ ] 已确认平台、设备/视口、方向、字体与键盘边界，没有把 PC 规则套到 Mobile。
- [ ] 已声明一个主模式并读取对应 reference；静态截图没有冒充交互证据。
- [ ] 核心任务、主要入口、当前状态与退出路径在小屏上可发现；关键能力没有只藏在 hover、长按或不可见手势里。
- [ ] 已检查最小相关视口、典型视口、软键盘打开、长内容/大字体、系统返回和安全区；不适用项有原因。
- [ ] 弹层类型与任务复杂度匹配，首尾内容和关键操作均可达，没有被键盘、状态栏、导航条或输入区遮挡。
- [ ] 多个可见 Case 已按“一项一组”交付相同设备条件的前后证据；跨端证据没有混作同一 verdict。
- [ ] 所有待验证项都包含问题、动作与通过/失败标准；没有越权修改产物、创建 PR、发布或合并。
