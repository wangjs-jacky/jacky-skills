# Goal First 任务工作台

DeepSeek Harness 的任务工作台：集中查看凝练目标、交付约定、实际文件、原生任务对话和用户对具体交付版本的认可。

[English](README.md) · [开发与验证](DEVELOPMENT.md)

## 安装与升级

需要 Node.js 22 或更新版本。当前对接 Harness 0.2.2-rc.1，使用公开 Cordis 接口。

在本包目录中执行：

```sh
npm run check
npm test
npm run build
```

然后用 Harness 插件管理器安装本包目录。入口指向版本化的构建结果，因此从源码安装前需要构建。运行和构建均无需额外 npm 依赖，没有安装脚本。

升级时遵循插件管理器的回执；同路径已经登记时，先移除旧安装登记，再安装新目录。同一组 Goal First 工具只能有一个活动实现。项目资料、任务状态和会话关联保存在包目录之外。

## 从任务到交付

1. 从“全部项目”进入项目。卡片显示原档案的凝练摘要、预期交付、实际交付入口和认可状态；完成记录与用户认可分开展示。
2. 点卡片查看详情。“新建对话”在任务目录打开空白原生对话；“执行任务”才提交该任务。已有执行显示“查看执行”，直接继续原会话；旧任务也能直接查看历史，无需先新建空会话。
3. 需要调整时，点击目标旁的“与 AI 调整”。模型可以读当前资料、整理只读草案；用户点击“确认这次调整”才归档。任务执行中可保留草案，不能覆盖冻结的执行依据。
4. 从文件树打开原文件，使用正文、源码和多标签阅读。“在原生阅读器打开”复用已安装的 Harness 文件渲染器。回到主界面时继续同一个会话。
5. 查看最终交付并认可具体版本。文件内容或交付约定变化后，旧认可失效；旧预览不会自动取得新版本的认可标识。界面会显示原因，并提供“查看最新版本”。

“进行中”筛选与卡片、详情四周的执行高光共用相同事实。图片加载失败会显示可读恢复提示，确认保存、登记和认可都有独立反馈。支持减少动态效果设置及详情标签的键盘切换。

## 文件与资料

资料来源支持默认发现及额外目录。移除来源只改变显示范围，不删除档案。任务文件取数沿用当前任务路径边界；目录按需展开，拒绝符号链接，文本与图片预览有大小限制。内嵌 HTML/SVG 预览隔离脚本、外部请求和表单；其他格式可交给原生阅读器。

任务状态仍只认原任务入口的 YAML `status`。确认目标、提交执行、生成文件、用户认可分别记录。薄导航确认时只更新一句摘要，完整契约归入原任务说明的补充段，保留已有授权和历史。
