# 评审量规：App UI / 设计

> 用于独立评审一份 App 设计是否可实现、状态完整、可访问且与平台一致。量规只列维度，具体标准随 scope 收敛。

## 事实型 must-pass（先核对）

- **可实现性**：设计是否能用目标技术栈与平台能力落地；是否依赖不存在或成本失控的效果。
- **状态完整**：关键界面是否覆盖空态、加载、错误、无权限、超长内容等状态，而不只是理想态。
- **无障碍基线**：对比度、可点击区域、动态字体、屏幕阅读器语义等是否达到基本可用。
- **平台一致**：导航、手势、系统控件、安全区是否符合目标平台约定，不生搬另一平台范式。

## 主观质量（事实通过后再评）

- 视觉层级与信息密度是否服务任务，是否有明确的视觉主张。
- 交互反馈、动效是否有意义，而非堆砌。
- 组件与 token 是否可复用、可扩展。

## 判定要点

- 无法实现、关键状态缺失或无障碍不达标，属事实型 fail。
- 只有静态稿、缺少交互/状态说明而无法判断行为，记 `insufficient_evidence`。
- `high_impact_fixes` 优先补齐会阻断实现或验收的缺口，而非美学微调。
