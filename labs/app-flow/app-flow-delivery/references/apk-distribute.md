# 安装包 / 直装分发的通用边界

> 面向“把安装包（APK/IPA 或等价产物）直接分发给用户或内测者”这一动作的跨平台通用取舍。具体渠道、地址和账号由目标仓库现场决定，本机私有值只留在被忽略的 `local/`。

## 分发前核对

1. **签名与身份**：安装包由正确、未过期的签名身份签发；同一 App 的不同渠道签名策略是否一致，避免覆盖安装冲突。
2. **版本与构建号**：对外版本号与内部构建号单调递增，用户能区分新旧；同一版本号不重复覆盖不同产物。
3. **包标识一致**：包标识（applicationId / bundle id）与目标渠道一致，且不与已装的其他变体冲突。
4. **完整性**：提供并核对产物指纹（哈希/大小），确保用户拿到的包未被截断或篡改。
5. **安装来源**：目标设备是否允许该来源安装（系统对未知来源、企业签名、TestFlight 类通道的限制），并给出用户可操作的安装说明。

## 分发方式的通用取舍

- **内部直装 / 内测通道**：迭代快、门槛低，适合评审与内测；需明确标注为非正式产物，并控制可见范围。
- **商店 / 受管渠道**：面向正式用户，受审核与政策约束；版本策略、权限声明、隐私说明需与渠道要求匹配，节奏比直装慢。
- 无论哪种方式，都要有回滚或撤回预案，以及发布后验活（可安装、可启动、关键路径可用）。

## 边界

- 分发只交付已构建、已验证的产物；基础代码问题退回构建能力，不在交付阶段临时改代码。
- 每次分发都重核当前渠道授权，未获授权只做预检与交接。
- 迁移到新项目/新平台时重新确认签名体系、版本策略、安装来源限制与渠道政策，不照抄任何具体渠道配置。
