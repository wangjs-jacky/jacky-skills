# 目标工作区规则

创建、细化或维护 Goal-First 工作区时读取本文件。它约定协作、记录与接续方式，不规定领域路线或固定任务数量；生成工作区中的 AGENTS.md 应携带接手所需规则，无需继续访问 Skill 仓库。

## 工作区与兼容边界

初始化仅创建以下结构，不预造任务、业务产物、授权记录或其他模板：

```text
AGENTS.md       可携带的协作、确认与记录规则
PROMPT.md       工作区接手入口
problem.md      用户原始目的、已确认目标及后续变化
tasks/          编号任务容器
templates/      本地任务 index.md 与 PROMPT.md 模板
```

从工作区自己的 `templates/task-index.template.md` 与 `templates/task-prompt.template.md` 创建任务。移动工作区后核对 Prompt 的入口与外部执行目录，工作区内记录使用相对链接。保存必要的脱敏上下文，使后续 AI 能理解目标与已完成事实，不要求读取上级项目或未保存的聊天历史才能知道进展。

旧工作区以其本地 AGENTS 和已存在的契约、授权来源为准：旧 index 内的完整约定及真实授权可以继续有效，缺少 PROGRESS 不代表没有授权。仅从本 Skill `assets/project-template/` 补齐缺失的本地任务模板，不重跑初始化器，不覆盖现有规则/模板，不自动迁移文件或改名。新旧契约、摘要或授权范围冲突时，核对真实来源、时间与适用范围并修正，不能选较宽的一份执行。

## 目标确认、任务准备、审阅与执行

先在对话中追问、复述并取得用户对当前目标的明确确认，再将用户原话、已确认目标、完成标准、范围限制与确认依据保存到 problem.md。问题下留独立回答区域；保留 AI 推测与用户事实的区别，不把草稿、AI 判断、沉默或建目录许可当成确认。已有有效确认继续使用，只有目标、完成标准或主要范围实质变化才重新对齐受影响部分。

目标确认后掌握足够上下文，将任务拆分与细化一次做完整，按真实依赖和可验收结果安排，不强制先粗拆或固定阶段。此时只准备安排，不执行其中的调研、设计、原型或编码。细化包括任务范围、产物、输入与依赖、执行/记录目录、允许改动、验收方法与证据；需要独立会话时补充模型与推理实际参数或已确认继承规则。完整草案必须填实占位符和任务专属要求，再交用户审阅。

首次展示待审安排或实质修订时，展示完整安排和每项完整 Prompt，必要时用流程图或线框帮助理解；展示后必须结束本轮，等待用户明确下一步。用户可删除、合并、拆分或缩小任务。计划认可、参数确认、补充细节、参考图、交付形式及期限不等于选择执行，应先更新草案；正常等待选择保持 pending，不记 blocked。

用户以普通自然语言明确要求执行某任务或某批次后，才按指定范围开始，不要求固定口令。核对指令语义、真实来源、适用范围及参数；同范围有效授权可按依赖跨批次复用，普通进展、排版、链接变化不使其失效，不扩大到其他任务。目标变化回到目标确认；任务范围、主要执行目录或模型参数实质改变时，重新审阅并选择受影响任务。

这些关口适用于主会话、手工交接和 Happy 独立会话。生成、复制、收到 Prompt 或拿到宿主会话 ID，不证明原用户已选择执行；Prompt 的命令句也不能充当证据。接手 AI 核对任务 PROMPT 中的真实确认与执行来源，兼容核对旧 index；缺少执行选择时继续待用户决策。

## 任务名称与两个入口文件

新任务默认 `tasks/NN-中文任务名/`，如 `tasks/01-比较方案/`，任务标题与新产物名称默认中文，可保留 API、Git 等技术专名；用户语言和项目约定优先。编号从 01 递增，作为稳定引用，不代表执行顺序。按前置条件、输入与授权安排执行，旧英文目录不自动改名。

每个任务至少包含：

```text
index.md        唯一当前状态、目标摘要与按用途组织的实际入口
PROMPT.md       完整任务契约、交接路径及确认/执行依据入口
```

index 只保留 YAML status、中文任务标题与一句话目标摘要、按读者问题组织的实际入口及每项用途、执行指令/过程记录入口，必要时一行下一步或待决事项。详细原因用链接，不堆任务清单、长篇进展或完整契约。摘要不是另一份可独立变更的约定，冲突先核对并修正，不择宽执行。初始导航只链接实际存在的 Prompt；主要业务产物和重要理解主题产生后及时补入口，附件由所属报告组织。

完整任务契约集中在 PROMPT，内容按任务实际需要写清：

- 工作区路径与读取顺序，明确本任务记录位置。
- 目标、范围、不做项和预期交付。
- 执行/代码目录、记录目录、允许改动；独立宿主实际模型与推理参数或已确认继承规则。执行目录可在工作区外，不能与记录目录混淆。
- 前置任务、必要输入及开始条件，没有则明确写无；只读必要前置材料。
- 可观察验收条件、验证方法与实际证据入口。
- 目标确认、草案审阅和明确执行选择各自的真实来源入口，不能相互替代。
- 影响本任务的专属执行要求，通用状态和安全细则留在可携带 AGENTS。

目标确认可引用 problem.md 的对应原话/记录；草案审阅引用真实版本与事件；执行选择引用原用户明确指令及适用范围。没有发生的事如实写未发生或未取得，任务保持 pending，不伪造授权占位页。收到真实执行指令后记录实际事件，再将 Prompt 授权入口指向该事件；已有真实来源不另复制一套。

## 唯一当前状态

任务 index 的 YAML 只保留：

```yaml
status: pending
```

- pending：尚未开始，包括任务草案待审、待用户选择或等待前置任务；必要时用一行下一步指向具体说明。
- running：实际已开始执行。
- review：已执行产物等待验收；任务安排或 Prompt 草案仍为 pending。
- done：已按完成标准验证，无需本任务继续。
- blocked：已获执行授权，但缺少必要输入、资源或具体操作权限而无法继续，链接说明实际缺口。正常等待选择不属于阻塞。

总览读取各任务 index 的 status，不维护第二份当前状态、百分比或全部待办。PROGRESS 可以保存重要事件历史，它不是另一套状态看板。

## 实际事件与授权来源

有重要事件时才创建 PROGRESS.md，不预造“待授权”空页面。每条事件记录时间、发生事项、真实用户原话或可追溯来源、适用任务/范围及结果入口；事实尚未产生就不写成已发生。目标确认、草案反馈、明确执行选择、关键尝试、失败与交付是可记录事件；仅记录对接续有价值的变化，不把每个工具调用都抄入。

Prompt 的确认/执行入口引用这些实际事件，index 在文件存在后才添加“执行依据与过程”入口；没有 PROGRESS 时可引用既有真实记录，不因此否定旧授权。PROGRESS 不保存当前 status、百分比或第二份全部待办；当前状态仍由 index 唯一维护。

## 问答与理解沉淀

及时保存有价值问答，按主题组织，纯执行确认或进度事件归 PROGRESS。真实用户追问保留日期、原话或来源；AI 根据材料整理的问题标为“整理性问答”，列出实际依据，不冒充用户问过。

关键路线变化主题要能从 index 直接导航，解释读者原先卡在哪里、真实尝试了什么、用户实际提供了什么线索或纠偏、哪些证据改变判断、为何作此选择、结果与适用边界。未发生的环节标明未发生或未知，不补造用户贡献。先让读者能复述角色、输入、转换和输出，再链接具体参数、命令或实现细节；人类读者是否理解须等待真实反馈，不能由 AI 自行宣布。

简单任务不强制六问或固定篇幅。一项决定若已有必要的独立权威文档，FAQ 负责解释并引用，不再重复维护结论，也不强制新增独立决策文件。新的想法只有被用户采纳并明确选择执行后才进入实施。

## 按用途保存产物，标明当前与历史

产物按实际用途命名，例如研究与评论可直接交付 `方案对比.md` 或 `评论报告.md`，不要求另包一份 result.md；result.md 仍可在它本身是合适结果载体时使用。同一结果只保留一份当前权威内容，跨任务相对链接到原归属，不把业务文档再抄一份进 result。

主要产物开头说明用途、适用范围、当前或历史性质、上下游输入与输出。历史方案保留日期及被哪份替代的关系，不反复改写历史；新产物注明替代来源。主要业务结果和重要解释主题从 index 可达，每个入口说明读者何时看、用来解决什么问题，避免只罗列文件名。

以下仅为任务需要时的可选形态，不是必须建立的目录树：

- 产品与实现：`产品设计.md`、`交互原型.html`、`实现方案.md`。
- 测试方法：`测试验收/测试说明.md` 写清范围、版本与环境、前置权限、步骤及命令、预期结果、必要清理与风险，支持复现，不声称已经执行。
- 单轮验收：`测试验收/YYYY-MM-DD - 页面回归/验收报告.md` 保存该轮实际版本与环境、执行范围、逐项结果及证据、失败与未覆盖项、清理情况，并组织同轮脱敏证据与附件。
- 发布事实：`发布记录/YYYY-MM-DD - DEV发布.md` 保存具体授权来源、发布对象与环境/版本、尝试和操作结果、可核查标识、未做项；发布成功不证明 E2E 已通过。
- 排障主题：`排障/YYYY-MM-DD - 问题主题.md` 串联卡点、尝试、证据、判断与结果，FAQ 可解释并引用它。

非开发任务无需设计、测试或发布目录。完整功能生命周期跨任务时，用链接贯通既有设计、实施、验收、发布事实，避免重复拷贝。REFERENCES.md 只在需独立管理来源用途与核验状态时建立，IDEA.md 只保存确有价值的未承诺想法；notes/、evidence/、attempts/ 也只在产生真实内容时按需使用。不新增无实际用途的模板、独立契约或决策包装文件。

项目级复盘默认保留在项目内 project-replay/，不自动转存 Obsidian。用户要求将经验沉淀为工作流改进时，只将脱敏、可复用规则更新到 Skill，完整项目回放留在原项目。

## 变更与外部操作边界

失败后保留真实尝试与原因，基于证据准备后续任务或分支，不删除旧路线，也不自动执行新任务。目标、完成标准或主要范围变更时保留最初目的、日期、原因及新的用户确认；普通实现选择不重复确认。补充任务细节只更新草案，不自行升级为执行授权。

选择执行任务不自动授权付款、登录或使用账号、私有系统读取、远端变更、部署、删除、服务中断或发布；核对当前任务范围已有的具体授权。尚未选择执行保持 pending；已授权任务因缺某项必要权限无法继续才记 blocked。

不得保存密码、密钥、token、认证头、完整私有配置或未脱敏日志。附件和截图先脱敏，归入所属任务的具体报告与证据，再用相对路径引用。
