# Goal-First Workflow Rules

只有创建、拆分或维护 Goal-First 工作区时才读本文件。它定义工作区内的持久化约定，不规定某个领域的任务数量或技术路线。

## 工作区边界

初始化目录就是一个目标的根目录。它包含：

```text
AGENTS.md       本目标的协作和沉淀规则
PROMPT.md       交给独立 AI 的入口提示词
problem.md      用户初始目的和重要后续变化
tasks/          编号任务目录
```

工作区应可移动和独立使用。不要要求后续 AI 读取 Skill 仓库、上级项目或聊天记录才能理解已经保存的目标和进度。

## 从问题到任务

先让 `problem.md` 保存用户的话和 AI 整理后的正式需求。每个问题标题下留出独立空白区域，便于用户输入，不把问题和回答混在同一行。

只有目标、完成标准和主要限制足够清晰时才拆任务。任务按真实依赖和可验收结果划分，不按固定阶段或固定数量划分。可以先有调研任务，再根据发现创建验证、实施、验收或学习任务；不需要的任务不创建。

目录格式为 `tasks/NN-short-description/`，`NN` 从 `01` 起递增。每个新任务至少包含：

```text
index.md        状态、目标、产物入口和简短进展
PROMPT.md       可直接复制给独立 AI 的完整任务指令
```

任务 `index.md` 的 YAML 只保留：

```yaml
status: pending
```

状态含义：

- `pending`：尚未开始。
- `running`：正在处理，有实际执行动作。
- `review`：产物已准备，等待用户验收或下一步确认。
- `done`：目标已完成且无需当前任务继续。
- `blocked`：缺少必要信息、资源或授权，正文必须写明具体缺口。

不要新增百分比、第二套看板、任务 ID 或独立进度文件。总览需要时读取各任务 `index.md` 的状态。

## 记录归属

任务执行中按需建立文件：

- `result.md`：实际结论、已验证/未验证项和下一步。
- `FAQ.md`：用户实际追问及回答，保留日期和必要依据。
- `REFERENCES.md`：资料来源、用途和核验状态。
- `IDEA.md`：未承诺执行的灵感或改进点，标明提出者和当前态度。
- `notes/`：调研和学习材料。
- `evidence/`：脱敏截图、日志和验证证据。
- `attempts/`：失败、复现和重复验证记录。

只有内容实际产生时才建文件。所有文件从对应任务的 `index.md` 链接。一个事实只在它产生的任务保存；其他任务以相对链接引用，不复制整段上下文。

## 反馈、分支与变更

每次实际追问回答后，更新所属任务的 `FAQ.md`。新想法先写 `IDEA.md`，只有用户采纳后才成为任务或任务变更。

调研、POC 或实施失败时保留尝试记录和失败原因。若一条路线失效，再基于已知证据新建后续任务或分支，不删除原路线。目标变更时，更新 `problem.md` 的变更记录，保留最初目的和变更原因。

## 外部操作边界

生成计划、任务 Prompt 或命令示例不是所有后续操作的授权。购买、账号登录、读取私有系统、远端变更、部署、删除、服务中断和发布都需要当前任务范围内的明确授权。未获得授权时，记录 `blocked` 与所需条件。

不得把密码、密钥、token、认证头、完整私有配置或未脱敏日志写入工作区。附件或截图先脱敏，再放入与其相关的 `assets/` 或任务 `evidence/`，并使用相对路径引用。
