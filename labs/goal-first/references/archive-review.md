# Goal First 归档整理

从读者能否找到并使用交付结果出发，核对磁盘上的实际产物、原任务约定和索引。检查请求保持只读；用户要求整理或修复时，直接处理归属明确、可逆的改动。

## 读取范围与既有约定

1. 定位用户指定的项目、feature 或任务。Goal First OPS 档案先读其 Skill 并按原导航或 GFT 标识定位；独立工作区读取本地 `AGENTS.md`、目标入口和 [Goal First 工作区规则](workflow-rules.md)。任务内容按需读取 `index.md`、`PROMPT.md`、过程和报告。
2. 从入口沿链接读到主要产物和验收依据，再独立枚举所选范围的目录。把「索引引用了什么」与「实际保存了什么」逐项核对。符号链接按真实路径识别，兼容入口可达时只算同一份档案。只按需读取附件元数据或正文，限制在当前任务的授权范围。
3. 以已确认的交付要求、原始记录和现有文件判断归属。目录名、修改时间和文件存在只能作为线索。遇到证据不足的项，说明缺少的依据和实际位置。

## 检查与整理

- **产物与证据** · 核对承诺的交付是否存在、可读、归正确任务，是否能识别当前交付、历史版本和测试证据。独立交付放在各自的 `tasks/` 下，共用材料保留唯一来源。源工程和外部制品从档案引用。缺失的交付记为缺口，不从文件名推断已完成。
- **文件命名** · 任务目录、任务标题和编号沿用 Goal First 工作区规则及用户已确认的例外。报告、截图、导出包使用能辨识用途的名称，版本或日期只在有助于区分时加入。校验文件、对外交付、安装路径或工具协议依赖的原名保留，在索引中写清用途。
- **渐进式索引** · 从项目进入目标，按阶段与前置条件定位任务，再从任务入口找到当前交付、报告和验收结论。支撑截图、日志和历史版本由所属报告组织。每个入口按读者的问题提供链接及用途，先展示当前结果，避免堆放附件、复制正文或维护第二份状态。
- **实际沉淀** · 核对报告是否交代做了什么、验证范围和剩余缺口，关键决策和方法能否从下次接续的入口到达。原任务保有唯一的状态、授权和验收来源。

## 修改与验收

移动或改名之前，检查 Markdown 引用、外部消费者和兼容路径。先确认目标位置无冲突，再迁移原件并更新上下游导航。兼容入口只指回同一原件。保留 GFT ID、状态、原始证据、作者内容和验证日期。疑似重复或归属不明的内容保持原位并写明依据，避免误并。整理授权仅覆盖当前档案。

复走「目标 → 任务 → 当前产物 → 验收证据」，检查改动涉及的本地链接、标题、真实路径和旧引用。移动二进制产物时复核摘要；涉及 OPS 任务迁移时复跑其任务标识检查。按实际结果报告修改位置、验收范围、剩余缺口及外部链接未验证的情况。目录整理与业务验收分别报告。
