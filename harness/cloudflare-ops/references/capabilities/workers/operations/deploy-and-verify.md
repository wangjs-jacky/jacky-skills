# 发布 Worker 并验证状态保留

## 目标

将目标代码发布到已明确的账户和环境，保留现有路由、绑定及持久状态，并确认涉及的事件链路符合禁止轮询约束。

## 适用状态与前置条件

用户任务已授权发布；已定位脚本、环境、当前活动版本、配置来源、绑定和可读回的现有业务对象。涉及 DO 时补读[能力档案](../../durable-objects/index.md)。部署授权不自动包含删除 namespace、重建数据库或付费升级。

## 设计与执行

1. 读取当前脚本配置和部署状态，私有记录只保存必要的非秘密字段；凭据值和完整环境变量不得进入日志。
2. 将拟发布代码、配置、bindings 和 migrations 与当前环境逐项比对。识别 class/namespace 变化及数据迁移，不能依靠重新创建状态对象解决普通代码故障。
3. 查看[事件链路审查](../../../event-driven-review.md)，覆盖前端、入口、DO、桥接、SDK。发现轮询时，在已授权范围内整改；剩余路径必须明确列出，不能通过降低查询频率过关。
4. 使用项目现有发布方式部署并保存版本标识。若超时或结果不明，单次读回活动版本确认，不能盲目重复发布或创建自动查询循环。
5. 核对目标环境活动版本、绑定映射、已有业务状态和新事件路径；记录真实读回证据。公共首页成功仅是其中一项。
6. 新增独立自定义域时，核对配置中的 custom-domain route 与应用 Origin；在授权范围内使用项目既有路由发布方式（例如 `wrangler triggers deploy --config <config>`），再核对实际域名响应。OAuth scope 名称不是某次域名配置必然失败的执行证据；独立预览域成功也不授权或证明正式域切换。

## 坑与恢复

- CLI 成功但环境/路由选错：比较当前活动版本与目标，不重复上传来“碰运气”。
- 回滚代码不能撤销有损数据迁移。发布前明确兼容范围；故障时按已有授权恢复已知兼容版本，迁移恢复单独处理。
- 流式接口可能仍由服务端周期读库生产数据。核对上游实现，而不是只观察浏览器收到了事件。
- 浏览器 WebSocket 失败时，区分浏览器握手前失败、HTTP 拒绝升级和升级后断线。可在已有诊断授权下做有期限的单次 owner 握手对照；严格直连应移除代理环境并显式关闭代理 agent，代理分支显式指定 agent。Node 收到 101 和业务帧只能证明该传输路径，不能替代浏览器实时交互验收。
- 执行器采用单活动连接时，诊断连接可能按协议替换真实执行器；先协调，优先使用不会替换执行器的 owner 连接。探针结束后确认进程退出，不以自动重连持续占用连接。

## 成功标准

- 活动版本、环境、路由和预期一致，绑定与持久数据保持正确。
- 与本次变更相关的业务操作有读回或事件结果，失败与恢复边界清晰。
- 涉及的空闲、运行中、完成/取消、重连路径已审查，无残余业务轮询；无法证明的路径明确作为缺口，不标完整成功。
