# 为本地服务发布固定公网入口

## 目标

给本地 HTTP 服务提供固定 HTTPS 地址，让用户用普通浏览器或兼容的原生客户端访问，不要求用户设备加入私有网络。

## 适用状态与前置条件

源站已运行并有独立本地端口；有受控域名、Tunnel 配置权限与明确的公网发布范围。应用登录和 API 认证已准备好；保留现有数据与其他应用路由。

## 设计与执行

1. 读取源站、持久化目录、现有入口和隧道配置，确认账户及域名归属；凭据不得输出。
2. 明确公网可达后的认证方式和原生客户端兼容性；选择固定 hostname。
3. 在授权范围内添加 hostname 到源站端口的路由与 DNS，运行持久 connector；更新应用 base URL。
4. 按[事件链路审查](../../../event-driven-review.md)处理启动等待、周期状态检查等残余轮询。内容采集计划与状态轮询分开记录，不模糊声明整个服务无轮询。
5. 新入口完成实际验证后再按请求处理旧入口；不改变其他服务依赖。

原生客户端可直接使用应用 API 认证，无须为了发布 Tunnel 而另加交互式 Access 登录。本次选择独立隧道，避免改写其他服务的 ingress；token-file 限制本机权限，禁用 connector 的定期自动更新检查。

## 坑与恢复

仅首页返回 200 不足以证明业务可用。登录重定向、Cookie、API 鉴权、路径编码和读写同步均可能受入口变化影响。切换失败时保留既有源站及数据，修复新路由；避免重装服务或清空数据。

API 读回的 JSON 键顺序可能不同，应做结构化比较。网页登录检查需区分有效会话 Cookie 和删除旧 Cookie 的过期响应。账户 CLI 授权与已登录控制台权限可能不同；列表为空不能单独证明账户没有资源。

## 成功标准

普通外网设备无需私网客户端即可连接；HTTPS 有效；匿名内容访问被拒绝；正常登录与 API 读写通过；原始数据及其他路由保留。针对本次修改明确列出已处理和仍存在的轮询路径。
