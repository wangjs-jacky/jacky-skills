# 为受保护本机服务开通限时公网入口

## 目标

为已获发布授权的本地动态 HTTP 应用提供临时 HTTPS 地址，并保留应用认证和明确的关闭期限。

## 适用状态与前置条件

源站监听 loopback，已实现登录及资源归属检查；用户已同意临时公开范围及最长寿命。宿主托管静态预览不支持动态请求时，先核实当前授权是否允许独立连接器，不把静态页面当动态服务交付。

## 设计与执行

1. 创建专用 Quick Tunnel，仅映射本应用端口。显式使用空配置，避免继承其他隧道入口；禁用自动更新，指标端口仅绑定 loopback。
2. 从连接器输出事件读取实际签发的 HTTPS 地址，并等连接注册事件。专用 supervisor 使用一次截止计时器，关闭时仅终止自己创建的 connector；不重启、不轮询业务状态。
3. 将确切公开 origin 写入应用启动环境，保留 Host 白名单、同来源写入检查以及 Secure、HttpOnly、SameSite Cookie。应用同时按墙钟拒绝到期后的 API 请求。
4. 在最长授权寿命内预留关闭宽限时间。短时子进程实验验证截止信号；生产截止时间仍需如实标记为已配置，不能说已经等待完整寿命并观察关闭。
5. 通过公网地址验证匿名拒绝、错误来源拒绝、登录、真实业务和退出。交付真实地址、应用测试口令和明确到期时间；认证材料不写入公共静态文件或知识。

## 坑与恢复

源站只接受本机 Host 时，直接接隧道会被应用拒绝；保留验证并加入唯一公开 origin，不关闭检查。首页200和连接注册只能证明入口，不证明业务成功。静态预览与动态入口需要分别说明。启动失败或连接器退出时不自动重试；保留脱敏事件，由用户动作触发诊断。

## 成功标准

签发地址通过公网 HTTPS 登录并完成实际业务，匿名内容和跨来源写入被拒绝；应用与连接器具有一致截止时间，关闭实验通过，未修改其他路由和服务。具体业务事件流与备用分支另按源码和运行证据检查，不能因使用 Tunnel 就声称整个应用没有轮询。

## 验证证据与边界

2026-10-26 UTC：受口令保护的本机聊天应用经专用 Quick Tunnel 上线，公网匿名历史401、错误来源403、错误口令401、跨访客图片404，登录 Cookie 安全标志和退出通过。Ego 在手机尺寸视口完成公网登录、真实指定文字回复、刷新恢复、实际图片生成与下载；下载摘要与源站原件一致。首次图片加载失败、刷新后通过，原因未确认，不把它记成已确认平台缺陷。独立短时 supervisor 实验收到到期 SIGTERM，运行入口设单次截止计时器，生产最长24小时未等待结束。原生上游和认证继续仅留本机，原有静态预览及其他服务保留。

应用页面无业务状态轮询；专用上游已禁用账号维护与备用图片查询，WebSocket 控制 ping 仅保活。没有增加监控或定期检查。公网验证由部署机通过公共地址完成，未代替实体手机或目标用户网络验收。实例证据保存在本机 Goal First 目标。

同日应用升级复验：保留原连接器和截止时间，在同一受保护 origin 更换生产静态构建及服务端接口。实际发布脚本、样式和页面逐项读回与本地摘要一致；未链接的可选 manifest 不公开。多访客工作区、历史改名/删除/清空检查归属，真实长回答、搜索来源、图片生成、参考图编辑与下载通过。原账号及服务认证未进入前端构建。临时入口不因应用重启自动延长期限。
