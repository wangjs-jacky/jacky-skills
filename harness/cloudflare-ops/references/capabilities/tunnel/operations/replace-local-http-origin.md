# 保留既有隧道更新本地源站

## 目标

在不更改已运行的 Tunnel 与 DNS 的情况下，发布本地应用的新版本并保留认证、历史及旧会话后端。

## 适用状态与前置条件

用户已明确授权上线，源站目录与进程管理配置受控，既有公网路由可用。专用上游配置、回退版本和数据备份可准备；不能因另一客户端离线就判定部署不可行。

## 设计与执行

1. 复核真实源站及启动入口，单独构建新 release，不覆盖旧目录，不收录无关工作树与私有数据。
2. 独立数据目录预检真实文字、图片、历史与停止；目录读取成功或合成回归不能代替真实推理。
3. 备份启动配置、指针、一致性数据库及认证存储；没有活动回合后才切换。等待就绪使用进程或文件事件与单次 deadline，不用查询循环。
4. 读回公网版本、匿名拒绝、跨来源拒绝及实际构建资源；通过真实浏览器验证业务与刷新恢复。
5. 按主键比对切换前原有数据与会话绑定，保留验收期间新增数据；回退配置不等于覆盖回旧数据库。

## 坑与恢复

宿主直接访问上游公网端口可能存在地址族与路由超时。扩大地址尝试窗口仅偶尔成功时，不能作为稳定修复。受控主机之间可以使用仅绑定 loopback 的专用 SSH 加密转发，仍保留 API 认证；协议保活与连接恢复不得查询业务状态。无需为源站代码更新重建公网路由。

一次 macOS 发布在紧接卸载后注册服务返回错误；读回确认服务已消失和监听释放后，单次注册成功。观察到时序相关现象，但未证明 launchd 内部根因。注册命令成功后仍必须等待实际监听日志及业务验证，不能盲目连续重试。

图片测试要符合应用领域。领域 Skill 拒绝无关 OCR 任务，不等于模型缺少视觉能力；使用虚构领域截图核对只存在于图片内的原文，避免放宽生产规则来迎合测试。

## 成功标准

新版本在原公网入口实际服务；认证与匿名隔离保留；真实图片、跨轮及模式切换后刷新恢复；原数据与旧绑定未改写。保留恢复产物并明确未覆盖路径。

## 验证证据与边界

2026-10-16：真实隔离预检与公网浏览器两轮聊天通过，图片引用、上下文标记、模式、刷新后的消息与图片均正确。公开资源匹配新版本，匿名历史 401、跨来源写入 403。原账号、访客、消息、配置、绑定与旧回合逐行比对一致，原认证存储及启动配置已备份。没有更改隧道、DNS 或其他服务。

新 API 请求只有一次上游流，重试为零；连接保活无业务读取，启动等待采用文件事件。既有认证数据库仍有周期就绪探测，共享旧平台内部未完整审计，不宣称全系统无轮询。未验证整机重启、长期稳定性、大并发及所有旧上游生成。实例证据保存在本机记录。
