# 只读鉴权

## 目标与前置

对已存的明确条目完成只读诊断，如实记录鉴权成败与区域；不创建生成任务。用户已授权接入检查。

## 执行

1. list --platform minimax查脱敏引用。
2. verify-minimax --region both，每个选定区域只请求一次GET任务列表；代理用--proxy显式传入。不读取全部历史，不输出正文，不重定向转发凭据。
3. 同时检查HTTP200、items结构和无API错误，成功入口写入该条目verification。某区401不自动删除或换Key。
4. 网络错误只记错误类型，不新增定时探测；后续由用户动作或业务事件触发。

## 成功标准

检查结果、时间和适用范围已保存，成功与失败区域均清晰；metadata无Key、历史任务或完整响应。operation的verified只表示此诊断流程已验证，不表示任意Key永远有效。

## 坑与恢复

无Key的401仅说明网络可达；带Key且合法任务列表200才证明该端点鉴权。此结果不证明余额、收费模型权限或生成完成。更换区域、账号或Key后不能沿用旧成功。

## 证据

2026-11-16从Keychain读取用户条目，对两个官方区域各请求一次；一个区域200且items有效，另一区域401。实际映射保存在本机条目，未创建收费任务或轮询。

同日用户再次要求测试H3时，对已存条目的中国区入口执行一次只读复核，HTTP200且items结构有效。限定鉴权已重新验证；生成预算尚待明确，不将该结果升级为模型生成成功。
