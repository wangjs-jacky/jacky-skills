# 安装 Agent 提示词：Release OPS 全局前置

完成正常安装，建议用户启用下方规则。保存或读取本文件不构成修改全局配置的授权。

## 安装 Agent 流程

1. 核对目标设备与当前执行机，从技能目录或注册表确认 `release-ops/SKILL.md` 可发现、可读取。独立安装三个兼容发布入口时同时安装本 Skill，避免只有入口没有共享知识。
2. 定位当前 Agent 实际使用的全局指令文件；Codex 考虑 `CODEX_HOME` 与 `AGENTS.override.md`，其他宿主按其真实机制处理。区分持久配置、隔离会话与项目文件，只展示相关段落。
3. 已有语义等价规则时报告已配置，不重复插入。已有相同内容和范围授权时沿用，否则展示下面完整规则、真实目标文件和生效范围，提供“加入全局规则（推荐）”“仅安装技能”两个选项，等待明确答复。
4. 同意后保留原内容、合并去重，冲突先说明；读回相关段落，报告写入位置及宿主加载时机，不声称其他运行中的 Agent 已重载。
5. 拒绝或无答复不阻塞安装，不写全局规则、不在普通任务重复追问。纯复制/链接不会自动执行这项交互。

## 建议全局规则

仅将以下代码块写入用户确认的全局文件：

```markdown
## 软件分发与发布：先读取 release-ops

无论当前使用哪个技能，只要任务涉及 GitHub 仓库推送、PR 合并、GitHub Release、npm 包或 VS Code/Open VSX 扩展发布，以及这些链路的配置或排障，都必须先读取 release-ops，并遵循对应 platform 及 operation。

- 从当前技能目录或安装注册表定位 release-ops/SKILL.md，按本次项目、发布平台与目标 operation 渐进读取。
- 执行途中发现属于上述范围时，在继续相关操作前补读；本轮已读取且仍适用的内容直接复用。
- 用当前用户指令、项目配置及运行证据复核历史经验；知识记录不扩大任务授权。
- 没有对应经验时按扩展规则处理，不虚构旧经验；Skill 缺失或不可读时明确说明，继续不受影响的工作。
- 完成、失败或中断后按证据维护经验，分别记录各发布目标的结果，不把部分成功描述为全部完成。
```

该规则依赖宿主加载及 Agent 遵循，不是执行器拦截钩子。服务部署和 OTA 继续遵循对应工程 OPS；发生交叉时只读取和写回各自职责范围。
