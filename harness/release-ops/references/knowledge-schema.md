# 知识格式与自动写回

新增、修正或重复验证经验时读取。Markdown 正文为事实源；元数据只用于路由和可信度。

## 平台档案

路径：`references/platforms/<platform>/index.md`。

```yaml
---
platform: npm
updated: 2026-10-15
docs_checked: 2026-10-15
---
```

包含平台边界、限制与认证、操作目录、常见坑和官方来源。`docs_checked` 只覆盖注明的文档事实；只复核一项时更新该项日期，不能把整表刷新成全部重新核对。

数值限制注明适用套餐/版本、作用域、单位、周期和超限行为；没有依据写未知。执行前涉及变化中的平台规则时访问当前官方来源，日期不是永久保证。

## Operation

路径：平台目录下 `operations/<operation>.md`。

```yaml
---
platform: npm
operation: publish-package
status: documented
last_verified: null
---
```

正文：目标、前置条件与授权、流程与检查点、成功标准、坑与恢复、证据与边界。一个 operation 对应一个用户目标，步骤可包含 CI/本机等适用分支。

| status | 含义 | last_verified |
| --- | --- | --- |
| documented | 文档与设计指导，尚无完整场景运行证据 | `null` |
| partial | 部分成功条件已有运行证据，其余未完成或未核实 | `null`；局部日期写正文 |
| verified | 声明目标与全部成功标准有真实证据 | 实际验证日期 |

结构校验和官方文档核对都不等于真实发布成功。配置目标可通过配置读回验证，但不得据此宣称首次发布成功；诊断完成与整改完成也分别判断。迁移保留历史证据日期，不刷新为迁移日。

证据说明日期、环境类别、源码/版本对应、观察方式、结果和适用范围。具体项目、版本、run ID 等留私有实例；公共摘要不链接私有路径。扩大 operation 目标时重新评估整个状态，不能沿用较小目标的验证结果。

## 私有项目档案

`experience.local.md` 只作小型索引，按需引用 `local/projects/<project>.md` 或已有工程 OPS 的相关记录。发布目标表包含平台、仓库/包/扩展身份、版本来源、分发渠道、工作流/脚本入口、触发方式、认证模式和凭据来源名称、对应 operation、证据位置与待办。

源码和 workflow 仍维护实际实现。实例保存核对时间与引用，不能复制脚本长期维护。没有实例时先按当前项目定位，不阻塞公共知识读取，不预建空项目。

## 写回顺序

1. 对照目标列出完整成功、部分完成、失败与未知结果；多目标分别判断。
2. 更新唯一归属文件，合并新事实、修正失效结论。成功维护验证日期；不完整结果不刷新成功日期。
3. 重复成功但无新事实时只更新验证记录；同日且内容相同允许无 diff。临时认证失败不能直接记录为平台缺陷，根因未核实要标为假设。
4. 同步平台操作目录中的 operation、status、last_verified 和链接；旧经验失效时降级并在正文保留历史范围，清空当前成功日期。
5. 静态核对字段、路径、链接、状态日期与共享内容。安装源只读时报告未写入，并给出可应用修改或用户可写的唯一经验源；不复制多份漂移知识。
6. 报告实际写回位置、结果与未完成项。无新知识时说明原因，不跳过应做的验证日期维护。

`.gitignore` 覆盖 `experience.local.md`、`*.local.*`、`local/`。被忽略不等于能保存秘密；任何经验文件都不保存凭据值或可重放材料。任务已授权的发布与经验写回分开处理，写回不自行追加外部动作。
