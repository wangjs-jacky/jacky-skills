# 合并指定 PR

## 目标

将指定 PR 的已核对改动按项目规则合入正确的目标分支。

## 前置条件与授权

已有本次合并授权，目标 PR 唯一。读[平台档案](../index.md)，核对 repo、base/head、head SHA、改动范围、当前必需检查、审阅和合并策略。

## 流程与检查点

1. 读回 PR 的当前状态和变更，不用本地分支名猜 PR。已有合并结果时先核对，不重复操作。
2. 对照项目要求和当前 head 判断可合并性。必要检查未完成时保留待办；已有有效 CI 证据可以复用，不默认重跑测试。
3. 使用项目允许的 merge/squash/rebase 策略；支持时用 `--match-head-commit` 绑定已核对 head，避免合入检查后新加的提交。
4. 合并队列或 auto-merge 仅表明已安排，继续按已有完成通知或本次读回证据判断，不能立刻宣称已合并。
5. 读回 PR 的 merged 状态、base 和实际合并结果，并核对目标分支包含它。squash/rebase 时不能要求原 head 必须以同一 SHA 出现在目标分支。

## 成功标准

正确 PR 已合并到正确 base，实际合并结果可关联本次核对的改动，目标分支包含该结果。若本次仅授权安排自动合并，报告安排完成且实际合并待确认，不标整个操作 verified。

## 坑与恢复

head 变化后重新检查新增差异。冲突按已授权任务处理，不能通过管理员绕过、force push 或删除分支掩盖。合并完成不自动授权清理远端分支、发布制品或重启服务。
