# Release OPS

采用用户确认的 **platform → operations**。平台经验共享，项目档案引用当前源码、workflow 和发布政策；分类及扩展规则见[分类模型](references/ops-model.md)。

## 安装时：建议启用全局前置

安装或配置本 Skill 的 Agent 先读[全局触发提示词](references/global-agents-prompt.md)，展示规则、实际目标文件与生效范围，获得明确授权后合并；已有同范围授权直接复用。普通发布任务不重复询问。文件复制或链接不会自动执行该交互。

`github-repo-publish`、`npm-publish`、`vsix-publish` 是兼容入口，使用本 Skill 的同一份知识。独立安装这些入口时需要同时安装 `release-ops`；本 Skill 可直接使用，不依赖旧入口。

## 开始前：渐进读取

1. 从当前安装位置定位知识根目录。若存在，先读小型 `experience.local.md`；只读命中的项目档案或已有工程 OPS 的发布记录。
2. 读[平台索引](references/platforms/index.md)，再读本次平台档案与目标 operation。跨平台仅补读涉及的档案，不扫描全库。
3. 明确仓库、分支/PR/源码提交、包或扩展身份、版本、目标 registry/市场与发布渠道；单仓多包逐个定位。源码、workflow 和项目指令是项目实现的事实源，历史记录不能覆盖当前证据。
4. 核实触发方式和认证模式。CI 发布不以本机是否登录来判断；不能用固定 workflow 名或缺少 `NPM_TOKEN` 推断发布未配置。
5. 额度、认证、版本门槛和平台政策会变化；需要据此做决策时复核档案中的当前官方来源。查不到时标明未复核，不拿相似平台规则代替。
6. 使用当前项目脚本、CI 或 CLI；用户授权范围内直接完成。用户已有授权持续有效，知识维护不扩大任务范围。

## 执行与结果

- 共享工作树只提交本次明确文件；遇到无关改动或分叉，按具体任务选择隔离 worktree 等方式，不能默认 `git add -A`、清理或覆盖。
- 明确本次需要推送、合并、tag、正式发布、预发布还是草稿。复用已有有效产物，不默认同时触发 CI 与本机的同目标发布。
- 对结果不确定的写操作先读回目标状态，不盲重发、自动升版本、删除 tag 或覆盖产物。具体恢复见对应 operation。
- 按 operation 的成功标准核对。CI 绿色、上传命令成功、进入合并队列和公开可下载是不同结果；无法取得最终证据时保留未完成项。
- 多平台/多包逐个留证，一端成功不代表全部成功；恢复只处理缺失部分。
- 项目要求的检查与测试沿用实际授权和已有证据；不因加载本 Skill 自动增加测试、试装或完整回归。
- 服务部署、实例切换与 OTA 由对应工程 OPS 负责；本 Skill 管源码与制品分发。浏览器操作加载当前浏览器执行 Skill 与 `ego-ops`；涉及 Cloudflare 先读 `cloudflare-ops` 并遵守禁止轮询约束。

## 自动沉淀与收尾

每次完成、失败或中断后读取[知识格式与写回协议](references/knowledge-schema.md)，当场处理本次经验，不等用户另说“记录一下”：

- 平台通用事实归平台档案；单个目标的方法、陷阱和证据摘要归 operation；项目映射、真实路径和运行证据归 ignored 私有实例，或其既有工程 OPS 的唯一记录。
- `documented`、`partial`、`verified` 区分文档、部分运行与完整成功。只在目标和成功标准有真实证据时填写 `last_verified`；重复成功维护日期与索引，有新事实才改正文。
- 失效结论修正或降级，不能只追加矛盾段落。无可复用新事实时如实说明；同日重复核对且记录相同可无 diff。
- 更新受影响的索引，核对链接、状态、日期与共享边界；写入或结构检查失败时说明未沉淀，不宣称已保存。

自动沉淀仅修改本次知识，不自动提交、推送、再次发布或创建后台监控。它依赖 Agent 遵循协议，不是宿主的强制执行钩子。

## 私有信息

真实账户、项目路径、内部域名、版本与运行标识只存 ignored 实例。凭据值、Cookie、私钥、签名 URL 和完整业务响应不进入任何经验或全局指令文件；只记录认证方式、凭据来源名称和核对结论。禁止为检查认证而打印整个配置或 Token。
