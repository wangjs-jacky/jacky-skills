# 分类与范围

## 已确认的分类决策

- **状态：已确认。** 用户明确要求由 AI 代为研究并实际使用复杂工具，覆盖四类场景，持续自动沉淀；网页以 Ego 为主，必要时加入少量桌面操作。声音复用现有工作流绑定，以后可更换为本人声音。
- **分类主键：`scenario`。** 按用户要完成的事情分，不按浏览器、录屏器、软件品牌、账号或机器分。
- **服务范围：** 上手工具做出结果、配置软件或插件、像真实用户试用自研产品、按需完成操作讲解与视频交付。
- **目录：** `references/scenarios/index.md` → `<scenario>/index.md` → `operations/<operation>.md`。索引先筛选，再读命中正文；不预建平台全部功能。
- **身份：** 索引与 operation 使用本 OPS 内唯一 `id`；路径或标题变化时保留身份并更新引用。`scenario` 与 operation 的 kebab-case key 是路由字段，不把一次任务编号当知识身份。

## 首批场景与操作

| 场景 key | 首批 operation | 用户目标与入口 |
| --- | --- | --- |
| `get-started` | `complete-task` | [上手工具](scenarios/get-started/index.md)：在陌生工具中做出一个实际结果。 |
| `configure` | `apply-and-verify` | [配置软件或插件](scenarios/configure/index.md)：应用配置并从日常入口验证可用。 |
| `tryout` | `first-user-walkthrough` | [试用自研产品](scenarios/tryout/index.md)：从用户视角走通目标，发现真实使用问题。 |
| `teach` | `record-explanation` | [教学交付](scenarios/teach/index.md)：用实际操作证据交付可理解的讲解或视频。 |

operation 的状态与验证日期以其文件为唯一来源。首批文件记录方法，不代表这些新业务流程已经实跑成功；旧 Paws 样例只在相关条目概述已证明的部分。

## 归类与组合

- 先按主要结果选择一个场景。工具探索以做成一件事为目标时归 `get-started`；重点是配置生效时归 `configure`；评价自研产品使用体验时归 `tryout`；主要产物是讲解时归 `teach`。
- 教学可附加到前三类任务。主任务保存一次操作事实，教学引用同一证据；不能重新复制一套“已完成业务”记录。
- 同一产品的域名、桌面端、插件、版本与机器是适用条件或实例。只有目标、成功标准或授权边界不同才拆 operation，不按“点击”“截图”“调用配音”拆成用户任务。
- 固定步骤的重复任务可在 operation 内保留轻量 SOP；首次探索允许按观察调整方法，不引入适用于所有业务的工作流引擎。

## 扩展策略

四类场景是首批清单，不是永久上限。在当前软件研究、实际使用、试用与实录交付的服务范围内，按既定scenario分类轴自动增加有真实依据的operation、别名和经验；现有场景无法合理容纳且目标与验收独立时，可新增同范围场景key并同步父索引。新软件、账号或版本通常是条件或实例，不各建一个场景。

新增事实依证据决定状态，不为增加内容预写成功步骤。改变分类轴、拆并既有归属或扩大服务范围前重新确认；不能把同范围正常新增变成反复征求许可。

## 可信度与唯一归属

- `documented`：方法、文档或准备已记录，尚无本 operation 全部标准通过的实跑；`last_verified` 为 `null`。
- `partial`：实际完成了一部分，明确哪些成功、哪些失败或未验证；不得填写本 operation 整体成功日期。
- `verified`：当前证据支持全部业务成功标准；才填写 `last_verified` 并同步索引。用户对节奏、音色或体验的评价单列，不能由结构检查代替。
- 跨能力编排和目标验收归本 OPS；网页具体入口、控件和恢复经验归 `ego-ops`；声音身份、版本、参考素材及绑定归 `voice-material-ops`。
- 完整原文、媒体、配置备份、实际设备、账号与证据路径归原任务；本机导航仅进入被忽略的私有记录。共享条目不保存凭据、个人数据或绝对本机路径。
- 自动维护的完整字段与收尾规则见[知识规范](knowledge-schema.md)，制作方法只维护在[制作与节奏](production.md)。

## 检索

自然语言先用[场景清单](scenarios/index.md)的摘要、`use_when` 和 `avoid_when` 缩小到一个场景，再按其 operation 清单读取。已有精确 ID 时直接沿该 ID 定位；有歧义先核对主要结果，不因无匹配就扫描全库。当前少量条目沿 Markdown 索引即可，不为检索形式额外建立数据库或脚本。

## 更名与知识身份

当前Skill调用标识为`knowhow-ops`，本库知识ID统一使用`knowhow-ops.*`。用户明确要求迁移ID时，定义与所有索引引用必须同步更新，迁移映射和原始备份留在原任务历史中。
