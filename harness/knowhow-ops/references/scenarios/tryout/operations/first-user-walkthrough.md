# 首次用户路径走查

## 目标

以一个真实使用目标检验产品能否被找到、理解并完成，交付可复现问题及已验证结果。

## 前置条件与授权

明确试用入口、当前版本、目标用户和允许操作的对象。优先使用本轮独立草稿或用户指定数据，保护已有内容。问题发现不自动授权修改代码、清理数据或发布；用户已授权的实现任务可按原范围接续。

## 执行方法

1. 把“随便试试”收束成一个可完成的用户目标，并记下可观察终点；不预先把所有页面列成测试清单。
2. 实操前确定采集范围。有视频目标先核实连续采集；普通试用保留能说明问题的最小证据，避免为了截图打断每个小动作。
3. 从普通用户日常入口开始，先看界面可见提示，再选择动作。网页由 `ego-ops` → `ego-browser` 执行；必要的编辑器、笔记插件或桌面交互使用当前可用桌面能力。
4. 记录自然出现的找控件、理解含义、回退与恢复；不先用开发者知识、隐藏 URL、后台接口或直接改数据绕过，再宣称首次用户轻松完成。
5. 关键动作后看可见反馈与实际状态是否一致。遇问题先核对环境和条件，用最小重现区分产品问题、执行能力限制和暂时外部故障，不盲目重复破坏性动作。
6. 到达终点后核对结果。按用户影响给出少量明确发现，每项写触发条件、实际表现、预期及证据；说明未走通路径和仍属假设的原因。

## 成功标准

- 实际走过普通入口到目标的路径，完成或受阻都有可观察证据。
- 体验问题能由明确条件复现，执行工具失败与产品缺陷未混淆。
- 原有内容受到保护，临时状态按要求恢复或保留。
- 报告不把试用、修复、发布与用户满意度混作同一结果。

## 失败与恢复

控制权变化时停止相关操作；页面、目标对象或版本变化后先重新观察。无法复现的现象保留为待确认，不反复操作以制造证据；缺少执行能力时说明未测范围，不用后台检查替代真实体验。

## 知识写回

按[知识规范](../../../knowledge-schema.md)保存跨产品的观察方法与验收教训；具体网页步骤归 `ego-ops`，产品缺陷与复现材料归原项目任务。本 operation 可以记录一次走查已完成，但不能由此宣称产品所有功能正常。

## 证据与可信度

当前为方法档案，尚无本 operation 的完整新业务试用记录。首次真实走查后，按目标范围与实际证据更新；不得借用旧教学素材充当新产品体验成功。
