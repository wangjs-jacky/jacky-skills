# 探索并完成实际任务

## 目标

把用户意图转成工具中的一个真实结果，同时留下足以复用的入口、选择依据和验收方法。

## 前置条件与授权

确认本次目标、已有登录或执行环境和允许影响的对象。优先读取已存配置与同范围决定；不重复索要已有信息。必要的创建或保存按当前任务授权执行，超出范围的付费、发布、删除或新账号授权另行处理。

## 执行方法

1. 用可观察结果确定本次终点，例如一个工作流跑出预期输出、一个请求得到有效结果；不要以“知道按钮在哪”代替终点。
2. 沿当前工具实际入口观察。网页先读 `ego-ops` 的对应站点与 operation，再由 `ego-browser` 执行；只为当前缺口阅读相关官方资料，不先穷尽全套教程。
3. 实操前决定证据与采集方式。有教学目标则先读[制作参考](../../../production.md)，确认能录到所需过程再开始；无教学目标只保留必要验收证据。
4. 选择最小有用任务，按观察调整动作；保护原草稿和对象。未知控件先核对语义、当前值与反馈，关键变更后检查实际状态，不依据过期画面连续盲点。
5. 沿同一用户路径走到结果，检查输入输出与用户目标是否一致。若中途使用 CLI 或 API 辅助，说明其作用，不能冒充界面操作成功。
6. 交付实际结果，并提炼下次可用的步骤与分支。只在重复任务确实稳定时整理轻量 SOP，不把探索过程固化成所有工具通用脚本。

## 成功标准

- 当前用户入口能到达目标对象，目标实际执行而非仅配置完成。
- 输出、状态或产物与本次目标相符，失败与未验范围明确。
- 用户原有内容得到保护，临时状态已恢复或按要求保留。

## 失败与恢复

结果不明时先观察，不重复提交。登录、控制权或权限缺项按执行工具规则处理；同一目标在原任务空间恢复，不另开空间隐藏失败。已知安全部分可继续，不能假装受阻部分完成。

## 知识写回

按[知识规范](../../../knowledge-schema.md)保存跨能力方法、选择依据和结果边界；网页控件经验回 `ego-ops`。新软件名称通常是实例条件，不自动新增场景。无完整实跑成功时保持或降为 `documented` / `partial`，不写成功日期。

## 证据与可信度

当前为已记录的方法，尚无本 operation 全部成功标准通过的业务实跑。首次真实任务完成后再按证据更新状态；结构检查不构成业务验证。
