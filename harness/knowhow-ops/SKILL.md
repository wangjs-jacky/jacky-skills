# Knowhow OPS

安装 Agent 先读[安装与全局触发提示词](references/global-agents-prompt.md)。创建或安装 Skill 不等于授权修改全局规则；普通任务直接进入下面的流程。

用户说想办成什么，Agent 替用户研究入口、实际操作并验证结果。服务范围包括网页工具、必要的桌面软件与插件；录屏、配音和教学视频按任务需要加入。不能用操作计划、截图或生成视频代替事情办成。

## 渐进读取

1. 首次进入先读[分类模型](references/ops-model.md)，确认范围与知识归属；已读且仍适用时复用。
2. 从[场景清单](references/scenarios/index.md)命中一个主要 `scenario`，再读该场景的 `index.md` 和当前 operation；不扫描全部场景正文。
3. 需要实际操作或采集时读[执行与采集](references/execution.md)；仅录制试用证据时不自动增加配音和教学镜头。需要讲解成片、已有教程配音或镜头修订时，再读[制作与节奏](references/production.md)。已有录像且只改声音时保留原画面，不重新打开软件或重录。实际任务已有主operation时，把教学作为附加交付，不另建一套事实记录。
4. 收尾必须读[知识与自动写回](references/knowledge-schema.md)，按证据维护 operation、父索引和必要的私有证据导航。

## 实际执行

- 把请求落实为一个可观察结果，例如工作流真实跑通、插件功能可用、首次使用路径完成或视频可播放。先查已有同范围决定；只有目标、范围或授权的实质缺口才询问，不重复索要已存信息。
- 从现状开始：观察版本、登录或连接状态、已有配置与草稿，复核旧经验是否仍适用。未知操作先观察入口和结果信号，再做范围有限、可恢复的尝试；结果不明时先检查，不能盲目连点或重发任务。
- **实操前安排采集。** 有视频目标时先核实连续采集能力并启动，再操作；否则保留足以验收的最小证据。截图、浏览器 trace 或间歇采样帧不能冒称连续录屏。采集失败时说明缺口，不假装过程已录全。
- 按真实用户入口执行，保留重要中间状态。已有草稿、目录与设置属于任务状态；临时改变前确认归属并留存原值，结束后恢复或保留用户要求的结果。用户接管或控制权变化时立即遵守执行工具的停止规则。
- 用与目标对应的状态或产物验收：实际输入输出、选中值、文件内容、真实回复或可播放媒体。区分已配置、已执行、部分通过和用户体验认可；命令退出成功或按钮已点击不能单独证明完成。

## 能力调用与边界

| 需要 | 调用与限制 |
| --- | --- |
| 打开、读取、点击、填写、截图或测试网页 | 必须先读 `ego-ops`，按站点与 operation 渐进读取，再由 `ego-browser` 执行。Ego 是网页主路径，不用其他浏览器控制器绕过。 |
| 必要的桌面软件或插件交互 | 先核实当前环境 `computer-use`、`agent-desktop` 等实际能力与权限，再小范围操作。只有网页不能完成目标时才加入桌面控制；不把工具文档存在当成已安装或已验证。 |
| CLI、API 或文件操作 | 用于当前任务真正需要的诊断、配置和结果核对；若目标是体验界面或演示用户操作，不能用后台请求伪装成界面已走通。平台专用 OPS 与当前授权继续适用。 |
| 配音与声音复用 | 先调用 `voice-material-ops` 查唯一素材库和本工作流已有声音绑定，沿用明确版本，不每次重新选音色。未来可按用户要求切换到本人授权素材；没有参考录音就不声称已克隆。 |
| 实际语音合成 | 使用所选声音兼容的当前服务。教学流程不固定声音 ID、性别或 TTS 提供方；服务不可用时说明，不静默改用系统朗读。具体节奏沿制作参考处理。 |
| 录制、缩放、字幕与导出 | 按制作目标组合已有能力，保留真实操作和原生动画。素材管理、语音服务、录屏器与后期各自独立，不为本入口重建通用 SOP 引擎或批量创建新 Skill。 |

## 自动沉淀与交付

每次执行遵循：读取 → 当前证据复核 → 实操 → 对照成功标准 → 写回唯一归属 → 同步索引 → 报告。完成、失败和中断都要判断可复用事实；没有成功证据不得填成功日期。首次探索可以留下 `documented` 或 `partial` 记录，不能把方法说明升级为已验证流程。

本 OPS 保存跨能力编排、目标验收和教学节奏经验；网页具体操作归 `ego-ops`，声音身份与版本归 `voice-material-ops`，原始媒体、配置备份与完整任务证据归原任务。共享知识不写本机绝对路径、凭据、个人数据或固定声音 ID。

按已确认scenario分类轴自动补充真实经验、同范围操作及必要的新场景，优先复用已有归属；改变分类轴、拆并既有归属或扩大范围前再确认。知识维护不扩大付费、发布、删除、提交或推送权限，也不是后台监控保证。

交付先说明目标是否办成，附必要产物及实际验证范围；有视频时通过当前宿主支持的媒体交付方式发送。明确未完成项与用户现在是否需要行动，不把技术通过说成自然度或满意度已经认可。

直接使用示例：

> 用Knowhow OPS 帮我把这个陌生工具用起来，做出一个能验证的实际结果；完成后再把关键操作做成一段讲解视频，声音沿用当前工作流的绑定。
