# 知识格式与自动写回

新增、修正、重复验证或中断收尾时读取。所有路径相对于本 Skill 的唯一知识根；默认就是安装注册所指向的真实 Skill 目录。

## 唯一归属

| 位置 | 内容 |
| --- | --- |
| `references/projects/index.md` | 项目 key、中文名或别名、适用目标及档案链接 |
| `references/projects/<project>/index.md` | 项目边界、共用背景与约束、决策条件、来源与 operation 目录 |
| 项目下 `operations/<operation>.md` | 单个可复用目标的做法、成功标准、证据、坑与恢复 |
| `experience.local.md` | 小型实例索引：project 与私有记录入口的映射 |
| `local/<project>/` | 脱敏后的本机条件、实际工作区及原始证据位置映射 |

只在有实际内容时建项目、operation 或私有文件。project 和 operation 使用稳定 kebab-case；任务编号、分支名和会话 ID 不作项目身份。索引保持薄导航，不复制 operation 的状态和日期。

## 本机沉淀与 Git 边界

全部项目沉淀都只保留本机：`references/projects/`（含动态项目索引、项目档案、operations 及其附件）、`experience.local.md`、`*.local.*` 和 `local/` 由本 Skill 的 `.gitignore` 排除。即使内容已经脱敏，也不默认提交。Git 仅维护 Skill 规则、元数据和空索引模板，不用 `git add -f` 收录沉淀内容。

新安装没有 `references/projects/index.md` 时按空库读取；首次实际写回时创建必要目录，并将 `assets/projects-index.template.md` 复制到该路径。目标已存在时复用，不覆盖、不重置旧内容。私有实例仍按需创建。只读安装沿用下方未沉淀处理，不另外创建知识副本。

任务工作区是目标确认、执行授权、任务状态、原始产物与完整验收报告的权威源。本库提炼“何时适用、为何选择、如何复用、证据支持到哪里”，不能演变为第二套任务归档或状态表。共享文件用可分享的来源名称、版本和相对链接；实际私有路径只写实例映射。

## project 档案

记录项目的名称和别名、目标边界、跨操作共用的背景和限制、关键决策及其适用条件、来源类别与核对日期、operation 导航。只核对一项事实时，只更新该项的日期；不得刷新整个项目为“已验证”。未知写未知，当前事实与旧记录冲突时明确修正。

## operation

最小元数据格式：

```yaml
---
project: research-notebook
operation: compare-source-claims
status: documented
last_verified: null
---
```

以上只是格式示例。实际文件必须填入当前项目和目标，正文按实际复杂度说明：

1. 目标与适用条件：输入、上下文、版本和必要授权；已有任务授权以真实来源为准。
2. 方法与选择依据：可复用步骤、重要分支、被当前证据排除的做法及原因。
3. 成功标准：哪些结果可以观察或读回；明确一次验证的覆盖范围。
4. 坑与恢复：现象、已验证根因、有效恢复方法；尚未证实的解释标为假设。
5. 证据与遗留项：日期、来源类型、实际结果、边界及未覆盖事项；私有证据的实际位置留在实例映射。

不保存命令流水、整段会话或完整响应。相同目标复用已有 operation；结果或授权边界不同才考虑拆分。

## 可信度与日期

| status | 支持范围 | last_verified |
| --- | --- | --- |
| documented | 有设计、文档或源码依据，尚未完成真实目标验证 | `null` |
| partial | 已有部分执行证据，仍有成功条件未满足或未知 | `null`；局部核对日期写正文 |
| verified | 当前声明目标的全部成功条件都有真实证据 | 实际成功日期 |

这些字段只描述知识可信度。任务已完成不代表所有方法均已验证；一次失败可以留下已证实的局部事实，但不能把整个失败操作标为成功。诊断目标与修复目标分别判断，结构校验与真实业务成功分别记录。

旧记录迁入时保留原日期和范围；没有证据的成功降为待核实指导。当前证据推翻旧结论时修正或降级、清空当前 `last_verified`，在正文保留必要历史条件。

## 每轮自动写回

1. 对照本次真实目标和成功条件，判断完整成功、部分完成、失败、中断或没有新增；只使用已取得且可保存的证据，不为补证据重做业务操作。
2. 先找唯一归属。项目共用事实进档案，具体目标进 operation，本机映射进 ignored 记录；领域已有权威知识用引用连接。
3. 合并新增事实并消除矛盾。重复成功维护 operation 的真实验证日期；同日、同条件且内容无变化可以无文件差异。没有新事实仍应说明已核对或无需写回的原因。
4. 部分结果和失败只记录已观察事实与待核实问题，不刷新成功日期。缺输入、缺权限与平台故障要区分。
5. 同步相关项目和操作导航。沿新增或受影响的相对链接读回，检查元数据、状态与日期一致性、私有文件忽略规则，以及共享内容是否带私有路径或认证材料。
6. 报告实际写回位置、证据范围及未完成项。默认知识根只读时报告未沉淀，提供补丁或等待用户指定唯一可写源；不得静默落到项目下制造副本，也不能报告已保存。

## 私有信息

项目知识目录和私有实例都受 `.gitignore` 保护；被忽略不等于可以保存秘密。知识仍只保存复用所需的脱敏事实。凭据、私钥、Token、Cookie、可重放签名 URL、完整私有配置、日志及会话均不得进入知识文件。

提交、推送、分享、上传、部署和跨设备同步沿用各自任务授权；知识写回协议不授予这些动作。
