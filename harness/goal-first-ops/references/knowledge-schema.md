# 目标记录与持续写回

## 读取和文件职责

从 `projects/index.md` 找项目，从项目 `index.md` 找 feature，再按 feature 的阅读入口读取本轮所需内容。索引是导航，报告和实际产物是正文；不要要求读者先翻遍过程记录才能知道结果。

一个目标的需求、确认、报告、过程、来源、产物、验收和方法都保存在 `projects/<project>/features/<feature>/`。简单目标可以只有一篇 index.md；复杂目标按实际内容建立文档、附件和分任务，不预造空目录或统一套餐。

核心报告解释目标、实际做法、重要发现、结论依据、适用条件及未知。过程记录保留重要真实事件、来源与变化原因。文件用内容和用途命名，当前与历史性质标清；独有内容不得因简化导航而丢失。

项目共用事实放项目入口，其余内容归对应 feature。跨目标引用唯一来源，不复制正文或维护多份当前结论。本机条件随目标记录，不另设本机经验索引。

## 状态与证据

- 按既有 Goal First 契约维护实际任务的唯一 status：pending、running、review、done、blocked。项目或 feature 总览读取、链接原状态，不另建重复看板。
- 方法的 documented、partial、verified 是证据可信度；不得当作任务的完成状态。迁入的旧方法保留其等级、日期和已测范围；旧 status 字段仍按其历史知识含义理解，新写时可用 evidence_level 区分。
- 文档依据、源码观察、部分执行、完整验证与用户认可分别说明。未执行、失败或中断不写成功日期；迁移日不是业务验证日。
- 原始授权与用户原话仍归产生它们的目标；收到或复制 Prompt 不等于获得执行授权。

## 每轮完成、失败或中断后

1. 复核当前目标与实际证据，判断有哪些结果、失败、未知或影响后续的重要变化。
2. 回到同一 feature 的既有报告、过程或方法，合并新增事实，修正过期描述。保留必要历史，不连续追加相互矛盾的当前结论。
3. 更新真实产物及重要文档的导航，使下一位读者从目标入口能找到核心结果与接续依据。仅为实际存在的内容建立链接。
4. 检查引用、状态归属、证据日期及隐私，读回修改。没有新增重要事实时可以不改文件，说明本轮无需新增沉淀。
5. 报告实际更新位置、验证范围及未完成项。写入失败时说明未保存，不把自动写回当作后台服务或执行成功保证。

## 本机保留与对外分享

`projects/` 整体由 Git 忽略，包括项目索引、feature、报告、过程、附件和本机信息。规则、模板与 Skill 元数据可纳入 Git。不使用 git add -f 将本机档案强制提交。

凭据、私钥、Token、Cookie、完整私有配置、完整无关日志不得进入档案。截图与对外材料按实际用途脱敏；提交、同步、分享、部署和公开发布沿用具体授权。

## 迁移与兼容

先记录当前用户确认、来源到目标的映射、修改前身份和需保留的引用，再执行归位。完整核对原始文件与资料，导航修改留前后记录；不以 Git clone 代替含 ignored 内容的原始档案。

旧路径有消费者时可以保留精确兼容链接，所有当前实际资料仍只在对应 feature。历史方法、快照和验收日期保持原范围。兼容路径不是新分类，不再向其中建立第二套目录和独立经验索引。
