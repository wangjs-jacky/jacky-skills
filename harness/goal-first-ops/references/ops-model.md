# 分类与存储模型

## 已确认的决定

- 依据：用户于 2026-10-16 要求将工作流改名为 `goal-first`，使用 `create-ops` 新建 `goal-first-ops`，主要解决知识沉淀，默认保存在该 Skill，采用 `project + operations`。
- 分类主键：`project`，路由目录为 `references/projects/`。project 是持续解决同一组目标的项目，不限于代码仓库，也可以是研究或学习项目。
- 同一项目的分支、Worktree、设备、环境、会话和任务批次属于实例。项目已有标识可稳定复用时优先沿用；无标识时按清楚的项目名称建立简短 kebab-case key，将中文名和常见叫法记作别名。
- 唯一知识根：本 Skill 的实际目录。用户明确改用其他目录时记录唯一映射；没有该指令时不把沉淀移到业务仓库、工作区、Obsidian 或其他 Skill。
- Git 边界：用户于 2026-10-16 补充要求沉淀内容不提交。`references/projects/` 整体（包含动态索引）、`experience.local.md` 和 `local/` 仅保留本机；Skill 规则、元数据和空索引模板继续纳入 Git。
- 服务范围：目标驱动项目的背景与约束、决策条件、操作方法、验收经验、失败和恢复线索。工作区负责原始任务档案，本库负责可复用知识。

## operations 的粒度与初始内容

一个 operation 对应用户能说清的可复用目标，以其结果和成功标准命名。它可以来自目标澄清、任务安排、实施、验收或接续，不要求每个项目按同一套阶段建目录，也不把每个命令或任务编号变成 operation。

本次没有指定需导入的历史项目或首批业务操作，所以只提供模型与空索引模板。运行时索引不随 Git 分发，首次实际写回时创建；已有本机索引保持不变。以下仅解释归类，不是已批准的任务或已验证经验：

| 项目 key 示例 | 可能的 operation | 归类说明 |
| --- | --- | --- |
| `research-notebook` | `compare-source-claims` | 在同一研究项目中复用来源比较方法 |
| `reading-plan` | `resume-study-session` | 在同一学习项目中复用接续方法 |

真实项目及其操作随实际工作补充，不为示例创建档案，不复制现有工程或工作区内容作为初始库。

## 别名、边界与扩展

- 新项目、同类 operation 和无冲突的别名，在已确认标准内自动添加；经验修正与证据维护自动完成，不逐条索要许可。
- 同名但目标和归属不同的项目不能自动合并。准备拆并、重命名既有归属、改变分类轴或扩展服务范围时再确认；等待期间只继续不依赖该决定的工作。
- 一个事实只保留一处权威来源。跨 operation 的项目事实进项目档案；具体目标的做法和坑进 operation；已有领域 OPS 的共通知识用链接引用。
- 跨项目复用时核对新项目条件，引用原结论与证据；不能把一个项目的成功日期传播给其他项目。跨项目方法需提升为 `goal-first` 通用规则时另审其适用范围，不自动增设 `shared` 虚拟项目或第二分类轴。

## 证据与实例

允许保存有明确来源的 `documented` 指导、带局部证据的 `partial` 经验和完整验证的 `verified` 操作；具体定义见[知识格式](knowledge-schema.md)。这些是知识可信度，不是工作区的 `pending/running/review/done/blocked` 状态。

项目档案只存脱敏的共享事实。实际目录、设备、工作区和证据文件位置放本 Skill 的 ignored 私有记录。任务原始产物及授权仍留在工作区；本库引用其来源摘要，不复制整份会话、报告或任务看板。
