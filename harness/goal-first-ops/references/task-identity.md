# GFT 任务标识与跨会话沉淀

用户给出 GFT 标识、创建具体 task、按需给旧任务补 ID 或检查重复时读取。ID 只负责定位；原 `index.md` 保存身份及唯一当前状态，正文与授权继续使用原文档，不建立平行任务档案。

## 格式与范围

- 字段为 task `index.md` 顶层 YAML `task_id`，值严格为 `GFT-[a-z0-9]{8}`。识别消息中完整标识，不能从更长的字母数字/下划线/连字符串中截取；不自动把大写后缀改成小写。
- 八位后缀用 Node 内建 `crypto.randomInt` 随机生成，在当前实际资料根中查重。ID 与路径、标题、任务编号、宿主会话无关，改名或移动后保留，不回收旧 ID。
- 默认范围为本 Skill 实际目录中的 `projects/<project>/features/<feature>/tasks/<task>/index.md`，不是当前 shell 的工作目录。路径可包含中文与空格；兼容符号链接按真实路径去重，越界链接报错。规范入口链接到同根历史 worktree 时，逻辑入口提供层级、实际文件提供身份，不扫描未引用的 worktree 副本。其他历史非标准目录仍按已有导航和契约接续，不自动迁移或为不可检索的位置分配 ID。
- 唯一性在一次完整扫描的资料根内验证；跨设备需能读取同一份资料。离线复制或合并任务可能产生冲突，不能声称随机 ID 天然保证全球唯一；发现同 ID 对应多份真实入口时停止定位和写回。

新任务入口示意（ID 仅为示例，不直接复制）：

```yaml
---
task_id: GFT-k7jm2p9q
status: pending
---
```

共用模板保留 `task_id: null`，具体 task 创建后才分配真实 ID，向用户展示任务草案前不得留下占位值。无 ID 的旧 task 继续有效；正常查询不修改它们。明确给某个旧 task 分配标识时才执行单项 `ensure`，不自动批量补齐。

## 本地工具

解析本 Skill 真实目录为 `<ops-root>` 后使用 Node，无 npm 安装、网络请求或后台进程：

```text
node <ops-root>/scripts/task-id.mjs resolve <GFT-ID> [其他GFT-ID...]
node <ops-root>/scripts/task-id.mjs check
node <ops-root>/scripts/task-id.mjs ensure <指定task目录>
```

所有命令均可用 `--root <OPS资料根>` 显式指定范围；不得为了找不到 ID 擅自遍历其他设备、Home 或备份。默认根从脚本实际路径推导，经过安装软链接启动仍执行同一脚本。

- `resolve` 只读，返回每项的 project、feature、task、真实目录、入口路径及 `indexSha256`。多 ID 去重并保留用户顺序；任一找不到就报错，不返回猜测或悄悄省略它。正文引用、模板和普通项目导航不是身份记录。
- `check` 只读，返回总数、已有 ID 数、缺 ID 入口、重复 ID 和解析错误。旧任务缺 ID 不视为错误；重复、损坏元数据或无法完成扫描时返回失败，不能宣称库已无冲突。
- `ensure` 只修改一个已指定且可检索的真实任务入口。已有有效 ID 时原样返回；缺失或 null 时生成并查重。保留状态、其他字段、正文、注释、BOM 及换行风格，不重排整份 YAML。没有 frontmatter 的旧入口只增加身份，不凭空迁移状态。
- 可为 `ensure` 加 `--expect-sha256 <读取时的indexSha256>`，拒绝处理已变化的入口。仅接受非软链接、非硬链接的普通入口文件；任务目录的同根兼容链接可以使用。

工具刻意只解析**扁平标量 frontmatter**：顶层普通或带引号的键、单行字符串/空值、注释。嵌套映射、数组、块标量、标签、锚点及非 JSON 兼容的双引号转义等复杂 YAML 明确报错，不当作“没有 ID”而覆盖。正文不受此限制。现有简单元数据可直接使用；遇到复杂历史入口先人工核对，不自动扁平化或引入第二份元数据。

生成器用短时排他锁串行化同资料根的 ID 分配；锁存在时立即报错，不等待、不轮询、不自动删锁。中断留下锁时，核对原操作已停止后再人工清理。写前复核文件身份和内容，以临时文件原子替换并读回。此保护不能锁住不遵循协议的外部编辑器；多个会话仍应避免同时编辑同一文件，不能将写前检查称为跨任意工具的原子 CAS。

## 新会话怎样读取

1. 从本次技能目录或注册表解析 goal-first-ops；不要从 ID 猜路径。缺少 Skill 或资料根不可读时明确报告。
2. 用 `resolve` 定位消息中所有完整 ID。找不到、重复或无法完整扫描时报告实际范围与原因，停止针对不明对象的写入，不自动创建任务或重编号。
3. 读取 task `index.md`、实际契约（新任务的 `PROMPT.md`，旧任务按原约定）及适用的工作区 `AGENTS.md`、目标确认与必要上级入口。再按本次问题选择相关报告和必要前置结果，不重放全部历史。
4. 回答中带 `[GFT-…]`、任务名及必要路径，方便用户确认归属。多个 ID 可一起讨论，不能默选第一个作为写入目标。

不要求初始化器、宿主会话或 Paws UI 参与解析；离开 Skill 的工作区仍可按既有路径接续。自动识别依赖宿主加载 Skill 元数据或获准的全局提示词，不是后台拦截器。只保存规则模板、Skill 可读、宿主实际加载和新会话真实触发分别验收。

## 讨论、写回与执行

| 用户意图 | 行为 |
| --- | --- |
| 给出 ID、查看、提问、结合任务讨论 | 只读定位与回答；不自动写回或补 ID |
| 明确要求把讨论沉淀到该 task | 仅在明确的目标中合并相关结论、方法或真实过程 |
| 明确要求继续执行该 task | 核对契约、当前指令、原授权和前置条件，按实际范围推进 |

沉淀时先确认本轮内容与任务的实际关联；无关观点留在当前讨论，不强行写进原任务。当前结论优先合入既有报告；有价值追问或方法可进入既有 FAQ，重要事件归过程记录。没有合适正文时可建立一份有明确用途的 Markdown 并加入导航，不强制创建 FAQ、PROGRESS 或固定文件套餐。

写前重新定位 ID，读取目标文档最新内容并核对本轮修改基线；如已被其他会话修改，先合并或明确报告冲突，不能用旧全文覆盖。只保存相关且有来源的内容，区分用户原话、AI 推导、待核实判断与真实验证结果，不复制完整聊天、凭据或无关日志。涉及多个 ID 时，用户明确“分别沉淀”可按内容归属写回；归属不明只澄清缺失的目标，不重复确认已明确的单一目标。

沉淀后读回正文和导航，核对 ID 未改变、status 未因知识补充而变化，报告 `[GFT-…]` 及实际更新文件。项目/feature 导航只在实际入口变化时维护，不复制状态或正文。已获执行授权的任务仍按原协议自动记录实际进展；仅凭 ID 进入的一般问答使用上述只读边界。
