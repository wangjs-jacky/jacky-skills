# 设计静态内容分发链路

## 目标

按访问地区、加载方式和域名条件划分页面入口、CDN 与 OSS 职责，给出可验证方案，不把迁移存储当作性能已改善。

## 适用状态与前置条件

用户授权设计或诊断；确认访问地区、OSS 地域、现有 CDN、备案和资源范围。输入未知时给条件分支，不假定账号已有对应配置。

## 设计与执行

1. 核对请求关键路径、真实字节/编码/缓存和运行成本；静态文件总数不等于首屏请求数。
2. 比较保留页面入口、仅把大资源改为浏览器直连 CDN → OSS，或完整静态站同源地走 CDN → OSS；前者保留入口延迟，后者需覆盖交互文档同源条件。按目标地区有限测试取舍，不由厂商名称决定速度。
   已有默认资源域名可用时，也比较“保留页面入口、资源直连 OSS”，不将 CDN 和备案设为所有方案的固定前提；默认域名的账号/地域限制、响应类型、缓存和应用读取能力分别验证。
3. 依据备案和加速地域选 CDN 入口，按分配 CNAME 路由，避免无证据叠代理。私有 Bucket 回源按官方授权设计，源站控制与访客可见范围分别验收。
4. 同一构建生成版本资源与 manifest，入口/指针短缓存，内容地址长期缓存；显式映射旧平台规范路径/响应头，核对 HTTPS、HOST、类型及必要 CORS。
5. 保留旧快照；先上传依赖再推进入口，两个镜像不作为两份手工编辑源。设计记录不自动授权上传、切换、付费或发布。

## 坑与恢复

缓存命中、首页 200、对象上传分别只证明对应环节。OSS 签名链接不能不经核对作为稳定 CDN 地址；字体/模块跨域读取与 iframe DOM 能力分别处理，CORS 不等于 iframe 同源授权。

本轮只读检查曾遇到 CLI 默认 endpoint 与目标 Bucket 地域不符，返回 AccessDenied 并附正确 endpoint；改为对应 endpoint 后列举与 CNAME 读取成功。属于已观察的地址选择问题，不作为账号失权或未开通 OSS 的证据。现存对象的匿名 Range 读取只证明对应对象链路，不能替代新 Bucket、浏览器效果或目标网络速度验收。

## 成功标准

方案明确入口与源站、地域/域名条件、资源加载/版本、测试及回退，并区分事实、建议与未知。性能改善需同条件请求与用户操作证据；不用定时查询监控业务状态。
