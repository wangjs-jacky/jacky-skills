# 发布内容寻址资源并核验复用

## 目标

向使用者已有桶的明确项目前缀发布选定公开资源，验证真实内容及重复执行复用；不将上传成功视为网页部署或性能改善。

## 适用状态与前置条件

已授权公开上传，明确身份、Bucket、地域、项目前缀和显式文件范围。目标桶和公开访问方式已准备，日常身份有该前缀必要对象读写权限，不必拥有账号列桶或创建桶权限。

## 设计与执行

1. 从明确公开目录按显式文件清单生成完整 SHA-256、类型、字节及内容寻址对象键。清单不包含凭据或签名 URL；源文件和输出路径须保持选定范围。
2. 在独立本地快照核对计划与实际字节，避免文件变更后仍用旧摘要名上传；资源以用户自己账号下的项目前缀组织。
3. 官方 CLI 消费已有认证，使用正确地域 Endpoint，对精确对象执行 stat。仅 NoSuchKey 支持后续新对象上传；权限、地域或默认域名限制不能当作不存在。
4. 已有对象以公开 GET 检查类型、字节及 SHA-256；一致才复用，不一致或无法公开访问就停止，不覆盖或改已有 ACL。
5. 新对象在具体授权下公开只读上传，写入实际 MIME 与内容地址适用的长期 immutable 缓存；随后做匿名 GET 内容核验。禁止公开写入，不用整桶同步/删除完成发布。
6. 资源就绪后才将对应清单交给页面构建，页面部署与浏览器功能/性能另验。不以计时循环查询状态或自动重试扫描恢复失败。

## 坑与恢复

HTTP 200 可能是错误 HTML；需同时核验类型、长度和哈希。存储元数据、经过默认域名后的响应头和浏览器图片嵌入能力分别判断。内容地址冲突时停止，不覆盖后继续声称幂等。默认数据 Endpoint 受限的新账号，应选符合当前条件的官方 CNAME 工具/SDK 或同站模式，不把老账号成功推广给所有用户。

## 成功标准

选定新资源真实上传、匿名字节与类型核验通过；重复执行核验旧对象并复用，没有再次建桶或上传。缓存响应及未涉及的页面/账号管理变化明确记录。仅声明资源链路，不涵盖页面、浏览器、不同账号或目标地区性能。

## 验证证据与边界
