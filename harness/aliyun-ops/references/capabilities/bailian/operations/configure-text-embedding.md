# 配置文本 Embedding

## 目标

让应用用指定地域的百炼模型生成有效向量，并完成一次最小入库和检索。

## 适用状态与前置条件

用户已选择百炼 Embedding；凭据来自授权私有源或本次创建的应用 Key。先确认地域、业务空间、模型权限和应用适配器，不复用被停用的历史 Key。已有知识库先记录模型绑定，避免破坏索引。

## 设计与执行

1. 从能力档案及当前官方资料确认文本接口、模型维度和批量限制。
2. 检查应用源码/配置指南：使用原生 DashScope 时按模型选端点；兼容适配器则确认需要 base URL 还是完整 `/embeddings`。配置显式维度以便验收。
3. 凭据只传入进程环境或应用私有设置，运行配置检查再应用，保留原有未涉及的设置。
4. 发送一小批不含私密内容的文本，检查返回向量数量、维度和数值有限性；不输出整个向量或凭据。
5. 用本次专用小型学习文档入库、检索其特有事实，再在应用页面核对可使用。保留测试资料与来源，避免把对话常识命中当作检索成功。

## 坑与恢复

API 400 时先看模型与文本/多模态端点是否匹配。401/403 分别核对 Key 来源、地域和模型权限，不自动扩大权限或更换全局 Key。维度或模型变化时新建测试库验证，不能直接重建用户已有知识库。

## 成功标准

实际向量数量和维度符合配置，所有元素为有限数值；同一应用配置下入库完成，检索能返回测试文档的独有事实和来源；Web 能消费该配置。仅 provider probe 成功保持 partial。
