# 知识格式与写回

## 唯一归属

- 能力索引只保存 key、别名、问题和档案链接。
- 能力档案保存边界、跨操作事实、限制及带日期的官方来源。
- `operations/<operation>.md` 保存一个用户目标的前置条件、执行分支、成功标准、坑、证据与缺口。
- `experience.local.md` 是小型私有索引，实际账号、机器、配置源路径和证据位置进入 ignored 的 `local/`。不复制共享正文，不保存任何凭据值。

能力元数据：`capability`、`updated`、`docs_checked`。操作元数据：`capability`、`operation`、`status`、`last_verified`。key 使用 kebab-case，并与目录名一致。

## 证据与状态

| status | 含义 | last_verified |
|---|---|---|
| documented | 官方文档、源码判断或尚未运行的指引，须标明来源 | null |
| partial | 只有部分成功标准有实际证据，列出缺口 | null |
| verified | 声明的目标及全部成功标准已真实验证 | 成功当天 |

迁移保留原验证日期；不能把整理日期当作业务成功日期。调用返回的 request ID、账号、业务空间、专用域名等留在私有记录，公共文档使用稳定语义。

额度和价格要标明币种、计量单位、地域、适用模型、核对日期及来源；不知道账号免费额度时明确未知。账单消费、付款、欠费和推理实时用量分别判断，不能凭金额没变化证明没有调用。

## 写回顺序

1. 对照成功标准区分完整、部分、失败和无新增。
2. 合并到唯一归属，修正失效结论，不追加互相冲突的说法。
3. 完整或重复成功才刷新 operation 和索引的验证日期；同日内容未变可无 diff，但报告已核对。
4. 失败或中断记录已观察事实与下一条件，不把登录失效当成平台缺陷。
5. 运行知识校验器，核对链接、索引、隐私与日期，再报告实际写回结果。结构检查不证明模型、计费或权限状态。

写入失败或目录不可写时明确说明，不能静默创建第二份经验源。维护知识不增加云操作授权，不触发后台采集。
