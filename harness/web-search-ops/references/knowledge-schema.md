# 知识与写回

## 目录与身份

`references/sites/index.md → <site>/index.md → 选中 operation`。父清单给稳定 ID、用途、读取条件和下一层入口；对象共享事实进站点索引。原生叶子使用 `id/site/operation/status/last_verified` 元数据，Ego 复用其现有 schema 与复合 ID，不改变上游格式。

可信度为 documented、partial、verified；前两者 last_verified 为 null，真实完整成功才填日期。迁入保留原日期与条件，结构通过不算业务成功。

## 每次工作

1. 判断用户目标与当前证据，复核选中知识的适用范围。
2. 完成、失败、中断均整理本次结果。选路修正及原生接口方法写回本 OPS；浏览器方法只写 Ego OPS，对应站点/operation 及其验证日期沿其规则处理。
3. 先修正冲突、失效事实，再同步父索引与检索线索；不得只在旧错误之后追加相反说法。
4. 新 Ego 操作由 catalog 在下次读取该站点索引时直接发现，不维护第二套操作正文或全量手抄清单。
5. API 同站点可补相同粒度操作，更新本 OPS 的站点索引；知识目录新条目分配稳定 ID，移动时保留身份。
6. 核对链接与元数据，执行本次相关测试和官方结构检查。浏览器知识校验由 Ego OPS 负责；无浏览器执行时不刷新其日期。
7. 报告实际结果与写回位置。没有新事实也说明原因；重复真实成功维护日期，不为刷日期追加业务请求。

机器路径、代理、账号引用、版本回执和本机证据只放被忽略的 experience.local.md/local/。密钥、Cookie、签名 URL、验证码与完整业务响应不进入经验；账号池仍是安全凭据唯一入口。安装只读或写回失败时如实报告，不另建漂移知识库。知识维护不授权全局配置、提交、推送、部署或付费业务。
