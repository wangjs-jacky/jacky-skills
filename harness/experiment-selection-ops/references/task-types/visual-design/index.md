# 视觉稿

适用于同内容页面、UI稿或原型的比较。候选可为设计 Skill、模型、工作方法；生成器和最终页面分别陈述。视觉偏好、内容存在、交互可用与读者理解是不同结果。

## 使用入口

- [比较文档首页](operations/compare-docs-homepages.md)：同 brief 设计方法比较，真实页面、状态证据与中性评看入口。
- 初次或没有匹配场景时，用[设计与执行](../../methods/design-and-execution.md)定义判据；报告按[报告指南](../../methods/reporting.md)。

## 跨场景条件

同一页面的多个视口、截图、按钮和修订不增加独立生成数。声称生成可靠性需要独立产物及与目标相符的设计；一份成品只能支持该成品观察。请求视口与实际 client/scroll 尺寸分开记录，字体、资产、浏览器及网络依赖是比较条件。

可交付源文件或已运行构建、重开方式、最终版本标识、必要视口/状态的精确截图或录屏入口。静态源码有文字不能证明用户理解，按钮存在不能证明动作成功；交互主张应有动作前后读回和可复核记录。

工具执行遵守宿主网页治理。没有实际页面/必要工具时，报告“仅静态预检/尚未运行”，不把设计描述、图片或构建成功替代交互验收。时间行为是主要比较目标时，使用[动画类型](../animation/index.md)的播放条件。

初始来源为[项目观察](../../sources/index.md)的V1/V2有界缺口与共享方法；0.1.0随后已有同题局部执行与08最终有界验收，具体覆盖/失败只在上述operation维护；没有全Skill或新场景成功结论。

选题、变量排程或图表论证需要细化时，按[共享方法检索](../../methods/index.md)选择补充正文；它不替代本类型的产物与成功标准。
