# 比较 CSV 导入解析接入

目标：在相同字段保真、错误定位与恢复政策下选择解析库及实际 API。适合本地 Node CSV 报名等表格导入；不包含业务去重、邮箱校验或生产上传部署。候选是实例条件，不是主键。

## 前置及设计

取得字段/编码、换行、表头、空行、类型转换、坏行恢复与严格/宽松引号政策。未决定的政策列为条件，不能把作者的严格程度自动当用户偏好。锁定包/lock及实际发布字节；保存真正用到的 API 源码/声明/许可和 SHA。

先按[共享设计](../../../methods/design-and-execution.md)留计划，按[区分解释](../../../methods/question-to-contrast.md)区分原生能力、解码/包装和产品政策。独立预期来自显式字段值及异常契约，不由两个候选互相同意生成。正常/错误控制走同一正式 gate；控制单列，候选真实失败与仪器失败分开。语义准入与诊断属性分别定义 oracle：本场景 executeRecord 只检查完整字段或条数/摘要、拒绝条数和 fatal，不自动核对所有错误位置、原片段和回调字段。若据诊断作采用主张，另列候选无关的位置/上下文预期与覆盖；不能由88/88推出诊断全面正确。gate 的版本检查使用声明常量，需另核实际安装包身份，不能将其称为独立防漂移认证。

## 有用的分支与检查

1. 用数组观察表头原字段后，再检查唯一/缺失/额外字段及映射；原生对象映射可能覆盖重复键或改名，不能单凭返回对象证明未丢字段。保存原生与应用政策两层结果。
2. 覆盖 BOM、中文/emoji、逗号、字段内LF/CRLF、转义引号、空字段、数字状文本与空格、不同记录换行，以及缺/多列、重复表头、坏/未闭引号、截断行。空文件与仅表头的意义需事前确定。
3. 流式能力须测实际入口。切分字节可跨UTF-8字符、BOM、CRLF和转义引号；安全解码是应用层时单列。固定/自动换行配置及起始块内容分别记录，不把“支持流”当成任意分块下均保真。
4. 对缺/多列测试合法前缀和后缀是否可恢复；结构歧义尾部不假定可恢复。保存原生错误及应用补充定位，区分物理行、数据记录序号、库row/index和字符/字节偏移。未观察到的定位能力写缺失。
5. 对同库不同API检查错误是否仍暴露给调用者。收到data事件并不等于全部记录可安全使用；不要把回调入口的诊断推广给仅推送数据的入口。
6. 开始成本批次前核对是否还有源码搜索、数据读取、构建或其他可见并发活动；保存实际条件。若未隔离或运行中出现重叠，只给有边界的观测，不把平衡顺序当作消除资源混杂。大小输入×实际用法需要比较时，按[区组方法](../../../methods/blocking-and-interactions.md)交叉并平衡顺序；保留[分条件表和反例](../../../methods/diagnostic-figures.md)。完整解析、映射、摘要与解码的管线耗时不能叫裸解析器耗时。输入生成后的进程峰值RSS不是解析器增量内存，也不证明流式内存上界。
