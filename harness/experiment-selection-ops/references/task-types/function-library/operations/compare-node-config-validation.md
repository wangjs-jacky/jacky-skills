# 比较Node配置校验接入

目标：按明确的产品语义比较候选库的可运行用法、错误边界及与实际分发相关的成本，给出条件采用或保留未决。本 operation 不承诺某库默认胜出。

## 适用与前置

适合JSON配置读取/校验的Node或TypeScript接入。先取得产品契约、候选版本、可用工具和本轮预算。若只有查API或静态阅读，交付来源与待测设计，保持documented。若不能运行真实builder，只验证交接/边界，不能称构建通过。

读[共用设计与执行](../../../methods/design-and-execution.md)，事前确定采用前提：是否真的打包分发、是否长驻/CLI、真实输入规模、错误诊断需求、允许适配层及成本取舍。未知前提留为未决或分支，不默认“小bundle一定重要”。

按需细化：[区分替代解释的比较](../../../methods/question-to-contrast.md)、[区组与条件交互](../../../methods/blocking-and-interactions.md)、[诊断视图与论证](../../../methods/diagnostic-figures.md)。共享步骤只在这些正文维护，本operation保存场景应用与证据。

## 把语义落实到可运行用法

1. **明确契约与待决解释**：把字段类型、缺省与显式false、错误/缺失分支、未知键处理、输出形状写成独立于候选的预期表。trim/coercion、相对路径、禁用分支额外键等未决产品解释不能自动收紧成用户要求；可按条件分别设计，但不能代用户确认。
2. **核第一方原文**：锁定包版本/安装字节与来源，保存真正用于API判断的package/声明/README精确文件或可核对摘录和SHA。仓库commit与npm发布字节分别陈述，不用仓库README独自证明安装实现。归档用到的来源，不搬整个node_modules。
3. **分层接入**：每库有最小可调用示例、安装/运行命令和输入输出。原生schema/API单列；适配器转换路径/issue与共同业务规则另列，保留原生与包装后结果，不能把展开未知键的能力算作库原生。
4. **选择有区分力的案例**：从契约选有效最小值、典型/较大输入、默认与false、类型错误、缺失/错误判别分支、多错/多未知键等必要边界。每例有稳定ID、输入、外部预期、理由；预期由契约或独立参考确定，不以两库互相同意为真值。列记录数与去重输入数及等价规则，不把手选案例当随机用户样本。
5. **检查实际副作用范围**：冻结/深比对输入前后以核输入不变。如果声称输出与输入不共享可变结构，列所有实际可变节点/嵌套项，逐节点做引用或隔离突变检查并保留覆盖表；只查site.name就只声明该节点。数据类型/循环引用等超出JSON的情形另定检查，不能套JSON序列化掩盖信息。

## 真实性准入与负控

建立本轮真正使用的准入函数/命令出口：**正常调用 → 按外部预期检查 → 统一通过/拒绝记录 → 仅合格数据进入性能汇总**。正常控制证明出口可达；复制正常fixture并仅篡改一项明确预期或注入已知失配，调用同一正式入口，观察真实拒收原因、退出状态/标记及汇总无该记录。恢复正常输入后同一路径可进入。

保存控制输入、正式入口版本、原始通过/拒绝记录和汇总成员核对。控制样本与业务数据隔离并标明用途。捕获独立自造assert、让另一验证器报错或只看`fired=true`，不能证明正式拒绝出口工作。已有原版漏负控不在此补测后回填。

候选确实违反契约是有效产品负结果：进入正确性失败记录、阻断该配置的采用主张；不能因不合格而删掉。只有仪器无效/版本错/日志缺失等使测量不可信时才标无效。正确性失败不会变成可用性能胜者，性能排除原因仍须报告。

## 执行、成本与解释

- 保存实际成功/失败输出、错误路径与issue计数、输入不变和别名检查覆盖。输出诊断若去重，说明等价规则并保留原始条数及可见路径；重复报错不伪装成更高覆盖。
- 按需运行类型检查、CLI及文件/JSON/业务错误边界，记录退出码和builder是否实际被调用。mock、validated-handoff、typecheck、bundle重放各按实际命名；生产构建未跑则留未知。
- 需要成本比较时，先通过准入，再按相同工作负载记录warmup、每批调用数、批次/进程/顺序、缓存、共享宿主与缺失。fresh process并不自动证明跨机独立。计时/启动/构建字节定义见[统计方法](../../../methods/statistics.md)；不强加所有端点。
- 构建体积保存真实构建命令、入口/配置、目标、依赖闭包或metafile、原/gzip字节及压缩实现。单个bundle字节不是npm安装/内存/生产冷启动；模块化或tree-shaking机制需要隔离证据，否则只作假设。
- 报告按[报告指南](../../../methods/reporting.md)，把相反方向的工作负载、绝对收益、诊断/适配成本及采用前提放进正文，不能仅放附件。不足时保留无定论，不用共同总分抵消正确性错误。

## 成功标准与写回

可核查的契约与未决条件、锁定来源、可运行用法和执行覆盖；真实准入及正常/错误控制证据；每项主要主张有正确的计量对象、输入范围与直接证据；缺失/失败/成本外推被正确处理；依[知识协议](../../../knowledge-schema.md)完成唯一归属写回判断与索引。

如果上述实质条件有缺口，本次比较可交付部分事实/失败报告，知识最多partial；不能把“库检查全过”代替整个比较成功。真人对错误信息的理解与生产选择若未测，单列未验证。
