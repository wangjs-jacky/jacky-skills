# 动画

`evidence_level: documented`。这是用户明确要求覆盖的类型方法；本项目没有动画业务运行、播放证据或真人观看，不建立空场景 operation，不写成功验证日期。

## 何时使用与应交付什么

比较目标以时间行为为主时使用，例如过渡的可理解性、节奏/运动连续性或状态切换。静帧不能替代动态观察。交付可播放的实际案例（视频、交互动画或可运行工程）、启动/播放条件及最终版本、必要采样和观察；不能只给分镜或关键帧就称动画已验收。

## 把问题变成可比较的播放过程

按[共用设计与执行](../../methods/design-and-execution.md)先固定输入素材、时间线/触发条件、交付格式和允许工具预算。候选使用同内容、尺寸、时长或用户指定的不同约束；无法对齐时说明比较条件。先定义想作的决定：例如用户是否能辨认状态变化，还是某设备实际播放是否流畅。偏好与性能是不同问题。

为本题选择有区分力的过程：开始/结束、主要过渡、循环边界，必要时包含中途重触发/取消、长短内容或低速回放。选择有理由的采样时刻/事件区间，记录对应时间码、触发动作和观察，不用固定帧数凑覆盖。若需求含减少动态效果或输入响应，相应记录设置与前后行为；未测则不扩展主张。

可播放产物应说明容器/编码或工程运行方式、声明与实际核过的分辨率/帧率/时长、浏览器/播放器/设备、音频条件、循环与控制方式。测量流畅度时另定义丢帧/帧时的采集源与计量对象、采样窗口和机器负载；声明60fps或导出设置不能证明设备实播60fps。

先核验最终版确实开始、推进和结束/循环，排除空画面、暂停、自动播放拦截或错误素材等仪器问题；保留真实播放失败。网页中的播放/录屏由宿主指定的治理和工具执行，能力不可用就披露未验。关键帧帮助定位，但播放QA必须实际观看，连续运动问题用可播放记录留证。

同一clip的多帧、多次回放、不同播放速度不是独立生成。若要比较生成稳定性需要独立产物；若只比较这两段动画，就按有限案例报告。重放顺序、播放器设置/负载等可影响判断，记录并按问题控制，不以导出墙钟直接推方法质量。

## 检查与报告

给中性编号的播放入口、每段最终版本与必要操作说明，身份映射另存任务证据。让真人先直接观看，保存其选择/理由原话；AI描述不代替真人偏好或理解。[报告指南](../../methods/reporting.md)要求每个主要观察有时间码/状态、播放条件、证据和其改变的决定。截图只支持该帧事实；不能证明整段运动。

当前方法是从任务需求和视觉/测量共同原则推导，非动画专属效果实证，详见[来源](../../sources/index.md)。未来有真实场景时，在本类型下建立有内容的 operation，定义其目标、成功标准、适用/不适用与证据。每次完成/失败/中断均按[知识协议](../../knowledge-schema.md)处理，不为了填满类型新增本轮业务实验。

选题、变量排程或图表论证需要细化时，按[共享方法检索](../../methods/index.md)选择补充正文；它不替代本类型的产物与成功标准。
