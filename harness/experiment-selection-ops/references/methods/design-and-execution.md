# 设计与真实执行

跨类型方法的唯一归属；类型 operation 负责具体案例和产物。本指南适用于一次小比较到有重复测量的研究，不要求固定任务数、报告文件数或大型campaign。

## 先复核，再取结果

定位当前目标与知识版本：要选择的对象、使用场景、约束、用户已决定/仍未决定的前提，以及本轮允许做的动作、预算和停止条件。旧经验是起点，不覆盖当前用户说明。

若同时评估“选型流程”与流程内的页面/库，先写清两层：外层单位是流程执行，内层单位是产物/输入/测量。内层失败可被流程正确发现；内层赢家不能变成外层框架赢家。不同检查集合或不同业务解释下的通过数不能直接排名。

## 调研记录要能移交

给候选建立小表：名称/能力、满足哪项约束、第一方URL、版本/commit/分支、查询时间、许可、事实与尚未验证的假设。采用规模/维护信息若影响选择，记录stars等查询时刻及仓库级/组件级范围；热门不证明有效，小众也不自动判失败。未知不要填0。

真正依赖的API/来源原文保存精确文件或可核对摘录，带原文件路径、行段/节名、原文件及摘录SHA256、获取时刻、许可与修改说明。安装包字节与仓库快照分别标识；只存URL/作者机器node_modules路径不能称证据可移交。许可不允许复制时只保存允许内容和定位，声明接手者仍需取得原文。无需带上整库或全部依赖。

资料输入的定位/提炼按[资料方法](materials.md)，一次运行输入和证据归任务工作目录；可复用方法才归本 Skill。

## 结果出现前留下最小计划

可复制[计划模板](../../assets/run-plan.template.md)并裁剪，或在小任务的同一文件先写短计划。内容必须让接手者能判断：

| 计划要素 | 需要作的具体决定 |
| --- | --- |
| 问题与候选 | 什么选择、为何值得测、候选与排除理由、采用前提还有什么未知 |
| 案例与区分力 | 为什么这些输入/场景能暴露相关差异；业务预期来自哪里、失败/边界怎么覆盖 |
| 单位与变量 | 一次独立产物/测量是什么；技术重复是什么；固定、变化、阻断/配对与无法控制的因素 |
| 判断方式 | 可观察成功条件、主/辅助指标的含义/单位/方向/基准、真实性准入、错误/缺失处理；何种结果足以改变决定 |
| 必要重复 | 服务何种主张；若预算不足只支持有限描述，写清而不机械增n；功效适用条件见[统计](statistics.md) |
| 公平条件 | 共同输入/资产、版本、宿主/工具、内层预算、并发、迭代权限及运行顺序；无法对齐的混杂 |
| 范围与停止 | 本轮预算/生成次数、单次操作截止、修正权限、停止条件及到限仍要交付的证据/未知 |

时间戳、计划版本/哈希和首个运行事件可以显示已有过程时序；不是不可篡改预注册。发现契约歧义时记录未决及条件设计，只有不可替代的人类判断才等待，其他已授权工作继续。不能用AI选择补成用户确认。

## 执行记录最少要留什么

首次实际操作前尽可能记录UTC与单调时钟起点；此前阅读未测则注明，不事后编保守上界。按实际可得粒度区分生成、测量、分析、核验、等待与最终封存/写回收尾，注明重叠，不把它们简单相加。结束记录覆盖完整收尾；漏段标未知。

**计时相减前先核比较域。** 每个读数记录API/时钟实现、单位、解释器或运行时的实际路径与版本、进程身份，以及起点/比较域的依据。相同API名或底层实现名不证明起点相同；跨进程、解释器或运行时不能默认可比。优先由同一控制进程覆盖所声明区间并计时；跨域比较须有本轮可比性证据，不能只因差值看似合理就采信。

没有可比性证据，或差值为负时，将派生耗时记为`null / invalid`并列原因，排除出耗时汇总，保留原读数、原件及SHA。另列有边界的UTC观察间隔或同一控制进程计时，说明启动/收尾/漏段及墙钟可调整等限制；它们不修复历史单调链，也不自动代表候选性能。不能取绝对值、回填新读数或补造精确阶段时长；新探针只证明其实际环境，不恢复历史未知。

保存运行ID、计划/输入、实现/指令与知识版本、候选及工具版本、关键命令/退出码、原始输出、失败/缺失和最终产物。模型/effort分别写请求值、可读到的有效客户端字段及未暴露的遥测；没有字段不推断。并发、缓存、共享机器负载、超时及工具替代影响比较时写入记录。

执行原件保持不改，数字来自唯一数据源；表/图从它派生。修正用新版本和注释说明原因、哪些事实仍成立、哪些主张撤回及受影响复验。再生成图表不需要重测业务；修订/截图数不计作独立n。

## 正式准入与控制

真实性检查回答“测到的是否真是目标”，先于“效果是否好”。按类型选实际风险：正确版本/可见目标/非空尺寸、语义oracle、计时边界/单位或输出完整性。没有通用guard脚本能替所有类型定义这些条件。

新建或改动正式验证通路时，在**同一实际入口、同一拒绝出口和同一汇总准入**验证：

1. 一个已知正常控制确实通过，记录进入正式通路的标识。
2. 对控制输入/预期只改一个已知会触发拒绝的因素，走正式入口，保存拒收原因、状态和原记录。
3. 核对错误控制不进入计时/成功汇总，正常控制可进入；控制记录单列，不能当业务样本。

另写一条assert并捕获它，只能证明那条assert抛错。没有执行控制就写“准入通路未完整自证”，不能用源代码看起来合理替代。

| 实际情况 | 记录与允许结论 |
| --- | --- |
| 仪器/版本错误、空输出、不可读日志 | 无效测量及原因，保留原件；相关性能/质量主张不可用 |
| 仪器正常，候选违背产品要求 | 有效负结果，进入失败事实；可阻断该条件下采用，不删成无效样本 |
| 缺工具、跳过、超时、权限/依赖失败 | 未运行/部分运行与原因，不算通过，也不直接归因候选无能力 |
| 只有静态/模拟检查 | 精确说明范围，不能替代真实交互、生产构建或真人反馈 |

错误控制验证不授权额外模型生成、部署或新业务轮次。补查/修复遵循本轮已有预算；到限保留失败或无定论，不自行追加实验让它过关。

## 检查、写回与收尾

按计划及实际偏离检查每个成功标准，取对应类型产物与证据。主要推断和报告检查读[报告指南](reporting.md)，连续数据按需读[统计](statistics.md)。有独立评审授权时给各角色必要的相同冻结输入，先各自初判冻结再合并；事实冲突回查原件/复算，不用多数票、作者自评或无限裁判取代证据。

最后按[知识协议](../knowledge-schema.md)处理成功、失败、中断或无新增的写回判断，检查索引/引用并报告。工具控制权失效/用户接管时立即遵循停止规则，只整理已取得且可保存的证据。
