# 重采已归档但字幕错误的视频

## 目标

对同一条自有已完成资料重新转录并确认新结果持久化。

## 前置条件与授权

仅在用户明确授权修复该资料时执行。先核对资料所有权、准确来源、`completed` 状态与 `cleanupPending=false`；重采会在成功后替换原字幕和笔记。对象不唯一或旧执行未停止时停止。

## 入口

已登录的原资料详情页；先核对来源、任务状态和旧字幕。

## 已验证步骤

1. 在已登录且仍由 Agent 持有的同一 Ego 任务空间内，打开原资料页。用 `page.fetch('/api/ingestion/tasks/<资料ID>')` 读取状态；检查资料链接、`completed`、`cleanupPending=false` 和旧字幕。
2. 对该 ID 调用一次 `page.fetch('/api/ingestion/tasks/<资料ID>/reprocess', {method:'POST', headers:{'content-type':'application/json'}, body:'{}'})`。读回 HTTP 200、`queued` 和保留的旧资料；状态不明时只读查询，绝不盲目重复提交。
3. 在原资料页用“刷新进度”查询：先核对来源、媒体、音频、字幕和质检，再等笔记与归档。质检收到字幕只是中间状态，不当作最终入库。
4. 服务端最终为 `completed` 且无待清理执行后，整页刷新原资料并打开“字幕”标签。核对新字幕、内容索引、两份资料附件与封面，再读回服务端结果确认刷新持久化。

## 检查点

- 提交状态不明时先读回同一任务，不重复提交重采。
- 当前页面可继续暂存旧资料；必须区分“旧资料可读”“新字幕已接收”“新结果已归档”。
- “刷新进度”仅查询状态，不会推动远端执行。当前视口可能不显示资料附件，应以资料接口读回或页面对应区域为准。

## 成功标准

同一任务最终为已完成，无待清理执行；新字幕和资料附件可读，整页刷新后保持，并与本次上传结果一致。

## 失败模式与恢复

尚未记录经证实且可复现的失败模式；结果不明时回到检查点，不更新验证日期。

## 验证证据

- 2026-10-03：中文歌曲原资料经一次重采后，服务端完成归档；刷新后显示中文字幕与新内容索引，旧英语误转录不再显示，资料接口确认两份附件与封面。
