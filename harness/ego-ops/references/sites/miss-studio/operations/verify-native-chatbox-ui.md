# 核验原生共学界面与草稿恢复

## 目标
核验本地原生构建的历史、草稿、讨论范围、引用接线和手机交互。本操作不宣称真实模型回答成功，也不替代发布验收。

## 前置条件与授权
用户已授权本地实现和验收。使用公开测试资料、独立Worker与Agent，不操作生产数据。准备完整任务结构，包括events、artifacts与transcript数组。登录仅作用于测试入口，不清空浏览器全局状态。

## 入口
本地构建的Studio资料学习页，以及归档资料的共学入口。先记录所属数字任务空间和精确标签目标；全程复用，不按同名空间恢复。

## 已验证步骤
1. 仅配置有效owner原生绑定，打开完成资料。核对输入可用、预置历史可读和无横向溢出。auth/status的nativeStudy与资料列表的chat能力必须一致；不要添加旧Paws配置掩盖能力缺口。
2. 输入长草稿，刷新后核对原文。新建讨论，核对空草稿；写入另一草稿，再切回原讨论，核对独立恢复。切换主题后再次核对。
3. 在手机宽度核对输入字号、发送目标和横向溢出。未配置采集的顶栏可能增加页面高度；用正常滚动显示完整输入区，再测实际可见目标。
4. 选择字幕时间点并提问。页面只显示原问题，不显示生成规范。通过独立执行端收据核对服务端解析的序号、时间和原文；不得用UI文本推断模型已接收或回答。
5. 请求停止，读回云端终态和页面发送入口，核对停止期间的新草稿。刷新后核对原问题、取消状态和草稿。初始化期间的停止不冒称健康模型输出中的停止。
6. 打开归档资料的“共学”，切换“提问范围”，核对同一Chatbox及可用输入。每个完成关键状态用当前会话绑定的截图收据回传一次。

## 检查点
原生用户消息需与旧界面使用同一显示格式化边界，并同时处理text和parts，否则复制仍可能带出内部规范。完整记录需分别保存事件序号与原始记录字节游标；这项由接口与组件测试补证，不能仅看按钮存在。

## 成功标准
在声明的本地UI范围内，历史可读；长草稿经刷新、讨论切换和主题切换保留；手机输入至少16px且主要目标至少44×44；引用收据正确；停止状态和下一草稿可恢复；归档范围可用。模型语义、健康模型三轮、真机键盘和生产发布另行验收。

## 失败模式与恢复
空白页先查真实错误及测试资料完整性，不将缺数组的fixture归因产品。输入禁用时核对服务端能力来源。认证过期时保留失败证据，继续不依赖模型的检查，不改用全局凭据或旧SDK。所有权、目标或非预期URL改变立即停止。Ego更新提示不授权升级。
