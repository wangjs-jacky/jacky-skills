## 目标

恢复既有Cloudflare登录，核对目标账户及任务所需权限，继续用户已授权的操作。

## 前置条件与授权

用户明确要求登录或恢复会话；已记录原数字任务空间及精确标签目标。只使用当前空间已保存且对应预期用户的GitHub入口，不自行换浏览器profile。多账户不唯一或出现人工验证时停止并交接。

## 入口

https://dash.cloudflare.com/login

## 已验证步骤

1. 接回原数字空间与原标签，核对登录页目标。React初始占位不等于可操作表单；以保存身份按钮实际可见为准。
2. 选择唯一对应预期用户的“Continue as … using GitHub”入口，使用已有GitHub会话完成跳转；不读取或打印凭据。
3. 认证回调期间仅观察origin/path及是否仍有认证查询参数。不要直接输出tabs完整URL、snapshot或截取带令牌的回调地址；等落地无认证查询的账户home再观察及取帧。
4. 核对账户导航、目标资源和当前任务所需的只读接口均成功；登录页消失本身不足以证明进入正确账户或具备写权限。
5. 通过隔离capture helper上报已验证的干净账户页面，按任务边界继续后续已授权操作。

## 检查点

- 保存身份必须与目标账户一致；界面出现新授权、验证码、设备确认或用户接管时，按Ego控制权规则交接。
- 不依赖readyState判断SPA已可交互，不盲点占位SVG，也不无限reload。
- 认证查询、身份凭据和完整响应不得写进操作知识、截图收据或日志。

## 成功标准

在原任务空间完成登录，正确账户页面可交互，任务所需只读接口成功，已报告无认证参数的验证帧。后续资源写入按其独立授权及operation验证。

## 失败模式与恢复

本次起初仅显示加载占位，后续真实保存身份按钮出现；未证明具体加载根因，不记录成平台缺陷。过期会话属于临时认证状态，不刷新其他未执行操作的成功日期。
