# 核验私有Worker应用的登录与注销

## 目标

验证受Access保护的私有Worker应用能以本人身份登录、保存原件，并在注销后撤销旧连接和私有读取；重新登录可恢复原有资料。

## 前置条件与授权

应用已配置精确本人访问策略，已有当前应用的使用与验收授权。复用同一任务空间的已记录标签；注销只针对当前应用，不清除整个浏览器的登录状态或其他站点会话。应用自有会话、跨标签通知与下载校验需由其实现，不能推定Access自动提供。

## 入口

从已核对的私有应用地址进入；本次身份提供方的稳定控件为Cloudflare。应用内以“退出登录”“我的资料”“下载原件”等语义定位，先核对当前页面和对应对象。登录页可能包含带签名参数的URL，不输出完整地址或认证页面原始数据。

## 已验证步骤

1. 在Access登录页选择Cloudflare身份提供方，回到应用后核对本人资料和实时连接状态；再次登录不以出现主页代替私有数据读回。
2. 在资料行点击下载按钮，在同一轮保存浏览器返回的下载产物，校验实际文件长度与SHA-256。鉴权读取、内容校验、Blob下载经过本次应用真实验证；不能只凭下载提示宣称已落盘。
3. 在同一空间另一标签建立只读事件连接。通过真实退出按钮结束会话，核对Access页面显示“You successfully logged out.”。
4. 另一标签核对旧事件连接以应用规定的注销码关闭，资料缓存消失且显示登录入口；对旧页面的私有API做一次读取，确认无私有正文。
5. 重新通过身份提供方登录，核对原有资料仍在，事件连接重新建立。清理临时验证连接和下载DOM，不保存认证材料。

## 检查点

应用bundle为目标版本；下载对象与目标资料行一致；关闭事件来自既有连接而非测试主动关闭；跨标签清空缓存和服务器拒绝读取是两项独立证据。Fetch手动重定向在浏览器中可能表现为status 0 / opaqueredirect，不把它写成HTTP 0；需结合独立HTTP读回确认Access跳转。

## 成功标准

本人登录与再次登录成功，原件下载实际落盘且摘要一致；注销后旧连接关闭、旧页面私有内容清空、旧请求无法读取私有正文，持久资料没有丢失。

## 失败模式与恢复

本次应用曾在服务端注销后仍显示另一标签的缓存资料，手动读取仅出现网络错误。其客户端只处理连接指示灯、未清理视图；加入同源退出通知、关闭码处理、认证重定向识别和迟到响应隔离后，真实跨标签测试通过。这是应用实现经验，不是Access会自动清理客户端缓存的保证。

直接文件链接的下载取消原因尚未定位，不归因于Cloudflare站点缺陷。本次通过鉴权读取、完整性校验和Blob保存完成实际下载；该结果不能解释所有浏览器取消原因。
