# 读取主评论与楼中楼回复

## 目标

读取当前笔记的评论及可展开回复，并提炼有来源的疑问与反馈

## 前置条件与授权

仅在本次明确授权范围内执行；对象不唯一、影响范围扩大或不可逆时停止并确认。

## 入口

已核对身份的笔记详情中的评论区；不把搜索卡片显示的评论数当评论正文。

## 已验证步骤

1. 将范围限定到当前详情的 .comments-container，读取页面声明的评论总数作为本次检查参照。
2. 评论位于 .note-scroller 内。滚动后检查真实 scrollTop 与评论区域是否进入视口，不能只滚动背景页面就认为评论已出现。
3. 以 .parent-comment 分组，分别读取 .comment-item 和 .comment-item-sub 中的 .content；保留主评论与回复的归属，作者回复与其他回复分开识别。
4. 存在 .show-more 的展开回复控件时按当前可见入口操作，等待同一分组实际增加回复，再读回新增内容；不点击回复、发送、点赞等写操作。
5. 记录主评论数、回复数、实际渲染总数、未展开控件与覆盖范围。只概括真实样本里的问题，不能把少量评论当作全体用户的比例结论。

## 检查点

- 展开动作前后回复数量增加，新增内容仍属于原主评论；重复 DOM 不重复计数。
- 本轮页面声明十五条，实际核对十条主评论与五条回复；该样本数量吻合不代表其他笔记都可一次读全。
- 若滚轮后容器未移动，先观察正确滚动容器；必要时通过同一 Ego Page 对已确认容器做 DOM 滚动，再核对视口与内容，不改用私有评论接口。

## 成功标准

至少读到真实主评论和对应回复，并能说明展开前后数量、作者回复及当前样本覆盖边界。

## 失败模式与恢复

只读评论区聚合文本会丢失父子关系，须按主评论容器分组。大评论区可能懒加载或虚拟渲染，未逐步覆盖时不得宣称全量读取。

## 验证证据

- 2026-11-25：实际将折叠的两条回复展开，从十三条渲染记录增至十五条，核对十条主评论、五条回复及作者回复，关键帧已上报。
