# 验证长回复批量批注与评论二次编辑

## 目标

在隔离的 Happy 完整 PC Web 会话页验证逐段选区、批注汇总、评论二次编辑与统一提交。当前证据来自尚未上线的功能分支，不能推断正式站点已包含此功能。

## 前置条件与授权

用户明确授权功能实现、E2E 与临时静态设计预览。使用单独本地服务、合成账号和正文，不能访问生产账号或向生产会话发测试消息。先读取当前 ego-browser 指南，保持本任务自己的数字空间、准确目标和同一 runId；遇用户接管或目标变化立即停止。

## 入口

从工程的 `packages/happy-app/e2e/fixtures/message-annotations/serve.mjs` 启动隔离环境，由生成的 runtime 文件取得本轮 Web 入口与两个会话。认证材料只能在本机读取，不记录、输出或录像。登录后导航去掉认证 query 的会话 URL。静态设计稿与真实完整页面是两种证据，不互相替代。

## 已验证步骤

1. 等正文、字体与选区目标几何稳定，真实鼠标跨 Markdown 粗体选择原文；点击“添加到对话”，填写或留空评论并保存，核对编号和汇总对应。
2. 继续添加多条及两个位置的相同原文。展开输入框批注汇总，铅笔回填旧评论，保存更新同一条；Escape 取消保留旧评论，删除同步移除。
3. 刷新后读回已保存批注；切换到另一测试会话再返回，核对会话隔离。
4. 在隔离文档临时注入队列持久化失败，单击提交后核对草稿保留、实际服务端未新增消息，并在 finally 恢复原存储方法。
5. 通过现有 SessionView 和暂存队列一次提交多条原文、评论及补充输入；解密测试服务端读回，仅新增一条且内容对应。单独验证仅批注 Enter 提交。
6. 从真实外观设置选择 Gingham 深色主题，核对普通、hover 与原文选中态。以窄屏尺寸检查长评论输入与保存按钮边界。普通模式通过后同一组 Case 录像复跑。

## 检查点

使用现有稳定 testID 和可见标签；Ego 无 Playwright locator API，不推测其接口。等待字体与布局稳定再计算鼠标坐标，不能用过期几何判断选区失败。原文定位按节点偏移和锚点核对，重复引用不得串条目。只读回合成测试数据，不持久化完整业务响应。

## 成功标准

每个 Case 均有可观察结果及断言：编辑不发送、保存不新增条目、取消不覆盖、删除同步、刷新恢复、失败保留、成功一条提交与对应原文评论、主题和窄屏边界通过。普通与录像复跑结果一致。关键最终状态经会话绑定 helper 验证与上报；视频经格式、完整解码和视觉覆盖核对后发送。

## 失败模式与恢复

输入框父级裁切浮层时使用 body portal，窄屏浮层采用 border-box 约束；两种修复已由实际页面验证。字体/路由布局未稳定可能使真实鼠标选区失效，先等实际正文几何稳定后再执行；无效选区不得直接判为产品失败。保留草稿的失败注入仅限测试页面且必须恢复。测试结束先报告最终状态、完成知识校验，再独立 finish 本任务空间，最后仅停止该夹具及其环境，不停止主 daemon。
