# 验证实时连接恢复与独立消息收发

## 目标

在浏览器实时连接故障恢复后，验证新会话真实收发与完成状态。

## 前置条件与授权

用户授权修复与消息收发复测。升级浏览器会重启，须明确取得升级许可，先结束旧任务空间；升级后重新读取当前运行指南。原有未发送消息必须保留，不以清除站点数据代替修复。

## 入口

正式 Paws 首页及其实时连接接口。使用独立的本次复测任务空间。

## 已验证步骤

1. 将页面普通请求、实时握手和模型执行分别验证；可用原生 WebSocket 只测握手，连接打开后关闭探针，不发送认证或业务内容。
2. 比较站点实时端点与独立外部测试端点、本机端点；浏览器失败而 CLI 握手成功不能推断服务停止。
3. 完成已授权的升级与重启后，按同一端点复测。本次升级并重启后两个外部端点恢复；不能区分新版修复与重启清理异常状态的贡献。
4. 首页存在暂停恢复记录时，在当前受控页面内存中暂存该记录，确认输入框无其他草稿、未启用图片代理，再发送仅要求回复本次唯一标记的独立文字消息。
5. 页面跳转到新会话后，精确恢复原暂停记录并读回一致性；不清理登录状态、其他站点或其他草稿。
6. 核对模型单独回复本次标记、发送按钮恢复且会话显示“已完成”；只声明本次样本收发通过。

## 检查点

升级前后版本、相同入口的握手结果；新会话真实回复与完成状态；原恢复记录保持一致。普通页面可加载不代表实时连接成功；握手成功不代表模型已经回复。

## 成功标准

升级后实时连接打开，新会话收到实际模型的唯一测试回复且状态已完成，原暂停记录已恢复。未发布的容错源码补丁必须与本次生产恢复分开说明。

## 失败模式与恢复

历史样本曾出现浏览器外部 WebSocket 握手空响应、普通 HTTP 正常；升级与重启后恢复。此对照不证明所有同类故障均来自浏览器版本，也不证明重启一定恢复。授权缺失、用户接管或恢复状态不明时停止相关操作。

## 验证证据

同一正式入口升级前后原生握手结果、CLI 对照、真实模型独立标记回复、会话“已完成”语义状态和原暂停记录读回一致均已核对。仅覆盖本次文字收发，未测试用户原图片任务或长期稳定性。
