# 核对账号并浏览会话历史

## 目标

区分账号不匹配、已到历史开头和容量保护导致的会话历史加载停顿。

## 前置条件与授权

用户授权查看目标会话；切换账号须匹配用户明确指定的目标，不能根据列表顺序猜测。不记录账号标识、会话 ID 或凭证。

## 入口

使用用户提供的会话链接。侧栏底部头像或“设置”按钮打开账号菜单；在“切换账号”中核对目标账号及服务器。

## 已验证步骤

1. 读取账号菜单，核对“当前账号”的勾选标记。若不匹配，按用户指定目标点击账号项。
2. 切换后重新打开原会话链接，等待消息正文出现，不能仅凭侧栏已出现就判定加载完成。
3. 将鼠标放到会话正文区域向上滚动。检查是否出现更早内容，区分历史分页与侧栏滚动。
4. 先尝试继续朝相同方向滚动。已验证修复分支可直接切换历史窗口，无需按钮；旧版正式站点如仍停在容量边界，可点击顶部“继续”后再向上滚动。需核对当前部署版本，不把本地通过等同于正式已发布。
5. 到达最早内容后再向下、向上滚动，确认列表正常移动。已在最早记录时无法继续向上属于正常边界。

## 检查点

- 页面“已删除”与本机可读取会话矛盾时，首先复核账号，不能直接判定会话不存在。
- 会话列表稳定定位为 `data-testid="conversation-transcript-list"`；历史续载按钮为 `data-testid="history-older-retry"`。使用前需在实时 DOM 中重新核对。
- 诊断时需区分网络页已返回与消息实际渲染成功。容量错误 `history-window-capacity` 会阻止普通分页；它不是历史数据丢失。

## 成功标准

正确账号下正文可读取，更早消息能够显示，上下滚动改变列表位置；到历史开头时确认没有更早分页，而非根据空白区域猜测。

## 失败模式与恢复

- 错误账号显示“会话已被删除”：切换到用户指定账号并重新打开链接，已验证可恢复访问。
- 长会话折叠了大量工具记录，历史窗口触发容量保护：本次线上版本点击顶部“继续”可恢复向前翻页。此为验证时的恢复方式，不要求未来版本永久保留手动按钮；重测时以实时行为为准。
- 顶部已是最早记录却无法继续上滚：检查历史边界。此时无需修复滚轮或扩大缓存。

## 验证证据

2026-10-03 在真实 PC Web 会话中验证：切换账号后能打开同一链接；容量保护后点击“继续”成功加载更早内容，最终到达最早记录；向下滚动后再向上可返回顶部。账号状态、正文、分页边界和滚动位置共同验证，关键截图已在对应 Happy 会话报告；这里不保存动态业务标识或截图路径。
