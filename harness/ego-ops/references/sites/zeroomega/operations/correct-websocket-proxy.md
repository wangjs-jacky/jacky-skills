# 修正 WebSocket 默认代理协议并验证连接

## 目标

定位普通网页正常但实时连接失败的默认代理协议错配，并验证连接恢复。

## 前置条件与授权

用户授权排查与修复目标站点连接。先记录目标代理行原值，核实本机监听端口实际提供的协议；不读取浏览器磁盘配置或导出整份扩展设置，不扩大修改范围。

## 入口

浏览器扩展管理 → ZeroOmega 详情 → 扩展程序选项 → 当前代理情景模式的代理服务器表。

## 已验证步骤

1. 将普通 HTTP、WebSocket 握手与应用收发分开观察；网页和后台在线不证明实时连接已建立。
2. 核对默认、HTTP、HTTPS 各行的代理协议、服务器与端口。未单列的 WebSocket 网址可能使用默认行，不能把网址的 wss 协议等同代理服务器的协议。
3. 在扩展自己的选项页，通过只读当前代理设置确认由本扩展控制，并只提取已知测试地址的实际路由结果；不输出完整脚本或未知设置。
4. 用本机配置或不带认证的协议对照确认目标端口是 HTTP 还是 SOCKS。将 HTTP 客户端连接 SOCKS 监听端口可出现 CONNECT 中止；改用正确协议后同端口请求成功。
5. 只修正错配默认行的协议，保留其他正确代理行；点击“应用选项”，读回当前生效路由，确认 WebSocket 已使用正确代理类型。
6. 对同一站点重做原生 WebSocket 握手，并确认实际应用 Socket 状态恢复。若已有队列，仅读取其是否继续处理，不手动重复发送结果不明的消息。

## 检查点

必须比较当前生效规则，不能仅依赖系统代理或保存的情景模式。修正前普通网页与实时协议走不同代理路径；修正后只改变错误协议，原目标握手恢复且实际应用显示连接成功。

## 成功标准

当前生效的 WebSocket 代理协议与监听服务一致，原地址握手打开，目标应用 Socket 连接成功；原队列继续处理的证据与业务任务最终完成状态分别报告。

## 失败模式与恢复

默认代理错误地使用 HTTP 协议指向 SOCKS 端口时，HTTP/HTTPS 的专用行仍可能正常；结果是网页可读、多个外部 WebSocket 却失败，而本机直连正常。修正默认行为正确 SOCKS 协议后，本次原地址及应用连接均恢复。重启浏览器不会改正保存的错误协议，不能用一轮重启后的成功声称根治。应用修复重连或队列提示也不能替代修正错误代理。

## 验证证据

已通过 ZeroOmega 设置界面独立核对默认行、只读当前代理控制状态与已知地址的路由，完成错误协议/正确协议 CLI 对照，仅更改默认行并应用。随后同一 WebSocket 握手成功、应用 Socket connected，原待发送记录消失且目标会话进入运行。业务最终完成未等待；浏览器任务空间随后关闭，按规则停止控制。
