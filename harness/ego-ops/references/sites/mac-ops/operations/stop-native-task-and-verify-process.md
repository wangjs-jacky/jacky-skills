## 目标

从真实云面板停止当前原生测试任务，并核对同一 task 的取消终态和对应真实 PID 已退出。当前验证范围为隔离测试程序，不推广为已验证任意软件的停止或卸载。

## 前置条件与授权

用户已授权本项目原生工具与停止验收；只对明确属于本任务的 fixture 操作。开始前记录数字任务空间与精确 target，确认 URL/控制权。不得用进程名称匹配或批量 kill 代替所有权核对。

## 入口

当前明确云环境的运维助手；测试程序已通过原生工具启动且实际 PID 可单次核对。

## 已验证步骤

1. 使用隔离测试程序，设置足够长的自然运行时间，并输出真实 PID；在停止动作前单次核对 PID、启动身份和仍在运行，不能只看“思考中”。
2. 当前页状态过期时，先显式刷新并确认原任务仍活动；点击“停止生成”。“已请求停止当前任务”只证明请求被接受。
3. 等待真实终态事件，核对原 task 为 cancelled，保留原生命令、退出码和停止说明。事件通道不可用时，明确说明缺口；只能在已有后端终态证据后显式刷新读回，不增加查询循环。
4. 对同一 PID 单次核对已退出；确认程序未自然运行完，也没有产生自然结束的标记文件。
5. 在原对话续问，真实模型返回期望短回复；重复同幂等键提交与显式重连后，fixture 的副作用计数仍为一次。

## 检查点

停止必须绑定原 task；PID 与启动身份必须属于本回合；重复提交复用 task 与序号，不创建新执行。未知或未确认的进程退出不得报告“已完全停止”。

## 成功标准

实际运行中的测试程序在 UI 停止后退出，原 task 终态 cancelled，副作用一次，续问可用。浏览器事件实时更新和无关进程隔离的额外测试分别记录，不用本次成功扩大结论。

## 失败模式与恢复

点击后提示“已请求停止”不等于已停止。以真实终态与同一 PID 的单次读回判定；只有前后证据相符才记成功。测试程序已自然退出或状态被热更新干扰时，该轮停止试验无效，应保留失败边界后重新设计独立试验。
