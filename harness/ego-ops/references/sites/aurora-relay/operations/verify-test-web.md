# 验证共享前端和长回答搜索图片

## 目标

验证 Aurora Chat 共享前端的认证、中文长回答、Markdown、搜索来源、图片生成、下载及参考图编辑；区分静态预览与真实动态入口。

## 前置条件与授权

用户授权接入同作者前端和修复重复输出；真实调用使用已配置的订阅账号。账号认证只在服务端，口令从受控配置读取，不写入截图或知识。入口沿用当前已授权地址与期限。

## 入口

口令页有“测试口令”“进入体验”。工作区有“聊天”“图片”“设置”；聊天页可开启“联网搜索”，图片页分“文生图”“改图”，结果提供“下载”“继续修改”。手机导航通过“打开侧边栏”进入。

## 已验证步骤

1. 进入真实 HTTPS 服务，等聊天输入框出现。不能只看标题或侧边栏就判整个懒加载界面完成。
2. 新建对话，使用曾失败的真实问题验证长回答；等待输入恢复且 Markdown 成文，检查开头没有重复、标题/段落/表格正确，刷新仍恢复同一对话。
3. 遇到官网专用布局组件，验证其转为可读文字和安全链接，保留正常代码块及正文。开启“联网搜索”，用需要官方来源的问题核对实际来源链接和无裸露引用标记。
4. 在“图片”生成合成测试图，等待 complete 且 naturalWidth 大于0，下载前先监听 download 事件并保存实际文件。点击“继续修改”，确认参考图，再提交修改要求；验证新图及下载。
5. 每轮手机验收显式设置390px视口并检查文档宽度。移动端通过侧边栏打开设置，退出后确认回到口令页且本应用聊天、图片、草稿和发送历史缓存清空；重新进入得到新临时身份和空历史。
6. 公开静态预览仍应提示无真实后端，不能代替上述真实请求验收。源站受控接口另用独立认证访问身份验证已知资源的拒绝行为。

## 检查点

真实请求终态、输入控件恢复、最终文本和保存内容分别检查；短标记回复不能代替长文本。图片必须加载非零尺寸，下载保存实际字节。截图使用同一任务的已记录数字任务空间、精确目标及预期地址；成功关键帧单独上报。

## 成功标准

真实长回答没有重复，刷新恢复、Markdown及来源链接可读，生图、参考图编辑、下载通过；手机无横向溢出，退出与身份切换不展示上一身份缓存。与实体手机和完整上游账号隔离的边界分别说明。

## 失败模式与恢复

曾出现回答开头反复拼接并保存超长正文。实际根因是上游交错发送隐藏分段和可见合并回答，后端未检查隐藏/片段元数据；新增过滤和流式/非流式回归后，真实长回答及同题公网复验通过。遇到重复先检查保存内容和上游事件，不只改前端排版。

官网自定义布局不属于普通 Markdown，需要转换为文字和安全链接，不能执行模型返回的组件代码。首次旧版图片加载失败过，同源获取完整 PNG 后刷新成功；根因未确认，不能记为已修复平台故障。

## 验证证据

2026-10-27：旧版本机与短时公网网页的聊天、来源、图片和下载留有成功证据，后来实际长回答暴露重复缺陷。

同日升级：真实账号长回答返回完整正文且首尾标记各一次；公网原始用户问题返回数千字符无重复，标题、表格、安全来源链接和刷新恢复通过。Aurora Chat 手机尺寸下真实生图及参考图编辑均1536×1024，下载保存完整文件，无横向溢出；独立 HTTP 访客无法读、改名、删除他人对话或访问他人图片。精确地址、文件摘要和回执保存在本机目标。

不把浏览器尺寸模拟等同实体手机；未验收命名用户、设备文件单独上传流程或共享账号 Memory/Library 全路径隔离。搜索来源通过，不宣称每次请求都单独导出了原生搜索工具轨迹。语音、通用附件和分支编辑入口未开放。
