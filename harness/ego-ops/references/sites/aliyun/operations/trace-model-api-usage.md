# 排查模型调用来源与异常用量

## 目标

通过模型用量和审计日志核对模型、时间、来源 IP、状态码与请求用量，判断异常调用的技术来源和证据边界。

## 前置条件与授权

用户已登录目标阿里云账户，并授权检查自身模型调用记录。此操作仅查看用量与日志；不创建密钥、不恢复停用密钥、不修改日志投递、不发起模型推理，也不替用户提交工单或联系来源地址。

账户、IP、Request ID 与请求明细属于私有调查证据，不写入本知识目录。不得输出或保存完整密钥、会话凭据 或控制台认证字段。

## 入口

- 模型用量：`https://bailian.console.aliyun.com/cn-beijing/costing-balance/usage-statistics`。
- 审计日志：`https://bailian.console.aliyun.com/cn-beijing/model/logs/auditLog`。
- 导航：顶部“模型” → “运维管理” → “模型日志”；当前侧栏具备稳定语义标识 `data-testid="nav-side-model_logs"`，使用前须在页面复核。
- 模型用量可切换“大语言模型”，在目标模型行选择“查看详情”；审计日志支持模型、调用密钥、时间范围、精确 RequestID 和分页筛选。

## 已验证步骤

1. 确认登录账户、地域与业务空间，进入模型用量，记录实际时间范围、调用次数、词元 总量及模型分布。模型详情还有失败次数等指标。
2. 从运维管理进入模型日志，选择审计日志。页面说明审计日志只记录元数据，不含 Prompt 和 Response；无需为排查来源而开启推理日志。
3. 选择“今天”等明确范围，观察日志总条数、模型、时间、状态码与掩码 Key。打开请求“详情”，先核对列表，再切换“JSON”。
4. 在 JSON 核对 `client_ip`、`start_time`、`apikey_id`、`request_id`、`status_code` 和 `usage`。普通详情列表未展示来源 IP，JSON 中可读取该字段。
5. 需要汇总大量日志时，可在同一 Ego 页面内观察一次真实列表请求，按当前接口与筛选范围读取分页。当前页面页容量为 10、20、50；已验证使用 50 条分页、按 Request ID 去重并与总数核对。只保留调查所需的元数据，不保留认证字段或完整业务响应。
6. 将来源按 IP、时间、模型和状态聚合；需要核对云厂商归属时，用厂商公开地址段等一手资料。归属云厂商不能证明实际租户身份，也不能单独证明盗用。

## 检查点

- 导航及筛选后等待目标数据呈现，不以刚切换时的旧表格作结果。
- 精确 RequestID 筛选后核对只有目标请求，详情内的 Request ID、模型与时间必须一致。
- 区分总请求、状态码为 200 的请求、失败及其他状态；控制台概览和日志可能有不同统计口径，不强行凑齐。
- 批量读取须核对页范围、去重数量、服务端总数和固定时间范围；无分页错误才可声明完整读取。
- 仅有来源 IP 时，报告定位到服务器或网络的程度；仍需用户正常使用记录或供应商证据来归因到具体应用或人员。

## 成功标准

在已验证页面中获得实际调用时间、模型、状态码和客户端 IP，并用明确范围内完整分页的元数据汇总来源。报告同时说明可确认事实、异常判断依据和尚未确定的使用方身份。

## 失败模式与恢复

- 源 IP 不在普通详情列表中：切换同一请求的 JSON 标签，已验证可见 `client_ip`。
- 页面列表请求使用另一个控制台域名：原样重放但省略跨域凭据时曾返回 `Login.NotLogined`；沿用当前页面实际请求及内容类型，并在同一浏览器登录会话中携带凭据后读取成功。认证材料仅留在内存，不输出、不写知识。
- 不假定可扩展页容量：超过界面支持范围的请求曾未返回预期列表，改为已验证的 50 条分页。不得把 HTTP 200 或外层成功标志当作业务列表成功。
- 开启原始 CDP 后快照引用会失效，应使用已复核的稳定语义定位，或重新生成快照。

2026-10-22：通过真实已登录控制台验证模型用量、审计日志、请求详情 JSON、精确 RequestID 筛选和分页汇总。关键页面截图已在对应会话上报；实际调查范围内的去重条数与列表总数一致。私有 IP、Request ID、账户信息和认证材料均未写入本知识文件。
