# 通过 ChatGPT 图片工作区生成图片并回传 Happy

## 目标

复用已登录 ChatGPT 的图片能力，生成图片并通过 Happy send_image 回传当前会话

## 前置条件与授权

- 仅在当前登录、权限和用户授权范围内执行。
- 对象不唯一、影响范围扩大或不可逆时停止并向用户确认。

## 入口

从 `https://chatgpt.com/` 的登录态首页进入侧栏“图片”，目标工作区为 `https://chatgpt.com/images`。

## 已验证步骤

1. 在同一 Ego 任务空间打开 ChatGPT 首页，用语义页面快照确认已登录；为本次浏览器调用生成新的 `runId`。
2. 从侧栏进入“图片”，等待 SPA 路由稳定，并同时核验目标 URL 与“描述新图片”输入框。
3. 填写用户提示词，重新观察输入文本和“发送提示词”按钮，再提交。
4. 等待“正在创建图片”消失，确认对话中仍有原始提示词、图片元素、有效自然尺寸，以及编辑或分享控件。
5. 从生成图片元素读取 `currentSrc`，在 ChatGPT 页面上下文内用当前登录凭据执行 `fetch(src, { credentials: 'include' })`；要求响应成功后读取 `arrayBuffer()`，以二进制安全的方式传到 Node 并写入临时 PNG。不要点击界面“保存”，也不要依赖 `Downloads`。
6. 用 `file` 验证 PNG 类型和尺寸，调用 Happy `send_image` 发送绝对路径与原始提示词。
7. 用新鲜私有截图上报最终浏览器状态；无后续人工操作时以 `keep: false` 完成 Ego 任务空间。

## 检查点

- 登录态、图片入口或唯一生成对象无法确认时停止
- 页面仍显示生成中、图片元素没有有效自然尺寸或页面内抓取响应不成功时停止
- 结果不明或需扩大权限时停止并向用户确认
- 不要把图片临时签名 URL、对话 ID 或账号信息写入经验文件；直接抓取失败时不要未经确认回退到界面“保存”

## 成功标准

ChatGPT 对话显示生成图片并有成品操作；页面内带登录凭据的抓取返回成功，临时文件经 `file` 验证为 PNG 且尺寸有效；Happy 当前会话显示内联图片

## 失败模式与恢复

| 现象 | 根因 | 恢复 |
|------|------|------|
| 点击“图片”后短暂仍在首页 | SPA 路由更新有延迟，或 href 在页面中出现多个匹配项 | 使用最新语义快照消歧，等待后同时核验 URL 和“描述新图片”输入框 |
| 页面外的 `serverFetch` 请求图片失败或返回未授权 | 图片资源需要当前浏览器会话上下文 | 回到当前 ChatGPT 页面，在页面上下文用 `fetch(currentSrc, { credentials: 'include' })`；仍失败则停止，不自动点击界面保存 |
| 把响应当字符串写入 PNG 后文件损坏 | 二进制响应经过字符串解码，PNG 文件头可能被改写 | 只读取 `arrayBuffer()`，用二进制安全的传输编码落盘，再用 `file` 校验 |
| 生成结果中找不到有效图片元素 | 页面尚未完成渲染或当前页面不是目标对话 | 重新观察当前页面；确认生成完成、`currentSrc` 存在且自然尺寸大于 0，否则停止 |
| 截图辅助函数报 `currentTab is not a function` | 把当前 tab 对象传给了需要函数的参数 | 传入 `currentTab` 函数本身，并在同一调用内完成 URL 复核和截图 |

## 验证证据

- `https://chatgpt.com/images` 页面显示图片工作区；ChatGPT 对话中出现生成图片预览；PNG 文件类型和尺寸通过 `file` 校验；Happy 客户端收到内联图片。
- 使用独立 `runId` 的浏览器步骤截图记录了首页、图片工作区、提交、生成完成和导出状态；截图文件由 `captureVerifiedBrowserStep` 私有生成。
