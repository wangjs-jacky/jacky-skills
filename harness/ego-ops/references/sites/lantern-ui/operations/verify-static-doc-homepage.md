# 核对静态文档首页的必要交互与终态截图

## 目标

对已冻结的虚构 Lantern UI 文档首页执行中性浏览器核对：所测桌面搜索命中与空结果、Dialog 关闭与焦点返回，所测手机搜索命中与 Dialog 开关，以及对应状态截图。存在标题入场动画时，用限定元素的动画与计算样式确认其终态。

这是一次有限页面操作的已验证经验。它不判定候选优劣、完整生成流程、整个实验方法或完整可访问性通过，也不代表已发布最终报告门户。

## 前置条件与授权

输入为用户已授权观察的本地静态稿、冻结清单和本次访问入口。保持源码及观察副本不变；展示的安装命令属于未发布虚构包，不执行安装。所测 Dialog 为本地演示，不发送真实邀请或建立远端业务对象。

开始实际浏览器操作须遵循当前 `ego-browser` 与宿主的任务空间、截图和收尾规则。本次原观察由根协调者独占同一 Ego 空间完成，关键帧由原观察者按 Happy 规范逐次报告；写回者仅核对已有证据，不重启浏览器、不代发或复用这些帧。后续任务重新建立自己的控制权与证据链。

## 入口

使用任务当时提供的本地入口，核对当前标题、Lantern UI 名称及虚构产品说明。由当前 snapshot 找到“搜索组件”、Dialog 条目或其预览、组件导航、开始使用及复制控件。两份静态稿的搜索入口与 Dialog 触发位置不同；每次按实际语义选择，不保存临时引用号或某份稿件的元素 ID 作为长期脚本。

## 已验证步骤

1. 在桌面视口 `1440×900` 打开静态稿，读取页面标题、主标题、实际视口及文档宽度。另记字体加载情况，保留已知网络依赖；字体就绪不代替视觉终态核对。
2. 从当前 snapshot 定位搜索输入；有搜索入口按钮时先打开并重新观察。搜索 Dialog 后读回“找到 1 个组件”和相应结果文字；桌面再使用不匹配查询，读回“找到 0 个组件”和实际空态。以文字证明相应结果，不把不适用的采集字段解释成结果数。
3. 从当前结果或预览定位 Dialog 的打开控件，打开后读取对话框状态与内容。桌面分别以可访问名称明确的关闭按钮、重新打开后的 Escape 关闭，每次读取关闭状态和焦点是否返回对应打开控件。此次手机仅支持已有开关及焦点返回读回，不据此补齐全部键盘路径。
4. 操作所测导航后读取片段目标及目标区域的位置；已有证据仅证明相应区域进入视口。触发桌面复制后读取“已复制”等反馈；已有 `clipboard-read` 状态为 `prompt`，未申请权限、未读回剪贴板，因此只记界面反馈。
5. 在手机视口 `390×844` 打开同一冻结页面，分别读取实际视口和文档宽度，按当前 snapshot 重做所测搜索命中、Dialog 打开与关闭及焦点返回核对。手机空结果及完整键盘流程未测。
6. 按目标状态取帧。首份稿件最初的手机首页图捕获到标题入场动画中途；原观察者随后限定到 `h1` 的两项有限动画，等待其均为 `finished`，并读回标题各 span 的 `opacity=1`、`transform` 为 `none` 或单位矩阵后另取稳定帧。只等 `document.fonts` 就绪不足；不等待页面全部 scroll-linked 或无限循环动画结束。
7. 保留原暂态图、来源及报告先落盘、稳定帧后补的时序，分别注明状态。按当前宿主规则记录关键帧与最终浏览器状态；截图与读回应关联同一目标，不用增加截图或视口数量扩充独立生成数。

## 检查点

- 动作后重新观察实际控件、文字、Dialog 开关状态与焦点；旧 snapshot 引用不跨页面状态复用。
- 本次桌面实际 `innerWidth=1440`、`innerHeight=900`，`clientWidth=scrollWidth=1425`；手机实际 `390×844`，`clientWidth=scrollWidth=390`。视口、可用文档宽度、内容宽度分别记，不能把桌面宽度差误判为视口未设置。
- 首份稿件搜索输出中的 `visibleCards=[]` 是不适用选择器字段，保持不可用；同一记录里的“找到 1 个组件”及 Dialog 文字仍是有效的结果文字证据。已有冻结 HTML 使用的目录结构支持该适用范围解释，未补做元素列表测量，也不改写原数组。
- 导航的中途坐标与后续进入视口读回分开；进入视口不等于最终平滑滚动位置。
- 字体状态与标题动画状态分开。首份稿件记录了实际加载的在线字体，存在网络依赖；第二份未设置外部字体 face。这不证明所有环境离线视觉一致。
- 仅首份稿件的手机标题补帧有上述明确的有限动画终态读回；不能把这项证据推广到所有预览、动画或所有截图的终态。额外浏览器浮层归属未知，不作为候选 UI 评价。

## 成功标准

本 operation 的成功限于：两份冻结页面在所列桌面与手机视口实际打开；两页各有桌面搜索命中、空态、Dialog 按钮及 Escape 关闭与焦点返回的读回，各有手机搜索命中、Dialog 开关及焦点返回的读回；所测导航有进入视口证据，桌面复制有界面反馈；截图来源可追溯，标题暂态与经有限动画状态确认的补充终态分开保存。

必须同时保留未知：手机空结果与全部键盘路径、剪贴板实际内容、最终平滑滚动落点、其他全部预览状态、完整可访问性、真人审美及理解。两次生成 CLI 在限时被终止，不因页面可观察而视为完整生成成功。上述有限目标的成功才支持当前验证日期。

## 失败模式与恢复

- **标题入场暂态被当作最终排版**：字体等待已结束仍捕获到标题动画中途。已验证恢复是限定主标题的有限入场动画，读回完成状态及标题 span 的完全可见、位移归零，再另取稳定帧；原图及先后关系保留，不回写为作者早先已见终态。页面全体动画不是可用的统一等待条件。
- **采集字段不适用**：空的 `visibleCards` 数组与同次结果文字不一致时，不据数组抹掉结果，也不填造元素列表。此次仅用已有文本和冻结 HTML 限定解释，没有验证新的通用选择器或新列表测量。
- 剪贴板权限提示、导航动作中途读数及生成 CLI 限时结束均按证据边界记录，未证明为站点缺陷，也未验证额外修复或授权路径。
