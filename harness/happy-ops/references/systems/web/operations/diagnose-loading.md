## 步骤与检查点

1. 从真实入口分开检查 HTML、哈希资源、反代、目标 API 与 Socket。
2. 连接失败文案先定位对应请求；会话列表 bootstrap 失败不等于整个 Socket 离线。
3. 慢请求记录体积、次数、首连/重连及服务端耗时。反代 reload 卡住时观察旧连接清理与新旧连接存活。

## 成功标准

原失败路径有可复核响应；只对实际覆盖的页面/连接作结论。

## 失败模式与恢复

不要猜默认 health/Socket 路径。延迟关闭旧流是缓解，不证明底层写阻塞消失；一次成功不证明间歇问题根治。
