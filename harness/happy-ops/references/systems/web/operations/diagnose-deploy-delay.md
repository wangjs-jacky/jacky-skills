## 步骤与检查点

1. 用 gh run view <run-id> --json jobs 获取同一 run 的步骤时间。
2. 分别计算排队、准备、构建、上传、激活和校验；并行 OTA 不叠加到 Web。
3. 定位最长步骤，再查看相应脚本、对象数/字节、重试或反代重载。
4. 记录实测瓶颈与尚未验证的成因，减少重复构建；优化需另有实现和对比证据。

## 成功标准

能够用步骤时间解释本次等待，区分测量结果与根因假设。

## 失败模式与恢复

一次上传耗时样本不能证明长期网络瓶颈。不能为加速跳过完整性检查、预激活或回滚保障。
