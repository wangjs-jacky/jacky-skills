## 步骤与检查点

1. 确认具体集成的实际 runner、持久身份、会话订阅和调用边界，再读相关项目规则。
2. 区分启动探针、隔离真实任务和产品完整流程；对照持久 root/turn-end/public-message 与 UI。
   延迟排查应分别对齐提交、领取、线程启动、turn/start、真正回答请求、原生文本增量与UI显示。显式目录查询已删除不代表执行器内部不刷新目录；turn/start到正文也不能整体算作模型生成。缓存控制实验必须核对原生TTL和命中记录，复制文件不等于有效命中。
3. 若涉及资源回收，对齐任务 ledger 和运行实例；产物按来源、验证状态和实际交付保存。

## 成功标准

所声明集成路径有真实执行与产物证据；未覆盖身份、UI、生命周期或生产写入明确列出。

## 失败模式与恢复

连接/订阅成功不等于模型可用；文件存在不等于线上任务完成。不要把隔离视频采集当成写入产品后的完整成功。

已删除对象的创建 ID 不能复用。只有服务端明确拒绝复用该 ID 时，才允许保留原输入、持久化一个新 ID 并有界重试创建；网络不确定或普通拒绝仍保留原请求。删除确认只清理匹配的创建恢复记录，不能清空连接存储、凭据或执行 outbox。

原生会话恢复必须保留原 thread：已成功恢复后不要因重复初始化再恢复一次，失败也不能静默创建空白 thread。同步过期判断涉及数据库无时区时间列时，应使用明确 UTC 比较，并在生产时区执行真实数据库回归。
