# Happy/Paws 运维经验

仓库维护发布实现，执行工具完成操作，本 Skill 维护经验的读取、路由、验证和写回。不要复制一套会与仓库脚本漂移的发布实现。

## 渐进读取

1. 从宿主提供的当前 Skill 路径得到 `HAPPY_OPS_DIR`，不猜测安装目录。
2. 先读 [experience.local.md](experience.local.md)：短的本机兼容入口，不再承载整本历史。
3. 读 [index.md](index.md)，按目标命中一个 system 的 index.md，再只读该目标的 operation。跨端发布先读发布路由，再按实际受影响系统继续。
4. 需要主机、路径、当前版本或同类案例时，沿 local/systems 中同一系统和同一 operation 的证据入口读命中案例；不加载全部系统、操作或历史归档。
5. 核实目标工程当前指令、相关源码/workflow 或运行态，再行动。没有经验时做针对性探索，没有证据前不写“已验证”。

普通源码修改不因碰到 Happy 就自动升级为部署、全站 E2E、截图或视频任务。

## 事实、授权与验证

- 用户当前指令及会话中持续有效的授权优先；Ops 经验不能扩大授权，也不能让用户重复确认同一已授权动作。
- 项目政策由项目指令维护；路径、版本、代理、active release 等事实要现查。历史里的“当前/最新”只是当时快照。
- 项目记载的入口与实际安装不一致时，先核实差异和当前等价入口；不盲用旧命令，不以历史经验绕过发布边界。
- 发布不自动授权重启其他服务、清理既有 worker、切换账号或写数据库。只有新增影响、目标不唯一或缺少必要授权时才澄清。
- 浏览器遵循用户指定的 Ego 方案及当前浏览器 Skill，不复制其 API、任务空间或截图隔离规则。
- 一次只改已定位的子系统；先只读判别，再做最小复现。合并、构建、发布、页面加载和真机使用是不同结果，CI 绿色不自动证明激活步骤执行过。
- 复用已完成的有效测试、构建、CI 产物与发布证据；只在代码变化、失败或未解疑点出现时补验。不默认同时跑本地和 CI 的同目标发布。
- 取得与任务相称的成功证据后收尾，不为形式扩展截图矩阵、视频、全站扫描或重复读回。

## 验证后维护经验

真实成功后更新对应 operation 的验证日期、scope 和系统索引；重复成功只刷新验证记录，有新事实才改步骤。失败不刷新成功日期。查阅没有新事实时不制造更新。写入前按需读 [经验维护协议](references/knowledge-maintenance.md)。

- 可分享的方法 → 对应 `references/systems/<system>/operations/*.md`；跨操作共识归系统 index，目录状态与正文同步。
- 真实机器、路径、主机、账号标识、版本、命令参数、具体执行证据 → gitignored 的 `local/systems/<system>/` 与 `local/records/`，只维护证据，不复制公共 SOP。
- `experience.local.md` 仅保留兼容指针和必要本机边界。旧调用方新写入的正文要先归位，再缩回短入口。
- 未成功不得标为已验证；失败可以记录观察、证据和下一步，不把猜测升级成根因。
- 旧结论失效时修正文并指向替代项，同步系统索引的 status、last_verified 与 replacement，不能只追加相互冲突的“最新”。

不得保存密码、token、Cookie、私钥或可重放凭据。既有私有档案中的敏感材料不得复制到公共文档或聊天。自动沉淀不自动 commit、push、合并或发布。

修改后运行：

```bash
node "$HAPPY_OPS_DIR/scripts/validate-knowledge.mjs"
```

校验只证明结构与静态分享边界，不代表实际操作成功。交付时简述更新入口、验证结果和仍待验证的结论。
