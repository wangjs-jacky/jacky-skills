# 验证WS身份生命周期

## 目标与前置条件

验证既有WebSocket经过身份网关正常建立，并随同一绑定会话退出关闭。已确认应用Origin、认证和升级路径；不向真实会话发送模型任务来代替连接测试。

## 执行判断

分别检查匿名/错误Origin、合法已登录握手、101与非101头部，以及实际外部浏览器连接。针对原生认证桥接，服务端Cookie不应从任一分支外发。

退出时检查下游与上游一起清理，包含已升级和待升级连接；HTTP长响应另用实际流测试边界。用事件等待和一次期限判定，不把“WS仍连接”通过周期业务查询维持。

## 成功标准

合法路径升级及浏览器打开有证据，原生凭据不外发；同绑定退出后现存连接关闭且旧API身份失效。只有握手证据时不声称消息收发或业务完成。

## 坑与恢复

只销毁下游可能遗留上游流或握手；只过滤HTTP proxyRes可能漏掉WS响应头。普通网页成功但WS失败时还需核对实际代理协议及Origin，不能凭页面200归因服务端。

## 证据边界

2026-11-08，原生服务真实101、浏览器WS打开、同一测试绑定退出关闭连接通过；真实socket测试覆盖未完成握手和长响应清理。应用消息/模型完整任务、SSE完整业务及长期重连不在本操作声明范围。
