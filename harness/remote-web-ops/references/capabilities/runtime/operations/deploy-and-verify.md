# 部署远端服务并分层验收

## 目标与前置条件

让指定版本服务在已选远端主机运行并支持外部使用。先确认数据真源、运行用户、启动必读依赖、访问范围和原有服务；具体部署选择读取architecture-deploy-ops相应拓扑，平台配置读取对应OPS。

## 执行判断

核对实际运行入口与版本、监听绑定和持久化路径，再配置最小部署单元与访问入口。纯本机服务的loopback地址不能直接被外部浏览器访问；需要入口时转connectivity。先保留原可回滚副本，再切换需要变动的单元。

启动就绪使用现有服务事件或一次验证；Cloudflare场景遵循其禁止业务状态轮询的要求。后台启动可读性须由实际后台进程验证，不能从SSH/Finder读取推断。

## 成功标准

版本/进程、后台依赖、外部真实业务及约定的恢复路径分别有证据；未做整机/未登录启动就明确留缺口。原数据与其他服务保留，停止/回退范围可定位。

## 坑与恢复

端口存在可能是旧进程；开发shell依赖可能未进入后台环境。定位实际入口后定点恢复，不能通过清空状态目录或整树覆盖来掩盖问题。

## 证据边界

此操作是已有架构方法的编排指引，未在本Skill声明完整业务部署验收。已有运行案例需从私有目标读取其真实范围，不沿用迁入日作为成功日。
