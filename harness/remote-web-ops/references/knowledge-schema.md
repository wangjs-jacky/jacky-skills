# 知识格式与持续写回

## 唯一来源

| 内容 | 归属 |
| --- | --- |
| 能力命中与档案导航 | references/capabilities/index.md |
| 能力共用事实、限制和操作目录 | references/capabilities/<capability>/index.md |
| 一个用户目标的适用条件、做法及验收 | 能力下operations/<operation>.md |
| 原始需求、执行状态、证据、实际配置与报告 | 已有Goal First目标；可选experience.local.md只保存定位入口 |

共享文档不链接创建者的私有文件。私有入口可反向引用共享操作；已有目标中同一事实不另存一份实例状态。没有Goal First目标时按用户指定的唯一目标位置保存过程，首次可只记录定位信息，不为形式创建多层空目录。

## 元数据

能力档案包含capability字段。Operation使用capability、operation、status、last_verified四字段；slug与目录/文件名一致。

| status | 含义 | last_verified |
| --- | --- | --- |
| documented | 文档/设计指导，业务尚未完整验证 | null |
| partial | 有实际部分证据，仍有成功条件未满足 | null |
| verified | 声明的操作目标及成功标准有实际证据 | 真实成功日期 |

操作正文包含目标、适用条件、执行判断、成功标准、坑与恢复、证据边界。源码/文档推断和运行读回明确区分；一个操作验证某版本的特定路径，不代表整个服务或其他版本均通过。

目录中的状态日期与operation对应；历史迁入不改验证日，今天创建文件不等于今天重新验收。能力没有当前操作时说明现有路由与候选范围，不虚构验证记录。

## 每轮写回

1. 对照成功标准，确定完整成功、部分执行、失败或没有新增知识。
2. 找唯一归属，更新过时结论及适用条件；同一事实跨能力通过引用关联。
3. 只在实际完整成功时刷新该operation和索引的日期；同日事实一致可无diff并说明已核对。失败/中断只记录已观察结果、缺口与下一步。
4. 检查文件引用、字段、日期及索引；公开方法脱敏，私有目标保留精确来源。静态检查不证明业务恢复。
5. 报告实际写回位置、验证范围和剩余问题。写入失败时明确未保存。

服务案例可提示新方法，但不能把其TTL、URL正则或提供商选择直接变成通用默认。新增同类经验自动维护；分类或职责实质变化再对齐。

## 隐私与授权

.gitignore排除experience.local.md、*.local.*及local/。真实主机/域名/路径等只留目标或ignored定位入口；凭据、Cookie、Token、签名URL、完整业务响应和无关日志不进入任何知识文件。

写回不自动提交、推送、安装、修改全局规则或执行额外业务。用户接管浏览器时立即遵循停止规则，只整理已取得且允许保存的证据。
