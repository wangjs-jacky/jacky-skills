# 确认 OPS

把一次次“选哪个、要不要继续”转为**条件明确、可撤销的决策经验**。显示名称为“确认 OPS”，调用标识为 `confirmation-ops`。不修改第三方 Skill；在 Agent 准备提问时先判断是否已有答案。

## 安装时

安装/配置 Agent 读取[全局前置提示词](references/global-agents-prompt.md)，核对真实全局文件和既有授权；有授权则合并并读回，没有则展示具体规则后问一次。只创建 Skill 不等于授权修改全局指令；普通任务不重复安装交互。

## 提问前的运行流程

1. **先查当前任务。** 已有明确指令、已批准方案或执行范围时，继续完成工作，不为保存记忆再问一次。常规实现细节由 Agent 判断，不人为制造确认节点。
2. **定位真正的决定。** 用一句话说明“为了哪个目标，在什么状态下，需要决定什么”。读[场景索引](references/scenarios/index.md)，命中 `scenario → operation`，只读对应档案和操作。Skill 名只是来源，不是决策主键。分类变更时才读[分类模型](references/ops-model.md)。
3. **查个人规则。** 如有 `experience.local.md`，只读取命中场景的规则与所需证据。未配置个人规则的分发副本没有任何人的默认授权。
4. **复核匹配。** 按[决策匹配](references/matching.md)比较目标、对象范围、环境、影响、前置条件、例外和有效期。先判断可否选择，再判断是否获准执行；不能用“推荐”替代授权。
5. **命中就继续。** 对可替代的偏好/流程确认，直接使用已匹配规则；不伪造用户消息、点击记录或“已人工验收”。涉及实际变更仍遵守原工具契约。可在进度中简述采用何项既有决定，不把通知改成新问题。
6. **未命中才问。** 真正缺失的选择或授权用一个具体问题补齐，展示推荐及关键后果。可独立完成的准备工作先完成，让用户决定可审阅的结果；等待时继续不依赖答复的工作。沉默、预选、超时都不是回答。不同性质的决定不能捆成一个含糊的“确认”。
7. **自动写回。** 按[知识与写回](references/knowledge-schema.md)记录人作出的选择、适用条件和结果；不额外问“要不要记住”。自动选择只增加执行证据，不增加用户同意次数。更正立即生效，撤销优先。

## 第三方 Skill 怎么接入

将它提出的确认理解为一个决策点。流程性“请确认方案”可由用户已经给出的同范围决定满足；若该 Skill 允许默认值且当前任务已授权，也可按默认值继续。用户明确委托可覆盖第三方 Skill 的一般提问习惯，但不能假造要求用户本人完成的签署、身份验证、验收或宿主强制批准。遇到不能满足的门槛，说明要求的来源和本次缺少什么，不仅说“Skill 要求”。

本 Skill 由执行中的 Agent 遵循，不是弹窗拦截器、后台监听器或强制钩子。不能替另一会话作答，也不自动修改第三方文件。已有系统/开发者/工具授权约束保持有效；如自动审批拒绝，报告原因并使用获准替代路径，不能通过重新包装成偏好重试绕过。

## 收尾

报告本次采用/新增/修正了什么规则及实际写回路径，区分选择已记录、行为已执行、结果已验证。没有新知识可简述原因；写入失败必须说未保存。知识更新不自动提交、推送或扩大业务权限。
