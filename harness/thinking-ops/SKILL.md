# 思维 OPS

让用户用自己的话讲困惑，由 Agent 选择有帮助的方法并实际运用。产出应让用户看见新的理解、可考虑的方向或值得验证的下一步，而不止收到框架名称。

以 **困惑场景 `scenario` → 思维操作 `operation`** 组织持续增长的方法与经验库。资料可以提供起点，实际使用会不断补充、修正和发展方法；方法数量与来源不设固定范围。来源与改编见[来源说明](references/sources.md)；分类与扩展决定见[分类模型](references/ops-model.md)。

## 安装时

安装或配置 Agent 先读[可选全局前置提示词](references/global-agents-prompt.md)，检查真实安装入口与已有同范围授权。展示完整规则及实际全局文件后，有明确授权才写入；仅创建或安装 Skill 不授权修改全局指令。普通使用跳过安装交互。

## 先选方法，再实际使用

1. 从实际 Skill 位置确认唯一知识源。有 `experience.local.md` 时只读命中场景的入口，不遍历个人经历。
2. 读[场景索引](references/scenarios/index.md)，按此刻卡点命中场景，沿子索引读取合适的 operation。指定方法时直接定位，先筛候选再读正文，不默认遍历全库。
3. 按[方法选型与灵感](references/select-and-use.md)核对目标、事实、约束和需要的深度。通常推荐一套并用一句话解释理由；比较方法时给少量候选及差别。信息充分就开始。
4. 按命中 operation 实际工作。只为可能改变判断的缺项提问，对话式方法每轮只问一个问题；已有答案不再问。只想快速找灵感时先给具体思路与适用条件，不强制长问诊。
5. 没有合适条目时，围绕当前事实分析、组合或设计新方法，明确哪些仍待验证，不把问题硬塞进既有框架。读到新材料时，提炼其解决的卡点、机制和适用边界，按知识协议判断是否入库。
6. 对照当前目标收束。需要下一方法时说明要补哪个缺口，再读相应条目；不机械跑完整个目录。

## 执行边界

- 用用户的问题分析。只有明确索要可复制 Prompt 时才输出模板，不让用户自己填空再来一次。
- 灵感、假设、类比、条件建议与核实事实分开。最新资料与事实核查使用当前真实来源；不能联网或证据不足时标明暂未核实的范围。
- 专家会诊是专业视角分析，不冒充真实专家或独立多 Agent 评审。天赋推测要对应经历、允许更正，不作心理诊断。
- 篇幅按请求调整，不继承上游默认万字要求。信息充分时给明确建议；价值偏好未知时给条件判断，不替用户发明偏好。
- 用户明确调用其他专用 Skill 时保留其目标和流程。真实研究、技术实验、开发与发布继续遵循对应工具及授权。
- 设计实验不等于获准执行；不因建议自行付费、联系他人、变更系统或安排后台任务。

## 反馈与自动沉淀

每次完成、失败或中断时按[知识与写回协议](references/knowledge-schema.md)判断和维护，不等待用户另说“记一下”：

- 共享选型线索和方法修正回到所属场景或 operation；私人实例只存必要摘要与证据导航，避免全文保存用户困惑。
- 既有方法能解释的新经验合入原条目；遇到机制不同且可复用的新方法时，创建独立 operation 并同步场景索引。无需为了满足方法数量补条目，也不因不在初始资料里而拒绝入库。
- 记录选了什么、为什么、产出了什么、实际反馈如何。没有反馈就写未知，不把沉默当满意或长期偏好。
- 文档导入保持 `documented`、`last_verified: null`。真实使用只验证当次目标，不能证明方法普遍有效或最终选择必然正确。
- 保留 ID、同步父索引并沿链接读回。写入失败如实报告；无新知识说明原因，重复真实成功仍维护对应日期。

交付简述所用方法、可用结果与必要下一步；修改知识时报告实际保存位置。自动沉淀是 Agent 协议，不是后台监控或宿主拦截器。

调用例：`用思维 OPS 帮我看看：我想做个人产品，但方向太多。先选合适的方法，给我几个有区别的思路和一个能试的小动作。`
