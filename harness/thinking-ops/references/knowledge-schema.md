# 知识、反馈与自动写回

## 归属与身份

沿[场景清单](scenarios/index.md)读场景，再读 operation。父索引给 ID、摘要、读取条件与关键避用条件，不复制完整正文或手抄另一份状态表。

跨场景选型只放 `select-and-use.md`；场景共性只放子索引；单方法经验只放 operation。私人实例由小型 `experience.local.md` 指向 `local/` 唯一记录，不复制公共方法。

Markdown 使用 `id`、`title`、`summary`。operation 另有 `scenario`、`operation`、`status`、`last_verified`、`use_when`、`avoid_when`。ID 稳定，不依赖资料来源的编号。

来源可以在正文说明，或用可选的 `sources` 元数据列出资料、用户提供的方法、实践提炼依据或尚待验证的设计。旧条目的 `source_prompt` 仅保留原始资料定位，不是新方法的必填字段，不限定来源和数量。

## 让知识持续增长

- **补充经验**：方法相同而情境、反馈或失效条件有新信息时，合入已有条目；不能因为又用过一次就复制一个方法。
- **新增方法**：卡点与机制明确、具有复用价值且不同于现有条目时，分配稳定 ID，写入适合场景的 operation，再同步父索引。写清做法、适用/避用条件、可观察的成功标准和来源。
- **吸收材料**：从文章、案例、用户做法或其他资料提炼机制与边界，保留准确归属。文档支持的是方法设计，不能当真人使用成功。
- **从实践提炼**：实际解决过程中形成的新做法，可以记录为待验证方法；泛化到什么范围由证据决定，不伪造通用理论或权威出处。
- **修正与整合**：新证据优先，失效知识降级或修正；同义条目先引用或合并内容，涉及改变既有归属时按分类模型处理。失败、错配和不确定结果同样是经验。

先复用和判断，再决定合入、补充或新增。没有可复用新事实时不凑条目；任何一次来源导入都不构成库的容量或能力上限。

## 证据与可信度

| 证据 | 能说明 | 不能说明 |
| --- | --- | --- |
| 资料、文件、链接核对 | 来源、导入内容与结构可读 | 已帮助真人解决困惑 |
| 实际运用得到分析或计划 | 当次产出是否覆盖标准 | 用户认可、最终选择正确或实验有效 |
| 用户明确反馈或现实结果 | 记录条件下的帮助或缺陷 | 永久偏好、普遍有效或因果疗效 |

- `documented`：来源或设计已记录，`last_verified: null`。
- `partial`：实际使用有部分证据，但声明的成功标准未齐，日期仍为 `null`。
- `verified`：当次目标及其全部标准有直接证据，写实际日期、条件和验证范围。静态检查不能升级；“理解了”“获得灵感”等主观目标必须由用户反馈支持。

行动没发生时只能验证计划形成，不能验证实验结果。一例成功不等于某方法永远最适合用户。新证据推翻旧结论时修正或降级，保留必要历史范围。

## 每轮自动写回

1. 对照 operation，分清产出、实际反馈、未知效果与中断原因。
2. 只沉淀会影响下次选择的事实：卡点、方法与理由、帮助或失配、适用条件。假设写假设，无反馈写未知。
3. 单方法改进回 operation，新方法按上节新增并进入父索引，路由改进回场景或共享选型；私人反馈只进 ignored 实例。没有新知识说明原因，不造空经验。
4. 重复真实成功仍维护该 operation 的日期与范围；同步受影响索引的摘要、条件、链接和已有验证字段，不用一项成功刷新全部方法。
5. 沿父索引读回修改，核对 ID、内容、链接和隐私；有适用校验器则使用。不为刷新日期重跑现实行动。
6. 报告实际保存位置与范围；写入或校验失败明确未沉淀，不把拟议补丁称为已保存。

## 私人实例

出现真实实例再建私有文件。按需记录日期、场景/方法 ID、去标识的问题摘要、明确目标和限制、选择理由、产出位置、必要反馈摘要、未知项和读取条件。不强制每次填满字段。

`.gitignore` 排除 `experience.local.md`、`*.local.*`、`local/`。不自动存完整聊天、亲密关系细节、健康经历或他人身份；只留方法复用所需的最低限度信息。用户明确不存或更正时遵循当前要求。密钥、Cookie 和认证材料即使在 ignored 文件中也不保存。

首次分类按[分类模型](ops-model.md)；分类确认后同类经验自动维护，改分类、拆并归属或扩大范围再确认。写回不授权全局配置、私人资料跨机、提交推送或额外业务行动。
