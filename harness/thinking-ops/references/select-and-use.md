# 方法选型与灵感

## 分辨两种选型

- **选思维工具**：推荐最符合卡点的方法，必要时附备选，解释分别能产出什么。用户想看目录时按当前索引列出，不将初始方法当完整范围。
- **解决实际纠结**：说明方法后直接展开。不要停在“可以用钢人论证”，也不要只给复制模板。

只想找灵感时，先给有依据的新视角；资料不足标记假设，不强制长问卷。明确的方法请求优先，不擅自换成喜欢的方法。

## 按真正瓶颈分流

以下是已经沉淀的选型线索，随着新方法和真实反馈继续修正。它们帮助缩小候选，不要求所有问题都套入表中。

| 卡点 | 优先操作 | 相邻误选 |
| --- | --- | --- |
| 说不清问题或目标 | clarify / socratic | 先出十个方案会固化错误前提 |
| 一个概念听不懂 | learn / two-layer | 不必默认开展行业研究 |
| 有优秀实例想学 | learn / reverse-engineer | 缺材料时不编造内部过程 |
| 缺领域全景与比较对象 | learn / vertical-horizontal | 核查一项数据不必大研究 |
| 关键说法可能有误 | learn / fact-check | 漂亮论证不能代替证据 |
| 多种利益、专业约束冲突 | solve / expert-panel | 三个相近头衔不等于互补视角 |
| 惯性方案只会打补丁 | solve / first-principles | 不得删掉硬约束制造新方案 |
| 同领域办法失效 | solve / cross-domain | 相邻产品换名字不等于跨领域 |
| 两条可行路线各有道理 | decide / steelman | 多个候选不要硬塞成假二选一 |
| 缺现实中可观察的证据 | decide / min-experiment | 不再靠想象中的偏好加权绕圈 |
| 不清楚优势与能量来源 | self / hidden-talent | 一句自评不能定天赋 |
| 不知道想过什么生活 | self / life-design | 更多 A/B 比较可能补不了价值方向 |

“复杂”本身不足以选专家会诊；先分清缺知识、缺解法、缺证据还是缺价值排序。“推倒重来”也可能只是情绪表达，要结合事实。

没有匹配方法时，在明确事实和约束下直接分析、组合或提出新做法，说明设计依据与待验证部分；不要只回“库里没有”或勉强套用近似方法。有复用价值时按[知识协议](knowledge-schema.md)补入所属场景，后续用实际反馈修正。

## 让灵感能使用

对值得展开的方向，说明它改变了哪个假设、为什么可能有用、成立条件，以及怎样用一个小动作观察。无证据的想法标记待验证。

例如“副业做内容还是工具”：目标与限制已明确时可比较两条路；分歧取决于能否持续写作或是否有人付费时，转短周期原型。若收入、表达和自由哪个更重要仍未知，先澄清目标；不能只见“副业”就固定分流。

思路的区别应体现在机制、交付、资源或反馈速度上，不是同一方案换三个名字。数量按请求调整，不强制每次三条。

## 有限串联与结束

常见串联：澄清→命中方法，核查→比较，钢人→实验，人生版本→原型。先解决一处瓶颈，看见新缺口才读下一操作。

本轮可用成果可以是准确问题、新理解、有区别的方向、条件建议或验证计划。不要以跑完所有方法作为标准。

用户纠正目标或说方法没帮助时，更新判断并更换路径，按[写回协议](knowledge-schema.md)记录失配条件，不将当次错配解释为用户人格问题。
