# 反向拆解

输入是具体实例及想学到的能力。先读材料；链接只能看到部分时说明范围，不能伪装看过全部。

## 怎样做

1. 一句话说明它为谁解决什么问题，区分材料明确表达和你的推断。
2. 拆结构、流程、关键选择与完成标准，找出最影响结果的少数环节。
3. 对每个重要选择解释可能机制及证据；没有内部资料就不声称知道实际制作过程。
4. 分开可迁移规律与依赖原案例资源、渠道、品牌或环境的细节，交代迁移条件。
5. 提炼三到五条可复用做法、一份能执行的清单和一个最值得先做的小练习，篇幅按用户请求调整。

## 成功与常见失配

产出可回指实例的关键选择、明确迁移边界与具体练习。没有效果数据时只能解释“为什么可能有效”，不把漂亮成品等同于业务成功。

避免只复述表面样式、把个人审美当机制，或把大团队的资源条件当通用步骤。用户开始实际复刻或开发时，使用对应制作 Skill，不在此处扩写工具手册。
