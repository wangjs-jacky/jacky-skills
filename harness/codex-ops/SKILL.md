# Codex OPS

按 **capability → operations** 复用 Codex 自身的使用与运维经验。五类能力和扩展规则见[分类模型](references/ops-model.md)。

## 安装时：建议启用全局前置

安装或配置本 Skill 的 Agent 先读[全局触发提示词](references/global-agents-prompt.md)，展示规则、实际目标文件与范围，获得明确授权后合并；已有同范围授权直接复用。普通任务跳过安装交互。

`codex-env-config` 保留为兼容入口；额度查询调用可单独安装的 `codex-quota`。按当前目录或安装注册表定位依赖，不能假设与本 Skill 相邻。复制文件不会自动运行安装交互。

## 渐进读取

1. 从本 Skill 的实际位置定位唯一知识源；存在 `experience.local.md` 时只读相关实例入口。
2. 读[能力索引](references/capabilities/index.md)，命中能力档案及本次 operation。首次归类或扩展时读分类模型，不遍历全部经验。
3. 核对实际宿主、二进制来源和版本、有效配置目录、账号归属及用户目标。隔离会话、PATH CLI 与桌面内置程序可能是不同实例。
4. 涉及 Codex 当前功能、配置键或官方规则时使用可用的 `openai-docs` 核对官方来源；没有该 Skill 时直接查官方资料。实际工具参数以本次二进制帮助和运行证据复核。旧补丁、分发版本、私有端点的行为不可当成通用保证。
5. 缺少经验时在既有授权内探索并按证据记录；同类 operation 可按模型自动补充，改变分类或扩大范围再请用户确认。

## 执行边界

- 只读取必要配置字段，不打印完整认证文件、全局指令、进程环境或会话日志。全局指令也可能含历史敏感内容。
- 配置文件写入、宿主实际加载、模型请求成功是不同结果。报告具体完成哪一步；不得把诊断工具通过当作端到端成功。
- 使用原安装渠道与实际配置层。改动前保存可恢复副本，保留无关设置；重启、停止、登录和真实模型请求沿用任务授权，不为采集证据自动扩大动作。
- 远端任务先加载可用 SSH 执行 Skill，核对当前设备；迁移配置时适配路径、hooks、MCP 与登录方式。历史设备清单不能覆盖用户最新说明。
- Happy 等宿主的会话生命周期、SDK、模型目录 UI 与服务协议由对应工程 OPS 维护；普通编码习惯继续由 `codex-harness` 维护。交叉任务分别引用，不循环调用或复制整库。
- 验证方式服从当前用户与上层指令；结构检查、配置读回和真实执行证据分别记录。

## 自动沉淀与收尾

完成、失败或中断时，按[知识格式与写回协议](references/knowledge-schema.md)更新唯一归属，不等待用户另说“记录一下”：

- 跨操作事实进能力档案，单目标步骤与坑进 operation，机器和证据映射进 ignored 私有记录。
- 完整成功才更新 `last_verified`；重复成功仍维护验证日期，部分结果和失败不能刷新成功日期。
- 当前证据推翻旧结论时修正或降级，保留必要历史；没有新增时说明原因，同日重复核对可无文件 diff。
- 写入受阻时报告未沉淀，给出补丁或唯一可写经验源；同步受影响的索引和引用。
- 报告结果、实际写回位置及遗留项。该协议依靠 Agent 执行，不提供后台服务、工具拦截或自动提交推送。

凭据、Cookie、Token、签名 URL 与可重放认证材料不得进入任何经验文件。被忽略的文件也不保存秘密。
