# 查询并解释 Codex 剩余额度

## 目标与前置

回答用户所指实例的日志额度记录，并说明来源和新鲜度。需要已安装 `codex-quota` 和 Node；缺依赖时报告，不为一次查询安装整个宿主应用。

## 流程

1. 读取已安装 `codex-quota/SKILL.md`，复用其脚本参数与字段解释。明确用户指当前隔离会话、持久目录还是指定实例。
2. 用户动作触发一次脚本查询；比较默认目录或指定目录使用该 Skill 的对应参数。不要打印原始 JSONL、认证文件或对话正文。
3. 按执行 Skill 的契约解释有效记录、窗口时长、观测时间、重置时间、过期及不完整状态；不在本 operation 复制一套易漂移的字段规则。
4. 多来源分别标注，不根据百分比吻合就绑定账号；宿主 UI 的 profile 归属问题由对应工程 OPS 继续排查。
5. 报告剩余比例、窗口、重置时间和记录时间。没有有效记录时明确未知，不发额外模型请求来刷新额度。

## 成功标准

目标来源正确，脚本结果的时间及不完整性得到准确解释，未泄露日志内容。“成功读取未知/过期状态”也可完成日志查询目标，但不能称为已经确认实时额度。

## 坑与恢复

固定把 primary/secondary 当作固定长度窗口、把记录重置时间已到当成额度已恢复、把另一个账号读数用作当前账号都会误报。具体解释以执行 Skill 为唯一事实源。

## 证据

2026-10-15 仅阅读现有脚本，没有运行额度查询。旧项目多账号额度归因经验保留在工程历史，不自动升级为本操作的完整验证。
