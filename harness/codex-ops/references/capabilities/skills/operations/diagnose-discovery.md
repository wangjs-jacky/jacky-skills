# 排查技能未发现或未触发

## 目标与前置

区分路径不可读、宿主未发现、匹配未命中和调用后未遵循。用户明确点名 Skill 时，先按目录表或注册表定位，不让名称匹配失败阻断已知入口。

## 流程

1. 查看当前提供的技能元数据和真实目录。展开 `rN`，原样使用目录表路径；不将 `plugin:skill` 猜成嵌套目录。
2. 检查 `SKILL.md` 大小写、frontmatter、权限、软链接目标及目标所在机器；同名多来源分别辨认。
3. 核对当前宿主支持的发现位置、配置启用状态与 `agents/openai.yaml` 的 `allow_implicit_invocation`。关闭隐式调用不代表显式调用被禁。
4. 未被发现时处理安装或加载问题；已发现而匹配偏差时检查 description 与用户实际目标，不把范围扩大成任何任务都触发。
5. 若要求全局前置，核对已批准规则及实际加载证据；不能把“description 含关键词”当成强制拦截。
6. 读回修复后路径/目录表；未进行真实调用时明确仅完成静态发现检查。按授权选择是否重载宿主。

## 成功标准

指出故障层及证据，修复后目标文件可读且对应发现状态改善；实际触发和遵循没有证据时保留未验证。

## 坑与恢复

旧经验中固定 `~/.codex/skills` 曾掩盖目录表提供的其他有效位置。不要为适配一个宿主把同源技能无条件复制到所有候选目录。

## 证据

旧环境 2026-09-09 路径解析案例保留原日期；2026-10-15 核对官方发现与隐式调用规则。本次未运行模型触发测试。
