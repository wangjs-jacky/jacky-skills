# 迁移 Codex 环境

## 目标与前置

在用户确认的目标设备上建立适配后的环境。先加载当前 SSH 执行 Skill，核对源、目标和登录身份；历史别名不足以确认设备，退役记录不作为连接入口。

## 流程

1. 只读盘点目标安装来源、有效配置目录、可发现技能目录及现有 hooks/MCP；核对目标是否已有有效配置。
2. 为计划改动建立目标侧备份，区分共享配置与机器专属路径、代理、应用入口及信任目录。
3. 按[安装升级](install-upgrade.md)准备程序；适配配置，不覆盖仍有效的目标 hooks。订阅认证、API key 和系统凭据存储分别处理，优先在目标执行适用的登录流程。
4. 若用户已授权传送认证材料，使用受保护通道和限制权限的文件操作，不读取展示内容、不把秘密写入经验；不能假设复制文件可迁移系统 keychain 登录。
5. 按[技能同步](../../skills/operations/install-sync.md)安装并解决目标软链接。配置键与加载规则按目标版本复核。
6. 分别报告安装、配置、技能发现、认证和真实请求是否已完成。需要重启的目标由用户授权的宿主管理路径处理。

## 成功标准

目标身份明确、所有本次迁移项可读且适配目标环境、原配置可恢复。用户要求的运行能力已有对应证据；未完成的登录或重载明确列出。

## 坑与恢复

本机绝对路径与软链接复制到另一机器常会断裂；不能一律解引用整个技能目录，先排除私有经验、凭据及无关文件，再安装共享内容。源机器更新不等于远端更新。

## 证据

保留旧远端迁移历史的原日期和退役标记；本次没有连接远端，也未用历史主机地址验证迁移。
