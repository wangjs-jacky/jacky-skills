# 安装或升级 Codex

## 目标与前置

让用户指定的入口运行目标版本，保留回退路径。先确认目标宿主、机器、版本需求及当前安装渠道；不把安装任务扩大为切换账号或所有会话模型。

## 流程

1. 用 `command -v codex`、shell 的命令解析信息和实际二进制 `--version` 核对来源；别名、函数、软链接与桌面内置入口分别记录。
2. 查询当前官方安装说明和本机包管理器状态；已有 npm、Homebrew、独立发行目录或桌面管理的程序沿原渠道更新。需要改渠道时明确原因及原入口的处置。
3. 在写入前保存相关配置、链接目标和版本信息；包管理器升级不顺带覆盖配置。旧版本仍被进程使用时保留其目录。
4. 按目标版本安装，随后读回实际解析路径和版本；检查包装函数及宿主启动路径是否仍指向旧程序。
5. 诊断命令先查看本版本帮助。若任务还要求证明可用，在授权范围内完成一次真实请求，并分别报告版本、认证、请求结果；不能为刷新验证日期自行发请求。

## 成功标准

目标入口的实际版本与用户要求一致、安装来源明确、无关配置保留且回退方法可用。运行中的其他实例是否更新另行报告。

## 坑与恢复

- `codex update` 并非对所有安装来源可用；失败时核对来源，不循环重装多个渠道。
- 新链接不影响已启动进程；按宿主管理方式处理用户授权的重启。
- 回退恢复原安装版本或链接与本次确实改动的配置，不删除其他程序或历史目录。
