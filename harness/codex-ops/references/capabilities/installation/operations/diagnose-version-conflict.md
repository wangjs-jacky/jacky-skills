# 诊断版本与 PATH 冲突

## 目标与前置

查明用户操作实际使用哪个二进制、包装入口和运行版本。诊断授权不隐含删除旧程序。

## 流程

1. 区分 shell CLI、桌面内置 Codex、宿主托管 app-server；只检查目标相关的启动信息，避免输出完整进程环境。
2. 对比命令解析结果、软链接真实目标、包管理器记录和具体二进制的版本。shell 函数/alias 与 PATH 排序可能先于磁盘链接决定入口。
3. 核对目标进程的启动时间和可执行文件；磁盘版本变化不证明既有进程换版。
4. 输出差异及最小修复建议；已有修复授权时调整精确入口，读回目标版本。保留仍被其他宿主使用的版本。

## 成功标准

能说明每个相关入口的来源和版本，并指出冲突发生在哪一层；已修复时另给目标入口的读回证据。证据不足时标未知。

## 坑与恢复

`which` 的单一结果不能证明桌面版来源；PATH 中存在新文件不能证明包装函数使用它。删除旧程序前确认没有调用方，恢复原链接时核对是否被其他任务修改。

## 证据

旧环境记录曾同时出现 PATH CLI 与桌面内置版本差异。本次只整理诊断方法，未重新盘点当前运行进程。
