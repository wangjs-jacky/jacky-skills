# 修改运行配置

## 目标与前置

在用户要求的实例和作用域修改模型、provider 或其他配置。先确认是单次运行、持久默认值还是宿主会话覆盖；运行时已明确应用的设置直接复用。

## 流程

1. 查明目标启动入口、有效配置根、命令行覆盖与当前 profile；按[能力档案](../index.md)复核字段允许出现的层级。
2. 查询当前官方键名和目标版本支持。模型可见、账号可访问、一次请求成功分别判断；不从旧目录或另一账号推断可用性。
3. 只读相关字段并安全备份。保留无关 projects、hooks、MCP、插件和策略配置。
4. 精确修改 TOML：顶层键保持在任何 table 之外；使用实际解析结构或可靠定点编辑，避免把顶层键追加进末尾 table。
5. 读回修改字段并核对差异。需要宿主重载时按授权处理，不停止其他活跃会话。真实请求按任务要求另行取证。

## 成功标准

正确文件与作用域保存了期望键，结构有效、无关内容保留；报告宿主加载是否有证据。若目标包含实际模型可用，需该实例的请求证据。

## 坑与恢复

启动参数可覆盖全局值；项目层不接受所有 provider 键；profile 格式随版本变化。恢复时只还原本次差异，不能用旧完整备份覆盖其后并发更新。

## 证据

基于 2026-10-15 官方配置资料及旧环境经验；本次未修改任何 Codex 运行配置。

## 宿主保留的 provider 名称与继承字段

2026-11-05局部验证：集成宿主的私有账号home可能继承全局provider表。命令行覆盖端点并不会证明旧认证字段已消失，应比较有效配置中的字段名及期望值，避免打印认证值。保留既有账号隔离校验，在已授权目标内备份并移除冲突项，再分别验证新进程加载及真实请求。二进制目录名不等于实际版本。具体宿主、字段和证据归本机实例索引；本项不代表整个操作所有配置层都已完整验证，原状态保留。
