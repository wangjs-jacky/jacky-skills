# 诊断配置未生效

## 目标与前置

定位期望值和实际值在哪个加载层分歧。只读诊断不自行降低权限、信任项目或重启活跃宿主。

## 流程

1. 明确具体设置与目标实例，核对实际二进制版本、启动时间、工作目录和配置根。
2. 按[配置档案](../index.md)检查 CLI 覆盖、项目配置及信任、profile、用户/受管/系统层和字段允许的层级。仅提取相关键，启动命令可能含认证值，应脱敏。
3. 对 AGENTS 问题另查 override、目录链、指令大小限制和宿主注入；Skill 发现问题转到[发现排障](../../skills/operations/diagnose-discovery.md)。
4. 对照磁盘值、宿主显示/有效配置和已知启动快照。配置解析或诊断报告可用时先查帮助再使用，不打印完整报告。
5. 给出证据支持的原因及最小修复；用户已要求修复时调用对应配置操作，否则记录待执行项。

## 成功标准

有可解释的“目标值 → 来源文件/覆盖层 → 实际值”证据链；原因未知时说明缺失层。修复后的加载或请求成功需各自证据。

## 坑与恢复

磁盘新值、版本已升级、宿主菜单更新都不能单独证明旧进程已使用该值。宿主历史模型目录也不能作为当前账号权限证明。

## 证据

2026-10-15 核对官方配置与 AGENTS 说明；旧记录中的启动覆盖与长期进程行为作为有适用范围的历史经验。

2026-10-17局部本地实测：技术选型项目在宿主线程受限后，用fresh CLI完成独立任务。01–06已有三个核验及采用决策角色的精确字段与产物；本轮再核对07–10中已结束的源码、修订、协调、资料入库、CSV作者及三路初判/复验的保存记录，model/effort/approval与退出字段分别可核。另有显式workspace-write续接的有限证据，见后节。这些结果不解释原宿主线程额度根因，也未覆盖所有配置层和第三方hook集成，整篇继续partial、`last_verified=null`。具体版本、线程、结束记录及产物入口只在本机实例索引“独立Max任务会话”维护；没有重新制造线程上限、发新模型请求、升级二进制或改全局配置。

## 独立任务的单次覆盖与字段核对

适用于已经获得执行授权、需要新上下文的独立任务；只复用已运行客户端接受的参数范围。fresh CLI成功不能证明原宿主限制已解除，也不能作为恢复原线程的替代声明。

1. 保留宿主报错和工具边界。线程上限的作用域、回收机制及根因未经证明时写未知；不把重试或中断未释放名额推导为确定根因。
2. 给每个角色独立的最少输入和写入目录，使用不带resume/fork的`codex exec`。显式`--model`及`--config 'model_reasoning_effort="max"'`仅覆盖本次请求；具体模型和等级须按目标客户端支持及授权选择，不静默降级。cwd可能加载项目指令，fresh不意味着没有AGENTS。
3. 从本次JSON事件的`thread.started.thread_id`定位精确自有线程，在本次有效`CODEX_HOME`的sessions中查找；只有未设置该根时才用默认根。只提取与该ID匹配的`turn_context.payload.model`、`effort`及必要的`approval_policy`；诊断写入策略时再提取必要的`sandbox_policy`。已有精确保存的最小读回时优先复核它，不为补记录读取完整rollout、认证或完整配置。请求键`model_reasoning_effort`与读回字段`effort`分开，不能用相邻会话或启动参数代替读回。
4. 分别记录请求、字段读回、退出/实际产物和未覆盖项。产物冻结或验收结果支持对应任务执行完成，不因此认证服务器内部推理等级。日志缺失或字段未暴露就标未知，不以成功退出倒推配置。

本地实测支持上述有界新任务路径；没有证明fresh CLI与collaboration工具等价、其他模型/版本均支持相同等级或原宿主受限线程已恢复。fresh本身不证明resume成功；CLI同线程续接的有限证据另记下节，不外推为原宿主修复。

## 续接时显式策略与本轮字段核对

适用于已有精确CLI线程、同范围执行授权仍有效的续接。resume保留历史上下文，不登记为fresh；不为恢复写入绕过受管策略或扩大可写目录。

1. 保存线程身份、原请求及最近必要读回；重用原精确ID，不能把新启动误记同线程恢复。
2. 按目标客户端已接受的单次参数或配置显式请求所需sandbox策略，随后核对本轮有效`turn_context`。不假定resume继承首次workspace-write，也不以参数已提交认定实际可写；未保存调用语法时不补造通用命令。
3. 将model、effort、approval与sandbox类型逐项分开记录。类型之外的可写范围仍受当前策略约束；只有实际保存及退出/产物记录才支持相应执行结果。
4. 本地历史先有视觉线程由workspace-write变read-only、作者交付正文后由协调者保存的结果；这只支持只读交接。随后另一协调线程续接显式请求workspace-write，同一thread的两段必要读回均为该类型、model/effort及approval保持目标值，结束码0且有修订后汇总。该条件支持这次CLI续接与保存，不保证全部resume、目录或宿主等价。

本轮只用已保存启动、最小客户端字段、结束及产物记录完成核对，未重新续接或探测写权限。原collaboration宿主的线程额度根因与受限线程恢复仍未知；全局设置未改变。客户端gpt-6.1-sol/max不是服务器内部推理遥测，正常退出也不认证整套业务或最终公共交付。原计时解释继续引用项目原归属，本操作不复制另一套时钟算法或宣称完整根因。

## 第三方命令输出过滤器

对 RTK 等 PreToolUse 重写器，分别验证二进制过滤效果、hook 输入输出协议、有效配置层和宿主实际执行。官方支持 Bash / unified exec 的 updatedInput，不代表已安装或受信任；现有 hooks 必须合并保留。

精简输出需检查错误名称、位置、退出码和完整信息回溯。遇到不识别的测试生态，只有末尾输出仍可能保留失败退出码但丢掉诊断；已精简的原生命令也可能没有增益。仅有局部样例不刷新本操作的集成成功日期。


## 隔离采集工具的环境与创建权限

2026-10-19，CLI 0.159.3 的局部证据支持以下检查。整篇仍为 partial，不刷新完整成功日期。

- `shell_environment_policy.include_only` 必须同时列出需要保留的继承键和 `set` 键。本次只列代理键时，十个显式设置的工具环境值没有进入实际命令。补齐白名单后，原生命令逐项匹配，五个合成秘密键均不存在。配置解析成功不能代替工具环境读回。
- 低层 `command/exec` 成功不能证明模型工具宿主可用。本次模型 `exec` 在 `code_mode_host=false` 时明确返回宿主关闭。只修改专用配置中的该键，保留已审核的固定项目 scope；未知配置字节变化仍应拒绝。随后真实模型工具完成下载和提音，但转录失败，不能称完整采集成功。
- 已有 0600 数据库上的重启，不能证明新数据库的创建权限。原生子进程继承 022 时曾创建 0644 私有数据库。固定 exec 包装器只在子进程设置 077；父进程仍为 022，现有文件的严格检查不放宽。本次元数据证明四个新建 WAL/SHM 为 0600，其他既有文件只证明保持 0600。
- 独立 store 配置可能被原生程序追加项目记录。修改前核对完整哈希及准确差异，在维护锁下保存私有备份并原子替换。不得自动删除项目记录、接受任意 trust 变化或修改全局配置。

本次同配置的原生 `command/exec` 在导入 `mlx_whisper` 时报告 `[metal::load_device] No Metal device available`，直接 Python 的同一保留音轨离线转录则成功。该对照定位了可复现的沙箱 GPU 限制；原始模型任务只保存了通用失败码，不能把低层命令探针冒称模型工具的逐项等价证明。固定媒体程序由受控 Agent 执行、模型只读转录的后续验证见下段；不据此推荐放宽模型沙箱。

固定媒体执行器的后续验证已通过：从已核验本地 snapshot 加载模型，完成实际转录、模型摘要与隔离归档。不要把 `refs/main` 的 `strip()` 比较当作库的真实解析行为；本次缓存准备多写一个换行，校验器放行，但安装库按原字节拼路径而离线失败。只读库源码与一次同环境探针确认了差异。修复为严格 ref 字节检查，并直接传递操作者配置推导、文件哈希已核对的本地 snapshot 数据目录，保留离线设置。`HF_HOME` 使用私有空目录，避免将公开缓存父目录当成认证根。该证据不证明其他版本的缓存布局相同。

实际默认传输审计、业务转录和正式部署是不同证据。新包装器审计的三轮与四个无工具请求已有回执，独立复核及完整业务状态仍以所属项目记录为准。没有验证 OAuth 刷新或凭据轮换。
