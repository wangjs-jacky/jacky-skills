# 知识格式与自动写回

每次新增、修正、重复验证或中断收尾时读取。公共知识用 Markdown；不建立执行队列或后台沉淀服务。

## 归属和元数据

- 能力目录：`references/capabilities/<capability>/index.md`，保存边界、共用事实、来源、操作链接。
- 操作：能力下 `operations/<operation>.md`，保存单个用户目标、条件、步骤、成功标准、坑与证据。
- `experience.local.md` 是小型实例索引，详情进 `local/`。历史快照只作来源，不与当前记录同时写回。

Operation 元数据：

```yaml
---
capability: configuration
operation: diagnose-config-loading
status: documented
last_verified: null
---
```

| status | 证据范围 | last_verified |
| --- | --- | --- |
| documented | 设计、文档、源码或未经完整复核的历史指导 | `null` |
| partial | 已执行部分步骤，目标或成功条件仍缺证据 | `null`，局部日期写正文 |
| verified | 声明目标在注明条件下全部达到成功标准 | 真实成功日期 |

记录日期、宿主类别、版本/安装来源、观察方式、结果和未完成项。路径、账号、进程 ID、私有证据位置只写本机记录。认证只存模式和来源名称，不保存凭据值。

配置读回可以证明保存；新进程读回可以证明加载；模型请求成功才证明对应请求链路。查询日志可以成功返回“未知”或“已过期”，不能据此声称实时额度已确认。诊断与修复分别判断。

## 自动写回

1. 对照本次 operation 成功标准，分别判断完成、部分、失败和未知。中断时只整理已经取得的允许保存的证据。
2. 更新唯一归属，合并事实并修正矛盾；不得只向旧错误后面追加相反结论。
3. 完整成功维护验证日期，重复成功也维护；同日、同条件且无变化可无 diff。未完成只更新观察记录。
4. 失效记录降级并清空当前 `last_verified`，正文保留历史验证日期与条件。迁移不得给旧成功换成今天的日期。
5. 同步受影响的能力路由和链接；索引只引用操作，不重复状态字段。核对格式、引用与隐私。
6. 报告写回位置和证据范围。没有新增说明原因；写入失败明确报告未保存，并提供补丁。

官方资料核对日期只覆盖该次实际阅读的事实；版本、配额、价格和支持情况在执行前重查。未公开限制写未知，不用 API 限额替代订阅 Codex 限额。

只读安装应选择一个用户可写的唯一经验源并报告，不能制造多个漂移副本。知识维护不自动授权登录、清理进程、远端迁移、真实模型请求、提交或发布。

`.gitignore` 覆盖 `experience.local.md`、`*.local.*`、`local/`。公共文件不能链接本机私有路径；私有实例可以引用公共 operation。任何经验文件都不得保存认证材料或完整会话响应。
